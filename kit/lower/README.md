# kit/lower: from syntax tree to IR

Lowers a runtime lambda, parsed by [kit/parse](../parse/README.md), to an [IR](../ir/README.md) kernel. Every identifier and member is resolved, and every expression typed, against an **environment**; whatever cannot be lowered comes back as a coded diagnostic with a one-line `tip`. No Node built-ins.

```js
import { lowerLambda, lowerProgram } from "./kit/lower/index.js";
import { dmgEnvironment } from "./kit/dialects/dmg/index.js";

const environment = dmgEnvironment(declarations);              // what one program declares
const r = lowerLambda(environment, src, { id: "Mole.onFrame#0", kind: "onFrame", on: "Mole" });
// r.ok, r.kernel (null on any error), r.diagnostics (parser, subset and lowering, in source order)

const { results, sigs, helpers } = lowerProgram(environment, lambdas, helperSources); // a whole program: infers payloads and method and helper signatures
```

- **The environment** ([`environment.d.ts`](environment.d.ts)), a dialect plus one program's declarations, names the objects a lambda can reach (entity kinds, the world, input, …) with their members' types, store rules and effects; the list operations that take callbacks; the free globals (`Math`); and each slot's calling convention, iteration space, and the effects it forbids. An environment is data plus one `slot()` lookup.
- **The DMG dialect** ([`../dialects/dmg/`](../dialects/dmg/index.js)) becomes an environment, via `dmgEnvironment(declarations)`, when combined with a program's declarations ([`decls.d.ts`](../dialects/dmg/decls.d.ts)): attributes with their types, baked constants, methods, params, pools, the board, aliases and sounds. `scripts/dmg-oracle/declarations.js` reads them from a built spec. It describes `self`, `w` (`frame`, `param`, `rand`, `rng`, `board`, `pool`, `spawn`, `emit`, `sfx`, `toast`, `input`, `grid`, `all`, `one`, `log`, `end`, `overlap`), the HUD's `at(c, r).text(fmt, …)` and `Math`. `w.bg` has `get`, `at`, `cell`, `set` and `scroll` (see below).
- **Whole-program inference.** DMG events and methods are untyped, so `lowerProgram` takes an event's payload type from its emit sites, a method's parameter types from its call sites (strict join, below), and its result and effects from its body, repeating until nothing changes. A method call's effects include the callee's.
- **Queries** (`filter`, `find`, `some`, `every`, `reduce`) take a callback with an expression body, which lowering inlines as an `each` loop over the list. The callback may read the enclosing lambda's locals; it may not change them, write state, or call anything with an effect other than a read (L006). A program function is judged by its own effects, so a pure helper may be called there.
- **Evaluation order is JavaScript's.** Operands and arguments go left to right, and each receiver is evaluated once: `w.board.at(w.rng.int(9)).ttl += 30` saves the mole to a temporary, reads `ttl`, then evaluates the right side, then stores. When an operand spills statements (a nested assignment, a lazy branch), the operands before it that could change are saved first.
- **Bounded loops.** A `for` loop counts by one, up with `++` or `+= 1`, from an integer literal or a param, to a bound that is a constant within the counter type's exact range (2^53 - 1 for f64, 2^24 - 1 for f32: an f32 `i++` stops at 2^24, so a larger bound would never end), a param, a list's length (whose max is within that range too), or a place its Dialect declares a size (`Member.size`: the DMG grid's rows and cols, a fields param with a `max` of at most 2^24 - 1; any other read-only place is L007). The loop only checks that a param or place is a name, not its value: a param whose value can pass the counter's range hangs an f32 loop, so declare such a param with a smaller `max`; the body may not change the counter (L007). A method that calls itself, directly or through other methods, is unbounded too (L007).
- **Effects through methods.** A method's effects include its callees'. A slot that forbids effects (`draw`, `hud`, `every`, `after`), or a query callback, may not call a method whose effects are unknown because it, or a method it calls, does not lower (L014).
- **Narrowing.** A possibly-empty reference (`w.rng.pick(…)`, `w.spawn(…)`) must be checked before use: `if (m != null) …`, `if (m == null) return;`, `m != null && m.up`. Only `const` locals narrow, and an optional global (an Event input's record global, null in a slot called without a record: [kit/define](../define/README.md)), which a lambda cannot assign. Write the check out: `m != null`, `m == null`, `m != null && m.up`. A bare reference, number or string as a condition is L003 (see the next note), so lowering never emits `truthy`.
- **Explicit null checks** ([`nullcheck.js`](nullcheck.js)): the loose ones narrow an optional as truthiness does, through `&&`, `||`, `!`, else branches and early returns, but test emptiness only: an optional date at the epoch (stored as 0) or a number holding 0 is present. Each form keeps its JavaScript meaning. `x != null` and `x == null` (or `undefined`) match both empty values; they lower to `present` and `not(present)` and narrow any optional (the parser does not warn S116 on a loose comparison with a `null` literal; it still does with `undefined`). `x !== null` and `x === null` lower to `ne` / `eq` against null as before and **narrow nothing**: the core itself gives undefined for an empty value (`find` with no match, an index past a known length, an optional struct key read by destructuring), and `!== null` is true for undefined. Using the value after one is L003, whose tip names `x != null`. (Corrected 2026-11-24, job hxjaI2: 62bec66 let the strict form narrow an optional primitive, "trusting that a Dialect gives null, never undefined". That premise was wrong: those undefineds come from the core, not the Dialect, so `if (x !== null) return x + 1` lowered clean and returned NaN.) `x !== undefined` and `x === undefined` on an optional are L003, with the tip to compare with null: the kit's empty value is null, for which `!== undefined` is true. Compared with any other non-optional value (`self.ttl === undefined`), `undefined` is L003 (the two can never be equal); used as a value anywhere else (`const y = undefined`), it is L001, with the tip to use null.
- **Writable world built-ins.** Besides declared attributes, `w.oamStart` (`u8`) and `w.over` (`bool`; true ends the game) are writable, as the runtime's world allows. `return f()` in a slot that returns nothing lowers when `f()` returns nothing.
- **Equality.** `===` and `!==` between a list or struct and anything but `null` are L003 (the tip says to compare fields or items): such a value has no identity here, and a shader or C backend has none either. A baked constant's items and fields compare normally.
- **Temporal dead zone.** A `const` or `let` name is dead from the start of its block (or the lambda body) until its declaration runs: a read before that (`const x = x + 1`, `const { a: x } = x`, `for (const m of m)`, or a read of a later `const x` while an outer `x` exists, even from a nested block or a query callback) is L001, never a read of an outer name of the same spelling, as JavaScript throws a ReferenceError there.
- **`for…of`** over a list (`w.board`, a `filter` result, any list-typed value) lowers to an `each` loop; the binding must be `const`. The body is lowered even when the loop is rejected, so errors inside it show. The item is the list's item type.
- **Destructuring.** `const { x, y } = p` takes a struct's fields (L002 for a field it lacks; an entity is not a struct, L003); `const [a, b] = list` takes a list's items by position, each typed possibly empty like any list index, unless the list is an array literal and the position is below its length (next bullet). Patterns nest and work as a `for…of` binding. The value is evaluated once.
- **A list's `length`** is built into every list in every Dialect (`listLength` in [`expr.js`](expr.js), a member typed as the Dialect's numbers are, its `numberType` (f64 unless it declares f32, so `i < xs.length` never mixes f32 and f64), when that type holds the list's max exactly, else an f64, and never above the list's max): `xs.length` reads, and bounds a counted loop (`size ≤ max`) when the counter's type counts to the max exactly (2^24 - 1 for an f32, as for a constant bound; past it L007), whether or not the Dialect declares list members. So an f32 Dialect's list of at most 2^24 items has an f32 length, and a longer one (an open state list, which a UI, port or Draw lambda sees with the max `OPEN_MAX`, [kit/define](../define/README.md)) an f64, the type kit/ir's verifier takes for it (`holdsLength` in [kit/ir](../ir/types.js)). An f32 length makes a UI, port or Draw lambda in an f32 Dialect compute in f32: `s.stages.length / 3`, on a list of max 8, is the f32 quotient, where before ce1e7b4 those paths typed every length f64 (leaf `v4Ya0z`). (Corrected 2026-11-27, leaf `v4Ya0z`: until then a length was the Dialect's number type whatever the list's max, so an f32 Dialect's UI lambda reading an open list's length made a Kernel the verifier refuses, V002, and an f32 counter was accepted against a length past 2^24.) A Dialect's `list` members (the Definition API's `list`, `Environment.list`) add to it; DMG declares none. It is read-only, and not a function (`xs.size` is L002). (Corrected 2026-11-27, leaf `o2RhFb`: this README listed a list's length as a loop bound for every Dialect, but only the DMG Dialect declared the member, so a Definition API Dialect got L002 on `xs.length` and L007 on a loop to it. The three Definition API lowerings that patched it in for themselves, ports, UI and Draw builders, no longer do.) Every Kernel lowering makes carries `needs: []`, the CPU tier's list of CPU-only features, which is always empty here ([kit/ir](../ir/README.md)).
- **List indexing.** `list[i]` has the item type made possibly empty, as `find`'s result is, and so must be checked before use (L008): bind it to a `const` and test it, or `if (m == null) return;`. `i` must be a number. A list literal records its exact length (`len`, next to `max`), so a constant index below it (`[5, 6][1]`), or a destructuring position below it, is not empty and needs no check; an index at or past the length, a non-constant, negative or fractional index, and any list without a known length (`w.board`, pools, `filter` results, parameters) stay possibly empty. There is still no tuple type, and `len` is never widened: lists of different lengths do not join. Storing into `list[i]`, or calling it, stays rejected (L012). Any other computed name is L009. **Inside a loop to the end of its list** the read is not empty: in `for (let i = 0; i < xs.length; i++)` where `xs` is a local or parameter (a plain name, not `w.board` or a member), `i` starts at a whole number from zero up and the body never assigns `xs` or `i`, `xs[i]` has the item type, so no check is needed. **The refinement keeps the pre-narrowing ways of writing the loop:** a read that is checked (`xs[i] != null`, `== null`, `!== null`, `xs[i] ?? b`) or bound by a `const` keeps its possibly-empty type, and a `const` so bound is then narrowed as present (a check of it still lowers, as `x != null` on an optional const), so the pre-narrowing way to write the loop lowers and runs the same. A `const` that copies such a const (`const k = x`, checked or not) is the same: possibly empty by type, present, and still checkable; a `let` copy takes the present type. Only the subject of a check or of `??` is read as the optional it was. One known exception: a read inside an array literal that a pattern takes apart, `const [a] = [xs[i]]; if (a != null) …`, is present, so the check is L003 (a check of something never optional), where before the narrowing it lowered; drop the check, or bind the read to a `const` first. **Corrected 2026-11-27 (leaves `nQY0cL`, `uyQknP`):** this said a refinement never breaks a program that lowered before, but a `const` copy of a checked read (`if (m != null) { const k = m; … k.ttl }`, a DMG pattern) was L008, since binding it read the copied const as optional again, and the wrapped form above is still the exception. A check of something that was never optional (`i != null`) is still L003. A list index may be an f32 as well as an f64 (an f32 Dialect's counter). It is the name `i` in the same loop and the same list only: `xs[i + 1]`, `ys[i]`, `xs[0]`, a `<=` bound, and a read after the loop stay possibly empty, and a shadowing `const xs` inside the body is another list. The IR carries no flag for it: kit/ir's verifier recognizes the loop ("Loop-index reads").
- **`??`** (`a ?? b`) is the value of `a` when it is present and `b` otherwise, and `b` is evaluated only then. `a` must be possibly empty (an optional, a list item, a `find`): otherwise it is L003, "never empty", as a null check of it is. It tests emptiness as `a != null` does, so a present `0` or `""` stays; the result's type is the join of `a`'s non-empty type and `b`'s, and a number literal on the right takes the left's type. It lowers to no new IR node: `a` is read once into a temporary of its optional type, and the value is `cond(present(temp), temp, b)` (an `if` that sets a temporary when `b` needs statements of its own). It chains and works in conditions. `??=` and `||=` are still L012.
- **Top-level helpers.** The program's top-level `const f = (…) => …` are lowered like methods that have no `self` (slot kind `helper`, keyed `$.name` in `sigs.methods`): parsed, held to the subset, parameter types joined across every call site (strict join, below), result and effects from the body, no recursion (L007, also through a constant: a helper that reads a constant whose value calls it back), a caller's effects including the callee's. A call inside a baked constant counts, at each use, for what the lambda reaches, but types no parameter (the constant's own lowering is that call site). A call to a helper that nothing a runtime lambda reaches calls has no typed parameters, so its arguments are settled to the default number type, not checked (that helper is L014 itself). A call lowers to a `helper` IR node and the helper's own kernel is a separate kernel. A helper that does not lower makes every caller fail: its code would not exist, so the caller has no kernel and names it in `blockedBy`, but adds no diagnostic of its own, and the helper's effects are not judged again at the caller (one mistake, one diagnostic; until 2026-11-25 the caller added an L014). A top-level `const` that is not an arrow is a **baked constant**: lowered as `() => (init)` with every effect forbidden (a Definition API Dialect may allow it to call pure helpers: [kit/define](../define/README.md)), and each use is replaced by a copy of its value. Constants are lowered in each inference pass, before the lambdas and with the helper signatures so far (each pass judges a constant against only the constants before it, so a forward reference is L014 however many passes run), so a constant that calls a helper has that helper's result type, and its calls are call sites: they type the helper's parameters and count as reached code, so a constant bounds a loop. Any expression the subset lowers may be baked, lists and structs included, and each use gets a fresh copy; that is why `===` and `!==` on a list or struct are L003 (see Equality), since a copy has no identity to compare. A constant is read-only (L013), and where a key must be written out (`w.sfx(NAME)`) it still must be (L011). The caller passes `lowerProgram` the sources (`{ name, kind, src }`); `scripts/dmg-lower` finds them in a preset. Top-level `let` declarations are not helpers. A top-level `function name(a) { … }` is a helper through the Definition API's module scope, which hands lowering its arrow twin as the unit's `src` ([kit/define](../define/README.md), "Module scope"); `lowerProgram` itself takes only arrow text, and the DMG path (`scripts/dmg-lower`) still ignores function declarations, since no preset has one.
- **Call-site join (strict).** A method's or helper's parameter has one type: the strict join (`strictJoin` in [`../ir/types.js`](../ir/types.js)) of what every call site passes, never the general `join`, which would fall back to a union. The closed list: the same type; two string literals give the enum of both (members sorted, so call order does not matter); a dialect enum and a literal that is one of its members give the dialect enum; a string literal or enum and `str` give `str`; a value and `null` (or a possibly-empty value) give possibly empty. Dialect types are nominal: a dialect enum (`declared`, see [kit/ir](../ir/README.md)) takes a literal only by membership, two dialect enums join only when their members are the same, and entity, handle and struct types join only with themselves. A list joins only with an identical list, and `void` joins with nothing. Literals nested in a struct or list do not join (`f({ d: "up" })` next to `f({ d: "down" })`): the L014 names the differing field or items and tells the author to pass that value as its own parameter, where the top-level join gives the enum. Anything else is one L014 at the later call site, naming both sites and both types: ``` `f` takes f64 at Mole.onFrame#0 line 2 and Mole at Mole.onFrame#1 line 2; one parameter has one type.``` A site is its lambda's slot id and the line within that lambda. "Later" is program order (lambda order, then source order); swapping the order mirrors the message. A site is a lambda and its owner: a lambda shared by several entity kinds has one slot id but one site per kind, so a conflict is reported once, at the later kind, and the message adds `on Owner` when the id does not name it. The parameter count is the declaration's, never a call site's: a call with another number of arguments is its own L015 and joins nothing, however the calls are ordered. Only call sites in code a runtime lambda reaches count (a lambda that is not a method or helper, and, transitively, what it calls); an unreached helper's calls decide nothing. The conflicts live in `sigs.methods[key].conflicts` (see `callsites.js`).
- **Array literals** lower to an `array` IR node typed `{ list: T, max: n, len: n }`: `n` is the literal's length and `T` the strict join of the items, so items read by a constant index or tuple position below `n` are not empty, and any other read is possibly empty. Items of different types are L003 at the first that does not join (there is no tuple type, so `["up", 1]` is rejected); nested literals work (`[[3, 2], [12, 2]]`), but nested lists of different lengths do not join. An empty `[]` has no item type and stays L012, and so does a hole (`[1, , 2]`). A top-level array constant is baked like any constant and bounds a loop by its `length`. The JavaScript backend emits it as an array literal.
- **List concatenation** is a spread inside an array literal, `[...a, x, ...b]`, and lowers to a `concat` IR node whose `parts` are the spread operands in order (a run of plain items is one `array` part). The result is a list whose `max` is the parts' maxes summed (a plain item counts 1, a max-0 list adds nothing), whose item type is the strict join of the parts' item types, and whose `len` is the parts' lengths summed when every part has one (so `[...[1, 2], ...[3]][2]` is not possibly empty). Everywhere a list's max is checked, the summed max is what is checked: a result of max 4 returned where `list<f64, 3>` is expected is L003. An operand that is not a list, or is possibly empty (check it for `null` in a local first), is L003, and so are parts whose item types do not join. A baked `.const` cannot spread (L012). There is no `a.concat(b)` and no `map`: draft ruling, [question 1](../../project/2026-11-26-draw-list-draft.md). Spread in a call's arguments or an object literal is still S109. **Where a list is expected** (a slot's result, an argument, a field, a ternary's arms under one), the expected list's item type is a hint for each item and part: an object literal against a union of structs is checked against the member whose one-string tag it writes (`op: "rect"` picks the `rect` struct, so a wrong field is one L003 at that field), and, when the expected item type is a **union**, items or parts whose item types do not strictly join, but which each fit it, make a list of that union (a draw list of rects and texts is a list of ops; leaf `vcIzt1`). Without an expected list, when its item type is not a union, or when an item fits it not, the strict join decides as before: a list<str> of a Dialect enum and a string literal, ragged rows against list<list<f64>>, structs with and without an optional field, a line's `points: [p, [k, 1]]` (a `[f64; 2]` parameter and a literal of known length) are all L003, since kit/ir's verifier accepts a declared item type only when it is a union (V002; leaf `9t99go`). When the two item types print the same, as a known length and a max do (`[f64; 2]` both), the message says which is a list of exactly 2 and which of at most 2 (leaf `cfoinu`), and where when the lists are inside the items or a record field (`at .a in each`, `at [i].a in each`; leaf `sD9Cfn`). The JS emitter writes `[...a, ...b]` and the interpreter flattens; the LIR (and so GLSL) refuses it as "a list" (R002), like any list.
- **`w.bg`**, the background map (type `Bg`): `get(cx, cy)` and `at(sx, sy)` give a tile name as `str`; `cell(sx, sy)` gives `{ cx, cy }`; `set(cx, cy, name)` and `scroll(x, y?)` give the map back for chaining. Reads are `read bg` (`at` and `cell` also `read bg.scroll`); `set` is `write bg` and `scroll` is `write bg.scroll`, so both are forbidden in `draw` and `hud` like any write. A tile name is a plain `str` because declarations do not list tile names; the host throws on a name it has no tile for. `fill`, `rect` and `text` are not described: presets call them only from `.background`, which runs at build time.
- **Verifying what it makes.** With `switches.verify` on (exported from `index.js`; off by default), every kernel `lowerLambda` makes goes through the [IR verifier](../ir/README.md#verifying-a-kernel), as a partial kernel, before it is returned: a broken invariant is a `V…` error diagnostic, tipped as a kit bug, and the result has no kernel. `npm test` and `npm run test:prerelease` preload [`../test/verify-lowering.js`](../test/verify-lowering.js), which turns it on, so every lowering under test is verified.
- **f32 and vectors** ([`numeric.js`](numeric.js); the IR side is in [kit/ir](../ir/README.md#f32-and-vectors-m2)). An environment that has them declares its vector types in `vectors` (name to type, usually `dialectVector`) and its f64↔f32 conversions in `conversions` (`{ f32: "f32", f64: "f64" }`); its slots and members may then use `f32` and those types. Operators resolve on types (D1): `uv + k * q` on vectors lowers to vector `add` and `mul`. Calling a vector type's name builds one (`vec2(x, y)`, one scalar per component, else L015); `.x`…`.w` read components; calling a conversion converts, and converting a value that already has the type is L003 (remove it). **f32 and f64 never mix**, and neither do two vector types, even of the same shape (`vec3` and `color`): each such operation is L003 whose tip writes out the fix (`f32(d)` or `f64(k)`; `color(v.x, v.y, v.z)`). A vector and a scalar mix only as `s * v`, `v * s` and `v / s`; `v + s` is L003 with the tip `v + vec2(s, s)`. Vectors are not compared, ordered, tested as a condition, or used with `%`, `**` or bitwise operators (L003, each with a tip). **A number literal is untyped until its context gives it a type** (the M2 plan's ruling, "Number literals are untyped until used"). In arithmetic on an f32 or a vector, as an argument or component, a store, a slot's result, or the other arm of a ternary, it takes that type and is rounded to f32 once; a literal out of range is L016. Arithmetic on literals alone (`2 * 3`) is a literal too. Where nothing gives a type (a `let` or `const` initializer, a helper's argument, a ternary of literals, an array or object literal's items, a returned literal, a `for` counter's start), the Environment's **`numberType`** applies: `f64` unless the Dialect declares `f32` (the fields Dialect does; the DMG Dialect declares nothing, so it stays f64 and lowers exactly as before). A top-level baked constant stays untyped until each use, so `const TAU = 6.28` is f32 where it meets an f32 and f64 where it meets an f64. So do the numbers in a constant array or struct, as far as a use reads one item: `A[0]` (a literal index) and `S.h` take their type from the use, as a scalar constant does. A use of the whole array or struct (`for (const x of A)`, `A` passed on) settles every number in it to the default number type, as a literal array does where it is written; to use one as f64 in an f32 Dialect, read it by item. Typed values never convert silently, whatever the default: an f32 meeting an f64 is L003 with the fix. `++`/`--` and for counters have the type of their target, so an f32 counter counts in f32. **A ternary's arms, and an inferred method's returns, must share a number type**: an f32 and an f64, two different vector types, or a vector and a scalar are L003 (a literal arm takes the other arm's type first), never a silent union. A vector's component may be assigned when the vector is a `let` local: `a.x = v` and `a.x += v` rebuild the vector (`a = vec2(v, a.y)`), since a vector is a value with no places inside it; `a.x++` is `a.x += 1`, and as a value `a.x++` yields the old component and `++a.x` the new one. The value of a component or place assignment (`a.x = 0.5` used as a value) has the place's type, not a literal's. An Environment may name components with `componentAliases` (`c.r` is `c.x`; the IR only holds x, y, z, w). An intrinsic whose signature has a type variable (`mix(a: T, b: T, t: f32) -> T`) takes `T` from its arguments, a literal argument taking the type the variable is bound to (else the default); `numeric: "number" | "vector"` on the signature limits what `T` may be (L003 otherwise). None of this runs for an environment that declares no f32 or vector types, so the DMG dialect lowers exactly as before.
- **Nominal scalars** ([`scalar.js`](scalar.js); the IR side is in [kit/ir](../ir/README.md#nominal-scalars-m3)). A Dialect's named f64 (`date`) reaches a lambda as a slot parameter, a member, a global or an intrinsic's result; it is not a constructor a lambda can call. Two of one kind compare (`<`, `<=`, `>`, `>=`, `===`, `!==`); anything else is one L003 with a tip: a compare with any other type (an f64, an f32, a literal, another scalar), every arithmetic, bitwise, sign, `++`/`+=` or concatenating use, and testing one as a condition (`if (d)`: the one stored as 0 would be false; a possibly-empty one is tested with the loose null check, `d != null`, which keeps the epoch present; a bare `if (d)` is L003 like any non-bool condition). A ternary or inferred return that mixes it with a number is L003 by the number-mixing rule.
- **Handles** ([`handles.js`](handles.js); Ben's ruling of 2026-11-25, from trial 4's hidden rejects). A handle is a name the language hands a lambda whose type is an object (an entity or a handle type, `ref` or `obj`): a slot parameter (particles' `p` and `rng`, DMG's `self` and `w`) or a global (`$`, `counters`, fields' `u`, `Math`). It is used only as `h.member` (read, or written where the member is writable), `h.method(…)`, `h(…)` when its object is callable (`ObjectDecl.call`), or passed whole as an argument of any call: a Program helper, a Dialect method (DMG's `w.overlap(self, b)`), an intrinsic, a keyed call, where the call's own type check still applies (the coordinator widened it from helpers only, 2026-11-25). A callable handle (particles' `rng`) is only called, never passed. Anything else is L018, whose tip names the allowed uses: binding it to a local (`const q = p`, `let s = $`), returning it, putting it in an array or object, testing or comparing it, a ternary of it. A helper's own parameter of object type is a handle inside the helper, whatever a call site passes it (so `keep(w.first())` with a helper that aliases its parameter is L018, where the same code inline is not), and the rule holds however far one is passed. A callable handle's members are refused too: it is only called. One expression that misuses a handle twice (`p === p`) is one L018. **A sampler is stricter** (kit/ir; fields' image params): a sampler read, `u.img` or a helper's sampler parameter, stands only as an argument of a call, so `sample(u.img, p)` and `f(u.img)` lower and `const s = u.img`, `u.img === u.other`, `if (u.img)`, `c ? u.a : u.b` (even as an argument), `u.img.width` and `return img` are each L018 (`refuseSampler` in `handles.js`), its tip naming the Environment's calls that take a sampler. This is the verifier's sampler rule, refused here first so the V002 stays a kit bug. A value of object type that is not a handed-in name is no handle: `const m = w.spawn(…)`, `for (const m of w.board)`, a query callback's item, and a local bound to one may be aliased and passed as before. Assigning to a handle stays L013. The rule is decided by where the name stands in the syntax tree (`handleRoles`), then by its binding, so one aliasing mistake is one diagnostic: the alias's later uses lower as the object they would have been.
- **Per-slot effects** (leaf 8vQJOw; [design](../../project/2026-11-25-per-slot-effects-draft.md)). A slot convention may carry `may`, a list of effect patterns (`verb`, `verb Obj`, `verb Obj.member`), each matching its verb on that target or inside it (`"write Particle"` matches `write Particle.vel`). With `may` present, every effect a lambda has, its own or through a helper or method it calls (`call …` aside), must match one, else L004, whose tip lists `may`; without it, `forbid` alone judges the slot, as for DMG. A helper's convention carries its own `may` (the Definition API gives helpers reads only), so a helper's mistake is reported at the helper. A **total** is a value member with `bump: true`: its place is marked `total`, a read records `read Owner.name`, and it changes only by the statement `x.m += <f64>` or `x.m++`, which lowers to the IR's `bump` (recorded `bump Owner.name`, reading nothing); any other change is L017, and so is a read of a total in a slot whose `may` lets it bump that total (named as written when the lambda reads it, as `Owner.member` "through h" when a helper or method it calls does). A bump by an f32 is L003 (f32 and f64 never mix), its tip the statement with the Dialect's conversion written in (`totals.n += f64(p.x);`). A helper's L004 for a read says to pass the value in, and for a total to read it in a slot that does not bump it.
- **Literals no number type holds** are L016: one that is not finite (`1e999` reads as Infinity, which the IR's JSON form cannot hold either), and an f32 literal past f32's finite range (about ±3.4e+38).
- **Helpers nothing calls** (leaf `LWKjTf`). With the Environment's `checkAllHelpers` (a Definition API Dialect's `helpers: { check: "all" }`) a helper no lambda reaches is lowered with its parameters left untyped and quiet, not L014: its syntax, subset, effects against the helper convention's `may` (a counter or any global it reads) and recursion (L007) are checked, and a type error that needs a parameter's type, or an effect through one (`p.kill()`, `p.heat = 0`), is not. Its result has `untyped: true` and no kernel (the IR would hold untyped nodes), with `ok` true; once something calls it the parameters have types and it lowers as before. An object's `rejected` (`ObjectDecl.rejected`, from a Dialect object's `rejected: { name: { message, tip?, fix? } }`) answers a use of that member with its message and tip as an L002. Every lookup of a declared table by a lambda's name (members, `rejected`, globals, vectors, conversions) and of a table the Program fills (event payloads, top-level helpers) is by own key, so `Math.toString` or `p.constructor` is an ordinary missing member (L002), and a `rejected` entry named `constructor` or `toString` is reachable. In a value, `a || b` and `a && b` need bools: a non-bool operand is one L003 at the first such operand (and one per chain: `a && b && c` adds no second, though the right side is still lowered so its own mistakes report), whichever Dialect (the whole expression is then of unknown type, so a use of it adds nothing).
- **Conditions are bool only** (Ben, 2026-11-26; no opt-out): a non-bool if or ternary test, or operand of `!`, `&&` or `||` in a test, is one L003 whose tip writes the explicit form for the type found (optional `m == null` / `m != null`, number `n !== 0`, string `s !== ""`, vector a component).
- **Strictness a Dialect asks for** (leaf `ydiY5Y`, decision MpZZsU): its `vectorMultiply` (by vector type name, from `vector(…, { multiply: "scalar" })`) makes vector * vector an L003, while a number / vector is L003 always; a slot's `body: "block"` makes an expression body an L012 (the body is still lowered, so mistakes inside it show). Both are off unless set.
- **Returns on every path** (on for every Dialect). A lambda whose declared return type is not `void` and does not accept null must end in a return on every path (`terminates`: a trailing return, or an if whose branches both terminate; a `for` may finish without running, so a return inside one does not count), else one L003 at its closing brace. A helper's type is inferred, so a helper that returns a value on some path is held to it too, and its inferred type then omits the `void` the missing path would add, so a caller adds no second diagnostic. A method keeps its inferred optional type (a path with no return makes it `opt`), which the DMG relies on. An expression body always returns. Surveying the repo found no preset, golden or example it newly refuses; two unit-test snippets that fell off the end of a DMG `done` encoded the old leniency and were changed.
- **One mistake, one diagnostic after L010.** A parameter past what the slot passes is declared with an unknown type, so its uses report no L001.
- **Not lowered yet** (L012): logical assignment (`??=`, `||=`, `&&=`), `let` without a value. String methods are unknown members (L002).

## Codes

| Code | Meaning |
|---|---|
| L001 | A free identifier the dialect does not declare, such as a top-level helper of the preset, or a name read before its own declaration finishes |
| L002 | An unknown member, with a suggestion |
| L003 | A type mismatch, including f32 with f64, two different vector types, and a nominal scalar with anything but its own kind; a non-bool condition; vector * vector where it says `multiply: "scalar"`; a value that can reach the end of a lambda that must return it, or a helper that returns a value on some path and has a bare `return;` on another (one L003, at the bare return) |
| L004 | An effect the slot forbids, such as a write in `draw` or `hud`; the tip is the slot's `forbidWhy`, led by its `forbidMove` when the Dialect has a place the effect belongs (the DMG: an onFrame or an event handler). Or an effect outside the slot's `may`, its tip listing `may` (see Per-slot effects) |
| L005 | A callback that is not the argument of a declared query |
| L006 | A query callback with an effect, or that assigns a local |
| L007 | A loop whose bound cannot be checked: its counter does not start at an integer or a param, its bound is not a constant, a param, a list's length or a declared size, or the body changes the counter; or a step other than one (the tip suggests counting the iterations and computing the value inside the loop); or a recursive method or helper. The loop tips are the Environment's `tips.loopBound` and `tips.size` (the DMG's name `w.param("n")`), else neutral ones; the neutral size tip names `{ value: "f64", size: true }` as something the Dialect's author declares, not the Program's. A recursion cycle is one L007, at its least key, not one per helper or method in it |
| L008 | A possibly-empty value used without a check |
| L009 | A dynamic property name on anything but a list (`self[k]`) |
| L010 | More parameters than the slot passes |
| L011 | A name argument (param, pool, sound, event) that is not a literal, or names nothing declared |
| L012 | A subset construct lowering does not handle yet (logical assignment; an empty array literal or one with a hole, a `for…of` binding that is not `const`, storing into a list element); or an expression body where the slot's convention says `body: "block"` |
| L013 | A store to a read-only place: a baked constant, a built-in, a `const`, a global of the Dialect (`$ = 1`, which lowered clean and vanished until 2026-11-25). The tip is the Environment's `tips.readOnly` (the DMG's speaks of ROM constants and `.attr`), or for a store to a top-level constant or function its `tips.topLevel`, else a neutral one |
| L014 | A signature lowering cannot infer (no call site, no emit site), emit sites that disagree, call sites that disagree on a parameter's type, a call from an effect-checked position to a method whose effects are unknown, or a read of a constant that does not lower. A call to a helper that does not lower is no diagnostic (see Top-level helpers) |
| L015 | The wrong number of arguments |
| L016 | A number literal no number type can hold: not finite (`1e999`), or past f32's finite range where it is an f32 |
| L017 | A total changed other than by a `+= <number>` or `++` statement (`=`, `-=`, `*=`, `--`, a bump used as a value), or a total read in a slot that may bump it; spelled as written |
| L018 | A handle (a slot parameter or global of object type, or a helper's parameter of object type) used other than as `h.member`, `h.method(…)`, `h(…)` when callable, or passed whole as a call's argument; a callable handle passed (see Handles); a sampler read used other than as a call's argument. |

Each has a test that reads its tip, in [`test/diagnostics.test.js`](test/diagnostics.test.js).
