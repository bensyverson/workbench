# kit/lower: from syntax tree to IR

Lowers a runtime lambda, parsed by [kit/parse](../parse/README.md), to an [IR](../ir/README.md) kernel. Every identifier and member is resolved, and every expression typed, against an **environment**; whatever cannot be lowered comes back as a coded diagnostic with a one-line `tip`. No Node built-ins.

```js
import { lowerLambda, lowerProgram } from "./kit/lower/index.js";
import { dmgEnvironment } from "./kit/dialects/dmg/index.js";

const environment = dmgEnvironment(declarations);              // what one program declares
const r = lowerLambda(environment, src, { id: "Mole.onFrame#0", kind: "onFrame", on: "Mole" });
// r.ok, r.kernel (null on any error), r.diagnostics (parser, subset and lowering, in source order)

const { results, sigs, helpers } = lowerProgram(environment, lambdas, helperSources); // a whole program: infers payloads and method and helper signatures
```

- **The environment** ([`environment.d.ts`](environment.d.ts)), a dialect plus one program's declarations, names the objects a lambda can reach (entity kinds, the world, input, …) with their members' types, store rules and effects; the list operations that take callbacks; the free globals (`Math`); and each slot's calling convention, iteration space, and the effects it forbids. An environment is data plus one `slot()` lookup.
- **The DMG dialect** ([`../dialects/dmg/`](../dialects/dmg/index.js)) becomes an environment, via `dmgEnvironment(declarations)`, when combined with a program's declarations ([`decls.d.ts`](../dialects/dmg/decls.d.ts)): attributes with their types, baked constants, methods, params, pools, the board, aliases and sounds. `scripts/dmg-oracle/declarations.js` reads them from a built spec. It describes `self`, `w` (`frame`, `param`, `rand`, `rng`, `board`, `pool`, `spawn`, `emit`, `sfx`, `toast`, `input`, `grid`, `all`, `one`, `log`, `end`, `overlap`), the HUD's `at(c, r).text(fmt, …)` and `Math`. `w.bg` has `get`, `at`, `cell`, `set` and `scroll` (see below).
- **Whole-program inference.** DMG events and methods are untyped, so `lowerProgram` takes an event's payload type from its emit sites, a method's parameter types from its call sites (strict join, below), and its result and effects from its body, repeating until nothing changes. A method call's effects include the callee's.
- **Queries** (`filter`, `find`, `some`, `every`, `reduce`) take a callback with an expression body, which lowering inlines as an `each` loop over the list. The callback may read the enclosing lambda's locals; it may not change them, write state, or call anything with an effect other than a read (L006). A program function is judged by its own effects, so a pure helper may be called there.
- **Evaluation order is JavaScript's.** Operands and arguments go left to right, and each receiver is evaluated once: `w.board.at(w.rng.int(9)).ttl += 30` saves the mole to a temporary, reads `ttl`, then evaluates the right side, then stores. When an operand spills statements (a nested assignment, a lazy branch), the operands before it that could change are saved first.
- **Bounded loops.** A `for` loop counts by one, up with `++` or `+= 1`, from an integer literal or a param, to a bound that is a constant within the counter type's exact range (2^53 - 1 for f64, 2^24 - 1 for f32: an f32 `i++` stops at 2^24, so a larger bound would never end), a param, a list's length, or a place its Dialect declares a size (`Member.size`: the DMG grid's rows and cols, a fields param with a `max` of at most 2^24 - 1; any other read-only place is L007). The loop only checks that a param or place is a name, not its value: a param whose value can pass the counter's range hangs an f32 loop, so declare such a param with a smaller `max`; the body may not change the counter (L007). A method that calls itself, directly or through other methods, is unbounded too (L007).
- **Effects through methods.** A method's effects include its callees'. A slot that forbids effects (`draw`, `hud`, `every`, `after`), or a query callback, may not call a method whose effects are unknown because it, or a method it calls, does not lower (L014).
- **Narrowing.** A possibly-empty reference (`w.rng.pick(…)`, `w.spawn(…)`) must be checked before use: `if (m) …`, `if (!m) return;`, `m && m.up`. Only `const` locals narrow. A test of such a reference lowers to `present`; any other value tested as a condition lowers to `truthy`, JavaScript's truthiness, so an optional number holding 0 reads as absent there.
- **Explicit null checks** ([`nullcheck.js`](nullcheck.js)) narrow an optional as truthiness does, through `&&`, `||`, `!`, else branches and early returns, but test emptiness only: an optional date at the epoch (stored as 0) or a number holding 0 is present. Each form keeps its JavaScript meaning. `x != null` and `x == null` (or `undefined`) match both empty values; they lower to `present` and `not(present)` and narrow any optional (the parser still warns S116 on the loose operator). `x !== null` and `x === null` lower to `ne` / `eq` against null as before; they narrow an optional primitive (a number, a nominal scalar, a string, an enum, a bool), trusting that a Dialect gives null, never undefined, for an empty one, and do not narrow a reference, since `find` gives undefined for no match. `x !== undefined` and `x === undefined` on an optional are L003, with the tip to compare with null: the kit's empty value is null, for which `!== undefined` is true. `undefined` elsewhere is L001 as before.
- **Writable world built-ins.** Besides declared attributes, `w.oamStart` (`u8`) and `w.over` (`bool`; true ends the game) are writable, as the runtime's world allows. `return f()` in a slot that returns nothing lowers when `f()` returns nothing.
- **Equality.** `===` and `!==` between a list or struct and anything but `null` are L003 (the tip says to compare fields or items): such a value has no identity here, and a shader or C backend has none either. A baked constant's items and fields compare normally.
- **Temporal dead zone.** A `const` or `let` name is dead from the start of its block (or the lambda body) until its declaration runs: a read before that (`const x = x + 1`, `const { a: x } = x`, `for (const m of m)`, or a read of a later `const x` while an outer `x` exists, even from a nested block or a query callback) is L001, never a read of an outer name of the same spelling, as JavaScript throws a ReferenceError there.
- **`for…of`** over a list (`w.board`, a `filter` result, any list-typed value) lowers to an `each` loop; the binding must be `const`. The body is lowered even when the loop is rejected, so errors inside it show. The item is the list's item type.
- **Destructuring.** `const { x, y } = p` takes a struct's fields (L002 for a field it lacks; an entity is not a struct, L003); `const [a, b] = list` takes a list's items by position, each typed possibly empty like any list index, unless the list is an array literal and the position is below its length (next bullet). Patterns nest and work as a `for…of` binding. The value is evaluated once.
- **List indexing.** `list[i]` has the item type made possibly empty, as `find`'s result is, and so must be checked before use (L008): bind it to a `const` and test it, or `if (!m) return;`. `i` must be a number. A list literal records its exact length (`len`, next to `max`), so a constant index below it (`[5, 6][1]`), or a destructuring position below it, is not empty and needs no check; an index at or past the length, a non-constant, negative or fractional index, and any list without a known length (`w.board`, pools, `filter` results, parameters) stay possibly empty. There is still no tuple type, and `len` is never widened: lists of different lengths do not join. Storing into `list[i]`, or calling it, stays rejected (L012). Any other computed name is L009.
- **Top-level helpers.** The program's top-level `const f = (…) => …` are lowered like methods that have no `self` (slot kind `helper`, keyed `$.name` in `sigs.methods`): parsed, held to the subset, parameter types joined across every call site (strict join, below), result and effects from the body, no recursion (L007), a caller's effects including the callee's. A call lowers to a `helper` IR node and the helper's own kernel is a separate kernel. A helper that does not lower makes every caller fail (L014): its code would not exist. A top-level `const` that is not an arrow is a **baked constant**: lowered as `() => (init)` with every effect forbidden, and each use is replaced by a copy of its value, so a constant bounds a loop. Any expression the subset lowers may be baked, lists and structs included, and each use gets a fresh copy; that is why `===` and `!==` on a list or struct are L003 (see Equality), since a copy has no identity to compare. A constant is read-only (L013), and where a key must be written out (`w.sfx(NAME)`) it still must be (L011). The caller passes `lowerProgram` the sources (`{ name, kind, src }`); `scripts/dmg-lower` finds them in a preset. Top-level `let` and `function` declarations are not helpers. Function declarations would need a parser change; no preset has one.
- **Call-site join (strict).** A method's or helper's parameter has one type: the strict join (`strictJoin` in [`../ir/types.js`](../ir/types.js)) of what every call site passes, never the general `join`, which would fall back to a union. The closed list: the same type; two string literals give the enum of both (members sorted, so call order does not matter); a dialect enum and a literal that is one of its members give the dialect enum; a string literal or enum and `str` give `str`; a value and `null` (or a possibly-empty value) give possibly empty. Dialect types are nominal: a dialect enum (`declared`, see [kit/ir](../ir/README.md)) takes a literal only by membership, two dialect enums join only when their members are the same, and entity, handle and struct types join only with themselves. A list joins only with an identical list, and `void` joins with nothing. Literals nested in a struct or list do not join (`f({ d: "up" })` next to `f({ d: "down" })`): the L014 names the differing field or items and tells the author to pass that value as its own parameter, where the top-level join gives the enum. Anything else is one L014 at the later call site, naming both sites and both types: ``` `f` takes f64 at Mole.onFrame#0 line 2 and Mole at Mole.onFrame#1 line 2; one parameter has one type.``` A site is its lambda's slot id and the line within that lambda. "Later" is program order (lambda order, then source order); swapping the order mirrors the message. A site is a lambda and its owner: a lambda shared by several entity kinds has one slot id but one site per kind, so a conflict is reported once, at the later kind, and the message adds `on Owner` when the id does not name it. The parameter count is the declaration's, never a call site's: a call with another number of arguments is its own L015 and joins nothing, however the calls are ordered. Only call sites in code a runtime lambda reaches count (a lambda that is not a method or helper, and, transitively, what it calls); an unreached helper's calls decide nothing. The conflicts live in `sigs.methods[key].conflicts` (see `callsites.js`).
- **Array literals** lower to an `array` IR node typed `{ list: T, max: n, len: n }`: `n` is the literal's length and `T` the strict join of the items, so items read by a constant index or tuple position below `n` are not empty, and any other read is possibly empty. Items of different types are L003 at the first that does not join (there is no tuple type, so `["up", 1]` is rejected); nested literals work (`[[3, 2], [12, 2]]`), but nested lists of different lengths do not join. An empty `[]` has no item type and stays L012, and so does a hole (`[1, , 2]`). A top-level array constant is baked like any constant and bounds a loop by its `length`. The JavaScript backend emits it as an array literal.
- **`w.bg`**, the background map (type `Bg`): `get(cx, cy)` and `at(sx, sy)` give a tile name as `str`; `cell(sx, sy)` gives `{ cx, cy }`; `set(cx, cy, name)` and `scroll(x, y?)` give the map back for chaining. Reads are `read bg` (`at` and `cell` also `read bg.scroll`); `set` is `write bg` and `scroll` is `write bg.scroll`, so both are forbidden in `draw` and `hud` like any write. A tile name is a plain `str` because declarations do not list tile names; the host throws on a name it has no tile for. `fill`, `rect` and `text` are not described: presets call them only from `.background`, which runs at build time.
- **Verifying what it makes.** With `switches.verify` on (exported from `index.js`; off by default), every kernel `lowerLambda` makes goes through the [IR verifier](../ir/README.md#verifying-a-kernel), as a partial kernel, before it is returned: a broken invariant is a `V…` error diagnostic, tipped as a kit bug, and the result has no kernel. `npm test` and `npm run test:prerelease` preload [`../test/verify-lowering.js`](../test/verify-lowering.js), which turns it on, so every lowering under test is verified.
- **f32 and vectors** ([`numeric.js`](numeric.js); the IR side is in [kit/ir](../ir/README.md#f32-and-vectors-m2)). An environment that has them declares its vector types in `vectors` (name to type, usually `dialectVector`) and its f64↔f32 conversions in `conversions` (`{ f32: "f32", f64: "f64" }`); its slots and members may then use `f32` and those types. Operators resolve on types (D1): `uv + k * q` on vectors lowers to vector `add` and `mul`. Calling a vector type's name builds one (`vec2(x, y)`, one scalar per component, else L015); `.x`…`.w` read components; calling a conversion converts, and converting a value that already has the type is L003 (remove it). **f32 and f64 never mix**, and neither do two vector types, even of the same shape (`vec3` and `color`): each such operation is L003 whose tip writes out the fix (`f32(d)` or `f64(k)`; `color(v.x, v.y, v.z)`). A vector and a scalar mix only as `s * v`, `v * s` and `v / s`; `v + s` is L003 with the tip `v + vec2(s, s)`. Vectors are not compared, ordered, tested as a condition, or used with `%`, `**` or bitwise operators (L003, each with a tip). **A number literal is untyped until its context gives it a type** (the M2 plan's ruling, "Number literals are untyped until used"). In arithmetic on an f32 or a vector, as an argument or component, a store, a slot's result, or the other arm of a ternary, it takes that type and is rounded to f32 once; a literal out of range is L016. Arithmetic on literals alone (`2 * 3`) is a literal too. Where nothing gives a type (a `let` or `const` initializer, a helper's argument, a ternary of literals, an array or object literal's items, a returned literal, a `for` counter's start), the Environment's **`numberType`** applies: `f64` unless the Dialect declares `f32` (the fields Dialect does; the DMG Dialect declares nothing, so it stays f64 and lowers exactly as before). A top-level baked constant stays untyped until each use, so `const TAU = 6.28` is f32 where it meets an f32 and f64 where it meets an f64. So do the numbers in a constant array or struct, as far as a use reads one item: `A[0]` (a literal index) and `S.h` take their type from the use, as a scalar constant does. A use of the whole array or struct (`for (const x of A)`, `A` passed on) settles every number in it to the default number type, as a literal array does where it is written; to use one as f64 in an f32 Dialect, read it by item. Typed values never convert silently, whatever the default: an f32 meeting an f64 is L003 with the fix. `++`/`--` and for counters have the type of their target, so an f32 counter counts in f32. **A ternary's arms, and an inferred method's returns, must share a number type**: an f32 and an f64, two different vector types, or a vector and a scalar are L003 (a literal arm takes the other arm's type first), never a silent union. A vector's component may be assigned when the vector is a `let` local: `a.x = v` and `a.x += v` rebuild the vector (`a = vec2(v, a.y)`), since a vector is a value with no places inside it; `a.x++` is `a.x += 1`, and as a value `a.x++` yields the old component and `++a.x` the new one. The value of a component or place assignment (`a.x = 0.5` used as a value) has the place's type, not a literal's. An Environment may name components with `componentAliases` (`c.r` is `c.x`; the IR only holds x, y, z, w). An intrinsic whose signature has a type variable (`mix(a: T, b: T, t: f32) -> T`) takes `T` from its arguments, a literal argument taking the type the variable is bound to (else the default); `numeric: "number" | "vector"` on the signature limits what `T` may be (L003 otherwise). None of this runs for an environment that declares no f32 or vector types, so the DMG dialect lowers exactly as before.
- **Nominal scalars** ([`scalar.js`](scalar.js); the IR side is in [kit/ir](../ir/README.md#nominal-scalars-m3)). A Dialect's named f64 (`date`) reaches a lambda as a slot parameter, a member, a global or an intrinsic's result; it is not a constructor a lambda can call. Two of one kind compare (`<`, `<=`, `>`, `>=`, `===`, `!==`); anything else is one L003 with a tip: a compare with any other type (an f64, an f32, a literal, another scalar), every arithmetic, bitwise, sign, `++`/`+=` or concatenating use, and testing one as a condition (`if (d)`: the one stored as 0 would be false; a possibly-empty one narrows by an explicit null check, `d !== null`, which keeps the epoch present; by truthiness, as an optional number does, it reads the epoch as absent). A ternary or inferred return that mixes it with a number is L003 by the number-mixing rule.
- **Literals no number type holds** are L016: one that is not finite (`1e999` reads as Infinity, which the IR's JSON form cannot hold either), and an f32 literal past f32's finite range (about ±3.4e+38).
- **Not lowered yet** (L012): `??` and logical assignment, `let` without a value. String methods are unknown members (L002).

## Codes

| Code | Meaning |
|---|---|
| L001 | A free identifier the dialect does not declare, such as a top-level helper of the preset, or a name read before its own declaration finishes |
| L002 | An unknown member, with a suggestion |
| L003 | A type mismatch, including f32 with f64, two different vector types, and a nominal scalar with anything but its own kind |
| L004 | An effect the slot forbids, such as a write in `draw` or `hud` |
| L005 | A callback that is not the argument of a declared query |
| L006 | A query callback with an effect, or that assigns a local |
| L007 | A loop whose bound cannot be checked: its counter does not start at an integer or a param, its bound is not a constant, a param, a list's length or a declared size, or the body changes the counter; or a step other than one (the tip suggests counting the iterations and computing the value inside the loop); or a recursive method or helper |
| L008 | A possibly-empty value used without a check |
| L009 | A dynamic property name on anything but a list (`self[k]`) |
| L010 | More parameters than the slot passes |
| L011 | A name argument (param, pool, sound, event) that is not a literal, or names nothing declared |
| L012 | A subset construct lowering does not handle yet (an empty array literal or one with a hole, a `for…of` binding that is not `const`, storing into a list element) |
| L013 | A store to a read-only place: a baked constant, a built-in, a `const` |
| L014 | A signature lowering cannot infer (no call site, no emit site), emit sites that disagree, call sites that disagree on a parameter's type, a call from an effect-checked position to a method whose effects are unknown, or a call to a helper or constant that does not lower |
| L015 | The wrong number of arguments |
| L016 | A number literal no number type can hold: not finite (`1e999`), or past f32's finite range where it is an f32 |

Each has a test that reads its tip, in [`test/diagnostics.test.js`](test/diagnostics.test.js).
