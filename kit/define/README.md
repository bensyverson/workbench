# kit/define: the Definition API

Declares a Domain Language as data and generates the rest. `defineDialect` says what the language **means** (types, objects, intrinsics with each target's spelling and a reference implementation, the Library, Iteration Spaces, targets, slot conventions); `defineGrammar` says how a Program is **written** (constructs and their slots), and the kit generates the builder, its diagnostics, the record it returns and the lowering of every Runtime Lambda. The spec is [the draft](../../scripts/define-trial/docs/api-draft.md); this page says what is built and where the build departs from it. No Node built-ins.

```js
import { defineDialect, defineGrammar, vector, exact, name, data, lambda } from "./kit/define/index.js";

const d = defineDialect({ name: "tiny", numberType: "f32", types: { vec2: vector(2, "f32") },
  spaces: { pixel: { pure: true } }, targets: { js: { accepts: "*", compare: exact() } },
  slots: { pixel: { params: ["vec2"], returns: "f32", space: "pixel" } } });
const tiny = defineGrammar(d, { root: "tiny", constructs: { tiny: { opens: [name()], slots: {
  pixel: { kind: "decl", args: [lambda("pixel")], once: true, required: true } } } } });

const record = tiny("t").pixel((uv) => uv.x * 0.5).build();   // { name: "t", pixel: "(uv) => uv.x * 0.5" }
const { lambdas, helpers, diagnostics } = tiny.lower(record);  // Kernels, through kit/lower
```

[kit/dialects/fields](../dialects/fields/README.md) is declared with this API: its [`dialect.js`](../dialects/fields/dialect.js) is the draft's worked example completed, and its builder is the one [`grammar.js`](../dialects/fields/grammar.js) generates. Its tests hold the generated builder to what the hand-written one it replaced built (`test/golden/hand-built.json`) and refused.

- **A Dialect value** ([`dialect.js`](dialect.js)). `defineDialect(def)` checks the whole definition and throws one `DefinitionError` holding every problem (`{ code, message, tip, path, file, loc }`: `path` is the key path inside the definition, `loc` the define call). It returns `{ name, numberType, def, intrinsics, library, targets, libraryFor(sources), text(state), environment(program, states?) }`. `intrinsics` has the shape of fields' table (`{ sig, ref, componentwise?, <target>: { call, prelude? } }`), `library` is `UnitDecl[]`, and `environment(program)` returns an [Environment](../lower/environment.d.ts) exactly as lowering reads it: type names resolved to core Types, each intrinsic a callable object plus a global, the hook's objects and globals merged in (a member it declares twice throws), and `slot(ref)`.
- **The text view.** Every Dialect gives `text(state)`: its screen and state as characters, sized for a model ([the architecture synthesis](../../project/2026-11-24-architecture-synthesis.md) §3.3). A Dialect without one, or with one that is not a function, is `D020`. The kit does not say what `state` is, since only the Dialect knows what its host shows: fields takes a rendered frame `{ width, height, pixels }` and draws it as at most 64 by 32 characters, a NaN pixel as `?` ([`text.js`](../dialects/fields/text.js)); the data Dialect takes one table `{ name, columns, rows }` and prints its columns with their types (an inferred enum as `enum(a, b)`) and its first 20 rows, a date as its UTC day (its number when Date cannot hold it) ([`dialect.js`](../dialects/data/dialect.js)). The kit does not yet call it: a workbench page or an agent tool will.
- **Nominal scalars.** `types` holds vectors and scalars: `date: scalar("f64", { note })` is a named type stored as an f64 (the core's `{ scalar, of: "f64" }`, [kit/ir](../ir/README.md#nominal-scalars-m3)). Its name may be used wherever a type is named (slot params and returns, members, globals, intrinsic signatures, convention functions); it compares only with its own kind (an optional one narrows by `d != null`, which keeps the epoch present; `d !== null` narrows nothing: [kit/lower](../lower/README.md)) and is no constructor: a value enters through a parameter, a member or an intrinsic, and a lambda calling the type's name is `B008`. A lambda that infers a scalar hands its name to a construct's `step`. Another backing is D002, options other than `{ note: string }` D011, and `scalar()` written inline where a type is named D002. A type, vector or scalar, named like a built-in type (`f32`, `f64`, `bool`, `str`, `null`, `void`, `unknown`) or a one-capital-letter type variable (`T`) is `D007`, since it would take that name over everywhere it is written.
- **Slot conventions.** A static convention is resolved once; a function `(ref, program, state)` is called per lambda, and what it returns is checked as a static one is (`D002`, `D005`). `object(label, members)` in a convention makes an object type on the spot, named by its label (numbered when the same label carries other members). The kit makes the `helper` and `const` conventions; a Dialect may not declare those names, nor `method`, which lowering reads specially (`D007`). Every space is pure and no member can carry an effect, so purity holds by construction and a generated convention's `forbid` is empty; the generated `const` convention forbids every effect, as DMG's does, unless the Dialect declares `constants: { calls: "pure" }`: then a constant may call a helper (`.const("K", "g()")`), every other effect stays forbidden, and the helper's own effects would be judged by the same rule (lowering lists a callee's effects beside the call), though a generated Dialect can express no effect but `call`, so nothing exercises that today. A constant is lowered in each inference pass, after the helpers' signatures so far, so it has its helper's result type, and its calls are call sites that type the helper's parameters (`const K = h(0.25)`). `calls: "none"` is the default; any other value, or a `constants` that is not `{ calls }`, is D011, and another key D001. fields declares `"pure"`, as its hand-written Dialect allowed; DMG, hand-written, keeps forbidding every effect.
- **The generated builder** ([`grammar.js`](grammar.js), [`record.js`](record.js), [`shapes.js`](shapes.js)). `defineGrammar(dialect, def)` returns the root builder, with `.lower`, `.dialect` and `.grammar` on it. Each construct instance's builder has its slots, its child constructs and its ancestors' methods (calling one ends the child); builders are mutable, so `b.param(…)` without reassigning works. An unknown method throws `B001` at once with a did-you-mean; everything else is collected with the call's `file` and `loc` (from the stack) and `.check()` returns the list, `.build()` throws a `BuildError` carrying all of them or returns the record. `B002`, `B004`, `B006`, `B007`, `B009` and slot `check`s are found at the call; `B003` (Program-namespace refs), `B005`, `B008`, `B012`, `B013` and construct `check`s at `.check()` / `.build()`, when every name is known.
- **The record** is the draft's "The record": openings under `as`, else their namespace, else `name`; a slot whose first argument is `name()` as an object from name to the rest; other slots as one value (`once`) or a list; `units: [{ name, kind, src }]`; children as lists under their construct's name; `record: "calls"` as `calls: [{ slot, args }]`. A lambda is its source text wherever it was passed.
- **Only a lambda's text is compiled.** A function lambda is read by its source text (`String(fn)`), so a variable it closes over is not captured by the lambda itself; what it reads from the file's top level comes in through the module scope (next). A bound function has no source (its text is native code) and is refused as `B007`.

  > **Superseded 2026-11-24 (leaf `gS9dBz`, Ben's ruling in [the architecture synthesis](../../project/2026-11-24-architecture-synthesis.md) §3.2):** this said that a name in a lambda means the Dialect's or the Library's even when a local of that name is in scope (a local `fbm` binds to the Library's `fbm`). A top-level binding named like a Dialect or Library name is now refused instead (`B002`, rename it): one name, one meaning.
- **Module scope** ([`scope.js`](scope.js)). `.check(options)` and `.build(options)` take `{ scope?, sources?, buildTime? }` (`BuildOptions` in [`define.d.ts`](define.d.ts)): `scope` is the Program file's top-level bindings by name, `sources` each top-level `const` declaration's initializer text by name (`topLevelBindings`' `init`, filtered to `keyword: "const"`: a `let` can be reassigned to an arrow made by other code with the same text, so its text vouches for nothing), `buildTime` the names the file declares only inside build-time code. A host gathers them, since the kit has no module loader: the values from the module (the define-trial checker appends an export that returns them), the rest from the file's text with `topLevelNames`, `topLevelBindings` and `buildTimeNames` ([kit/parse/toplevel.js](../parse/toplevel.js), a lexical scan, no Node built-ins). A lambda's free name that the free-name rule does not allow and the scope holds resolves into a Program unit, as DMG lowering takes a program's top-level consts ([kit/lower](../lower/README.md), "Top-level helpers"): an arrow function is a helper (`{ kind: "fn", src: String(fn) }`), whose own free names resolve the same way, transitively; plain data is a baked constant whose source is the value written out (`{ kind: "const", src }`). **A helper must be the arrow its `const` declaration writes:** `String(fn)` must equal `sources[name]`, else `B012`. The scan's `init` leaves out comments around the initializer and parens that wrap it, as `String(fn)` does, so `const f = (x) => x * 2 // note` and `const f = ((x) => x * 2);` are helpers. An arrow made by another function (`const mk = (k) => (x) => x * k; const triple = mk(3)`) closes over that function's `k`, which its text loses, and resolving its free `k` against the module scope would silently read some other `k`; the fix is to declare the helper itself at the top level. Without `sources`, no arrow is a helper. **A host must not guess between two declarations of one name:** `topLevelBindings` throws a `ScanError` (naming the name and the second declaration's line) when it finds a name declared twice where one is a `const` or `let`, which a program cannot do, so the scan misread the file and none of its initializers can vouch for a helper; the define-trial checker reports it as `LOAD` and checks nothing more of that file. The refusal lives in the scan, not in this module, because `sources` is a plain record by the time it gets here: a host folding the scan's list into it (as `Object.fromEntries` does) would already have kept one of the two. Plain data is a finite number, a string, a boolean, and arrays and plain objects (identifier keys) of them; anything else (null, NaN, a Map, a class instance, a builder chain, a function inside an object, a cycle) is `B012`, and a function that is not an arrow `B007`, each with a fix. The value is read through its own property descriptors, so no getter runs: an accessor, a non-enumerable or Symbol key, the key `__proto__`, an array's hole or extra key, and an Array subclass are each `B012`. A Proxy cannot be told from a plain object, so one is baked as what its traps report. The constant is the value the host saw, not its initializer's text, so `const K = Math.PI / 2` works. A free name in `buildTime` is `B013` ("declared only inside build-time code"), with the fix to move it to the top level or write its value into the lambda's text; any other free name stays `B008`, whose tip then also offers the top level. Every scope binding named like a Dialect name (an intrinsic, global, type, conversion, a name the environment hook adds), a Library entry or a Program unit is `B002` at the root's call, resolved or not. **Where the units land:** `.build()` puts them first in the root record's `units`, whatever the root's slots (first, so a `.const` may read a top-level constant: a constant sees only those before it), so `lower(record)` stays a function of the record (lowering reads `units` on every instance); so the root construct may put nothing else under the record key `units` (`D017`). Without `scope`, nothing resolves and the record is as before.
- **Binding-time params** ([`params.js`](params.js); the ruling is [the binding-time design](../../project/2026-11-24-binding-time-design.md), Option A). A Program file exports a function of its params, `export default ($) => program(…)…`, and `run(programFn, { values?, scope?, sources?, buildTime? })` calls it with a `$` that answers each declared param with the host's value, else its declaration's `value`, and records the read; then it checks and builds the Program the function returned and returns `{ record, diagnostics }` (`record` null on an error, a `BuildError` thrown at a call included). A host's mistake throws a `TypeError`: a function that returns no builder, or a value for an undeclared param (reported even when the Program's code stopped at a `BuildError`, the message then naming where it stopped, since a param declared after that point is not known yet), or a value that does not fit its declaration. Every host value is checked at `run`, whether build-time code reads it or only a Kernel does (and when build-time code reads it, before it gets it): it must have the type of the declaration's `value`, be finite when a number, lie inside the declaration's `min..max` and be one of its `options` when it has them. The host's values then replace the declared ones in the record's param declarations, so `record.params` says what was built. The Grammar names its param slot, `params: { slot: "param" }`, a root decl slot taking a name and a declaration (else `D011`); the Dialect names the object lambdas read params through, the name they read it by, and its run-time-only members, `params: { object: "Uniforms", name: "u", runtime: ["t", "aspect"] }` (else `D011`); the kit owns no param construct. A build-time read is folded: the value is in the record where the code put it. The record keeps the reads under `reads` (`{ param, value, by, file, loc }`; `by` is the builder call made next after the read, `top.limit#5` (in a construct whose record keeps its calls, the index its lambdas' ids have; elsewhere `#n` counts that slot's earlier calls), or `table "top"` for an opening, or null when none came after; it orders the read among the calls and says nothing about which call used the value, so a value read early and passed late is placed before the next call, its `loc` still right; the root may put nothing else there, `D017`). `grammar.lower(record)` adds `params`, each declared param's binding time, `{ build: [{ by, file, loc }], kernels: [lambda ids], live }`, the Kernels found by their loads of the Dialect's params object (a Program helper as `helper 'name'`), `live` when nothing read it at build; `bindingText(lowered)` prints a line per param, saying where each build-time read was and which call came next (`topN   folded at build, read at 05-query.js:22 (before top.limit#5)`, `year   uniform, read by top.filter#0`; a read after the last call says `(after the last builder call)`). `needsRebuild(record, changed)` is true when build-time code read a changed param. A read before the param's declaration, or of an undeclared one, throws `B003` (with a did-you-mean); a run-time-only member, `B014` with the fix to read it in a lambda, also when it is tested with `in` (`"t" in u`). Before the Program opens its Dialect is not known, so a read then of a name some defined Dialect knows only at run time answers `undefined` and is decided when the Program opens: `B014` if that Program's Dialect lists it (fields' `u.t`), else `B003` (a data Program's `$.t`), placed at the read; if no Program opens, `B003`, which names no Dialect's object. Before it opens, `in` is `B015`. **Every refusal `$` makes (`B003`, `B014`, `B015`) is kept on the run as well as thrown**, so build-time code that catches one (`try { T = u.t } catch {}`) still gets no record and the refusal in `diagnostics`; an exception build-time code throws after a refusal is taken as its knock-on, and the refusal is reported instead. **A param's declared `value` is held to its own declaration** by the same rules as a host value, at the param's call: `B004` (collected, `arg: 1`) when it is not finite, outside `min..max` or not one of `options`, so `.param("n", { value: 99, min: 1, max: 5 })` is refused rather than folded; when the Dialect's own check refused the call already (fields' `F001`, a value outside its range), that is reported alone. A date param's string (`{ value: "2026-01-01", kind: "date" }`) is not checked: the `date` kind is the data Dialect's declaration, and how its string becomes a date is the host's (kit/dialects/data), so the kit has no date format to hold it to. **`$` is read by name only.** Any other read (`"topN" in $`, a spread, `Object.keys`, `Object.entries`, `JSON.stringify`, a rest pattern `{ a, ...rest } = $`, a property descriptor) is `B015`, with the fix to read each param by name, `$.name`: a recording `$` could neither answer it truly nor record it. Destructuring by name (`const { topN } = $`) is a read by name. `$` answers the properties runtimes and test libraries probe (`then`, `toJSON`, `inspect` …, D018's list) with `undefined`, so a param may not take one of those names: `B004` at its declaration, with the fix to rename it. The three that are Object.prototype's own (`constructor`, `valueOf`, `toString`) stay legal param names, since a lambda reads them like any other, and `$` answers a declared one by name (a runtime that probes one then records a read, which can only make `needsRebuild` say yes more often). One form for a value from a param: a zero-parameter lambda where a slot takes a value (`.limit(() => $.topN)`) is `B004` with the fix `.limit($.topN)`. Runs do not nest (one module-level run, safe because builds are synchronous). Not built: caching, a module loader (the host re-runs the function), data-flow attribution.
- **The free-name rule** (`B008`) allows a lambda's own names, the Dialect's globals (with those `environment(record)` adds), intrinsics, Library entries, vector constructors and conversions, and the Program's units. The tip names the Grammar's `const` unit slot, and `$.name` when the Dialect declares `$`. A member of a JavaScript global (`Math.sin`, `console.log`) gets another tip: the bare name when the lambda can see one of that name (an intrinsic, global, Library entry or unit: `use sin, not Math.sin`, `use PI, not Math.PI`), else `Math is not in the language`. The diagnostic's `lambda` field carries the lambda's source and the place inside it (also on a `B007`), so a tool can show the line.

- **`oneOf` with a lambda, and the ambiguous string.** The record keeps a lambda as its source text, which a `"string"` form also takes, so a record's lambdas are found again by matching its text, and a call and its record must choose the same branch. The rule: among the forms a value fits, the one holding the most lambdas wins, the first on a tie. So a string that parses as an arrow function is the lambda (`.y("() => 1")` is the lambda, as `.y(() => 1)` is), any other string is the ref or string (`.y("a")`), and a function is always a lambda; and it holds when the lambda sits inside a compound form (`oneOf({ f: lambda("v") }, { f: "string" })` with `{ f: () => 1 }`, or `oneOf(listOf(lambda("v")), "string[]")` with `[() => 1]`), wherever the `oneOf` sits. A string that is meant as a name or text yet parses as an arrow function cannot be given to such a `oneOf`. Text that holds `=>` but does not parse stays text (or a ref), and the call also gets a `B007` **warning** naming the parse error; a warning does not stop the slot's `check` or `.build()`. A function that is no Runtime Lambda (`async () => 1`, a method shorthand) is the lambda form's `B007`, with its detail, not a `B004` that lists the forms. A value whose record form would be read as another branch than the call took is `B004` at the call: with `{ f: lambda, g: "string" }` and `{ f: "string", g: lambda }`, the call `{ f: "() => 1", g: () => 2 }` fits only the second (a function is no string), but its record, both fields text, ties and would be read as the first, so its `g` lambda would never be lowered. Both fields as text (or both as functions) agree, and take the first form.

- **Lowering** ([`lower.js`](lower.js)) lives on the grammar, because only the grammar knows where lambdas sit in a record: `grammar.lower(record)` returns `{ environment, lambdas: [{ ref, src, result }], helpers, diagnostics, states, params }`. Every lambda goes through `lowerProgram` with the Library units it uses and the Program's units, in that order (as `lowerField` does). A lambda's slot id is `<on>.<slot>#<index>`, plus `.<key>` inside a `recordOf`; a `once` slot drops the index (`swirl.pixel`), so Kernel names match the hand-written Dialects'. Stateful instances share one namespace whatever their construct (an unnamed one goes by its construct's name), because `stateOf(name)` and `states` find an instance by name alone: a second with a name already taken is `B002` at `.check()`. A construct with `state` is built call by call: `init`, then per call its state-namespace refs are checked against the state at that step (`B003`, with a did-you-mean), its lambdas are lowered with that state (the convention's third argument) and their inferred types (in definition terms: `"f64"`, a vector's name, `enumOf`, `opt` …) go to `step`. A `stateOf` loop is `B010`: each instance on the loop is told it depends on its own state, one that only reads a looping state is told so. A convention that returns a reason is `B011`. Lambda type errors keep lowering's own `L…` codes. Every diagnostic in the flat list is tied to where it came from: `B003` and `B011` are pinned at the call (also in a by-slot construct, whose record keeps each call's place), `B011` carries the refused lambda's `ref`, and a lambda's `L…` diagnostics carry `file` and `ref` (their `loc` is inside the lambda's source), a helper's or constant's carry `unit`.

  **Step context.** `step(state, call, inferred, ctx)` gets `ctx = { program, stateOf, error }`. `program` is the record, as init's; `stateOf(name)` is another instance's final state, the same lookup as init's (by instance name, built lazily on first ask, `undefined` for an unknown name), so a join reads `ctx.stateOf(call.args[0]).columns` at the step where the join happens, with no closure in the state. A `stateOf` loop that goes through `step` is `B010`, attributed exactly as one through `init` (each instance on the loop depends on itself, one that only reads it reads a looping state). `error(code, message, options?)` refuses the call with the Dialect's own code; `options` is a check's `{ tip, arg, suggest, fix }` (one function, `dialectError` in [`codes.js`](codes.js), makes both), and a string there is taken as the tip: a diagnostic pinned at the call (`file`, `loc`, as `B011`) carrying `on` (the instance) and `slot`, collected into `lower()`'s diagnostics in call order; a code that is not one letter and three digits, or starts with a reserved letter, throws, as a slot or construct `ctx.error` does. **The state `step` returns still applies after an error**, so later calls and lambdas type against it and one mistake yields one diagnostic; the diagnostic is what makes the Program fail. A `stateOf` loop re-runs the steps of the instances on it for each instance that is told about it; a call reports each of its diagnostics (`B003`, `B011`, `ctx.error`) once however often it runs, so the mistake before a loop is one diagnostic beside the loop's `B010`s, while the same mistake on two calls is two. `init` is unchanged.

  **Instance names.** An instance is named by the value of its construct's `name()` opening, under whatever record key that opening has (`name("table")` records under `table`, `name({ as: "title" })` under `title`), else by its construct's name. `nameOf` in [`record.js`](record.js) is the one place that decides, for the builder and lowering alike; a slot, lambda slot or child construct called `name` renames nothing. `B002` for stateful instances is keyed by this name.

  **Ref ids** are unique within a Program and deterministic. The id is `<tag>.<slot>`, plus `#<index>` unless the slot is `once`, plus `.<key>` for a lambda under a `recordOf` key, plus `[n]` when several lambdas of one call share that key (or all lack one): `x.k#0.a[0]`, `x.k#0.a[1]` (two lambdas under `a`, whether a `listOf` or two `recordOf`s sharing the key), `x.k#0[0]`, `x.k#0[1]` (unkeyed, as `rest(lambda())` gives), `x.k#0.0` (the key "0", which `[n]` cannot be mistaken for). A lone lambda has no place. `<tag>` is the instance's name; two instances with one name (two unnamed instances of a stateless construct, or one name in two constructs) get `~2`, `~3`, … in record order (`t.k`, `t~2.k`), while `ref.on` keeps the real name. A last guard appends `~n` to any id still taken, so odd names and keys cannot collide. The fields Grammar's names (`swirl.pixel`) are unchanged. `step`'s `inferred` for a call with several lambdas: all keyed, an object by key (a key holding several lambdas has the list of their types); all unkeyed, the list in call order; a mix of keyed and unkeyed, the list of every lambda's type in call order.

  **Own keys.** A name-keyed slot's record is built with own properties, so an entry named `__proto__` is a key like any other and is lowered (not refused with `B004`).

## Codes

`D…` (a definition) and `B…` (a Program) are listed with their meanings in [`codes.js`](codes.js) (`DEFINE_CODES`, `BUILD_CODES`); D001–D015 are [rules.md](../../scripts/define-trial/docs/rules.md)'s, widened where the revised draft added keys. Beyond the draft: **D017** refuses two things of one construct that the record would put under one key (an opening argument, a child construct, a slot's name or `as`, `units` beside a unit slot or on the root, which takes the module scope's units, `calls` in a `record: "calls"` construct), **D018** refuses a slot or construct named like a property runtimes probe on every object (`then`, `toJSON`, `inspect`, `constructor`, `valueOf`, `toString`, `prototype`, `nodeType`, `asymmetricMatch`, `$$typeof`: the builder answers them with `undefined`, so such a method could never be called), **D019** refuses a `lambda()` in a construct's `opens` (not built yet), **D020** refuses a Dialect without a text view (above), **B011** is a convention's refusal, **B012** and **B013** are the module scope's, and **B014** and **B015** the binding-time params' (above). D016 (which refused `scalar()` before the nominal scalar was built) is retired and its number not reused. A Dialect's own check codes take its own letter; `B`, `C`, `D`, `L`, `P`, `S` and `V` are reserved, and `ctx.error` with one throws.

## Where the build departs from the draft

- A `once` slot's lambda id has no `#index` (above); `ref.index` is still passed. In a by-slot record (no `record: "calls"`) `index` counts in slot-declaration order, since the record keeps no order across slots.
- An opening `name()` (`field("domain-warp")`) is a label and takes any non-empty string; other names must be identifiers.
- A slot `check`'s `ctx.state` is always `undefined`: state needs each lambda's inferred type, so it exists only when lowered. State-namespace refs are checked by `lower`, not by `.build()`. A construct **without** state may name its namespaces in `names: { column: (record, { program, stateOf }) => [...] }`, functions of its record and other instances' final states; its refs into them are checked by `lower` too (`B003` with the did-you-mean, pinned at the call), so a chart checks its encodings against its table's last step without a state of its own. `names` beside `state`, a value that is not a function, or a namespace a `name()` declares into is `D015`.
- No `edits` on builder diagnostics: the builder has the call's place but not the file's text, so the replacement goes in `tip` (and `fix` from a check).
- A type `enumOf` holds strings only (the core's enums do); a shape `enumOf` may hold numbers.
- A builder in a template literal or `String()` is its description (`[field builder 'p']`), not an error.
- Unit slots in a `record: "calls"` construct go into `calls` like any slot; lowering finds them there.

## Not built

Effects, store rules, `emit` and inferred methods (every space is pure); fragments; build-time slots; Dialect imports; lambdas in a construct's opening arguments (`D019`).
