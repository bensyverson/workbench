# kit/define: the Definition API

Declares a Domain Language as data and generates the rest. `defineDialect` says what the language **means** (types, objects, intrinsics with each target's spelling and a reference implementation, the Library, Iteration Spaces, targets, slot conventions); `defineGrammar` says how a Program is **written** (constructs and their slots), and the kit generates the builder, its diagnostics, the record it returns and the lowering of every Runtime Lambda. The spec is [the draft](../../scripts/define-trial/docs/api-draft.md); this page says what is built and where the build departs from it. No Node built-ins. An agent building a language reads [START.md](../START.md), [API.md](../API.md) and the topic pages in [kit/docs/](../docs/) instead; keep them in step with this page when the API changes.

```js
import { defineDialect, defineGrammar, vector, exact, name, data, lambda } from "./kit/define/index.js";

const d = defineDialect({ name: "tiny", numberType: "f32", types: { vec2: vector(2, "f32") },
  spaces: { pixel: { pure: true } }, targets: { js: { accepts: "*", compare: exact() } },
  slots: { pixel: { params: ["vec2"], returns: "f32", space: "pixel" } } });
const tiny = defineGrammar(d, { root: "tiny", constructs: { tiny: { opens: [name()], slots: {
  pixel: { kind: "decl", args: [lambda("pixel")], once: true, required: true } } } } });

const record = tiny("t").pixel((uv) => uv.x * 0.5).build();   // { name: "t", pixel: "(uv) => uv.x * 0.5" }
const { lambdas, helpers, diagnostics } = tiny.lower(record);  // Kernels, through kit/lower
```

[kit/dialects/fields](../dialects/fields/README.md) is declared with this API: its [`dialect.js`](../dialects/fields/dialect.js) is the draft's worked example completed, and its builder is the one [`grammar.js`](../dialects/fields/grammar.js) generates. Its tests hold the generated builder to what the hand-written one it replaced built (`test/golden/hand-built.json`) and refused.

- **A Dialect value** ([`dialect.js`](dialect.js)). `defineDialect(def)` checks the whole definition and throws one `DefinitionError` holding every problem (`{ code, message, tip, path, file, loc }`: `path` is the key path inside the definition, `loc` the define call). It returns `{ name, numberType, def, intrinsics, library, targets, libraryFor(sources), text(state), environment(program, states?) }`. `intrinsics` has the shape of fields' table (`{ sig, ref, componentwise?, <target>: { call, prelude? } }`), `library` is `UnitDecl[]`, and `environment(program)` returns an [Environment](../lower/environment.d.ts) exactly as lowering reads it: type names resolved to core Types, each intrinsic a callable object plus a global, the hook's objects and globals merged in (a member or global it declares twice is `D007`, a `DefinitionError` like any other), and `slot(ref)`.
- **The Definition API's version** ([`version.js`](version.js)). `KIT_VERSION` (`"0.5"`, major.minor; 0.5 since declared Controls, which renamed the manifest's `elements` to `modules`) is exported from `kit/define`. A Dialect package's manifest names it in `kit`, and [kit/package](../package/README.md) refuses a package whose `kit` is not equal to it (before 1.0, a minor bump may break).
- **The text view.** Every Dialect gives `text(state)`: its screen and state as characters, sized for a model ([the architecture synthesis](../../project/2026-11-24-architecture-synthesis.md) §3.3). A Dialect without one, or with one that is not a function, is `D020`. The kit does not say what `state` is, since only the Dialect knows what its host shows: fields takes a rendered frame `{ width, height, pixels }` and draws it as at most 64 by 32 characters, a NaN pixel as `?` ([`text.js`](../dialects/fields/text.js)); the data Dialect takes one table `{ name, columns, rows }` and prints its columns with their types (an inferred enum as `enum(a, b)`) and its first 20 rows, a date as its UTC day (its number when Date cannot hold it) ([`dialect.js`](../dialects/data/dialect.js)). The kit does not yet call it: a workbench page or an agent tool will.
- **The run's state.** A Dialect may declare `state`, the shape of the **run's** state: the value `text(state)` and a UI's views are handed while a Program runs. It is not a Grammar construct's `state` (a build-time record of a construct, a different thing that happens to share the word). It is a plain object of member types in the Dialect's own vocabulary: `"f64"`, `"bool"`, `"str"`, a vector or scalar declared in `types`, `enumOf([…])`, `opt(t)`, `list(of, max)`, `list(of)` and `struct({ … })`; a nested plain object is refused with a tip to write `struct`, so there is one way to write it. Not objects (`object()` or a declared object): a run's state is data. The Dialect value gains `state` (as written), `stateType` (the resolved core Type, a struct, which `defineUI` reads and UI lambdas are lowered against) and `checkState(value)`, which returns every mismatch as `{ path, message }` (`player.x`, `bodies[1].mass`, `""` for the root; a missing member, an undeclared member, a list past its max (a list declared `list(of)` has none), a NaN or infinite number are mismatches; a vector is an array of its components, as at run time). With `state` declared the Dialect's `text` first checks its argument and throws an error naming every path, since a host handing the wrong shape breaks the contract; `text`'s own source is host JavaScript and is not checked statically. **`list(of)` with no max is allowed in a Dialect's `state` only** (Ben, 2026-11-25): there `stateType` resolves it to a list Type with no `max`, `checkState` applies no cap to it, and a UI lambda reads its `length` and indexes it but never loops over it (`defineUI` refuses that, below). Everywhere else (a slot's or a method's types, an object's members, a kernel type) `list()` still needs a positive whole max, `D011` (`D023` inside `state`, which also refuses a max that is not a positive whole number). A malformed state is `D023` (collected with every other problem). Optional: a Dialect with none (fields' state is a frame, the data Dialect's a table with columns known only per Program) keeps its untyped `text(state)` and has no `stateType` or `checkState`.
- **Per-Program state** ([`state.js`](state.js), [`dialect.js`](dialect.js); Ben, 2026-11-26). A Dialect may mark one struct in its `state` extensible, `struct({ <fields> }, { extensible: true })`, as a member or the item of a state list (or inside `opt`), with or without fields of its own. `environment(program)` then may return `state: { <field>: <type> }` beside `objects` and `globals`: the fields the Program's declarations add to that struct, in state types, so the data a Program declares (a particle's `.field`s) lives in the run's state, one field per declaration, with no cap. They are judged when the Program lowers, as its other additions are: a field the struct already has is `D007`, a type a state cannot hold is `D023`, and so is `state` from a Dialect that marks nothing extensible. More than one extensible struct, one inside a `union`, a field the Program declares that is itself extensible, or `extensible` that is not `true` is `D023`; `extensible` outside `state` is `D011`. The Dialect value gains `stateFields(program)` (the fields as declared, `{}` when none), `stateTypeFor(program)` (the `stateType` with them added, made once per record) and `checkState(value, program)`: with a Program it checks the extended shape, and a field in the extensible struct the Program does not declare is a mismatch marked `outside: true`, memory kept outside the Program's state, which a run reports as N003 ([kit/run](../run/README.md)); without one it checks the struct's own fields and lets others through. `text(state, program?)` checks the same way. The content key and replay cover the fields, since they are the record's and the state's. A UI's paths and a value output's `from` are still judged against `stateType` alone, so they read the Dialect's own fields, not a Program's.
- **Nominal scalars.** `types` holds vectors and scalars: `date: scalar("f64", { note })` is a named type stored as an f64 (the core's `{ scalar, of: "f64" }`, [kit/ir](../ir/README.md#nominal-scalars-m3)). Its name may be used wherever a type is named (slot params and returns, members, globals, intrinsic signatures, convention functions); it compares only with its own kind (an optional one narrows by `d != null`, which keeps the epoch present; `d !== null` narrows nothing: [kit/lower](../lower/README.md)) and is no constructor: a value enters through a parameter, a member or an intrinsic, and a lambda calling the type's name is `B008`. A lambda that infers a scalar hands its name to a construct's `step`. Another backing is D002, options other than `{ note: string }` D011, and `scalar()` written inline where a type is named D002. A type, vector or scalar, named like a built-in type (`f32`, `f64`, `bool`, `str`, `null`, `void`, `sampler`, `unknown`) or a one-capital-letter type variable (`T`) is `D007`, since it would take that name over everywhere it is written.
- **Slot conventions.** A static convention is resolved once; a function `(ref, program, state)` is called per lambda, and what it returns is checked as a static one is (`D002`, `D005`, and its `may` and params as below: `D021`, `D022`). `object(label, members)` in a convention makes an object type on the spot, named by its label (numbered when the same label carries other members). The kit makes the `helper` and `const` conventions; a Dialect may not declare those names, nor `method`, which lowering reads specially (`D007`). A generated convention's `forbid` is empty and its `may` says what its lambda may do ([Per-slot effects](#per-slot-effects)); the generated `const` convention forbids every effect, as DMG's does, unless the Dialect declares `constants: { calls: "pure" }`: then a constant may call a helper (`.const("K", "g()")`), every other effect stays forbidden, and the helper's own effects are judged by the same rule (lowering lists a callee's effects beside the call), so a constant calling a helper that reads a writable member or a total is L004. A constant is lowered in each inference pass, after the helpers' signatures so far, so it has its helper's result type, and its calls are call sites that type the helper's parameters (`const K = h(0.25)`). `calls: "none"` is the default; any other value, or a `constants` that is not `{ calls }`, is D011, and another key D001. fields declares `"pure"`, as its hand-written Dialect allowed; DMG, hand-written, keeps forbidding every effect.
- **The generated builder** ([`grammar.js`](grammar.js), [`record.js`](record.js), [`shapes.js`](shapes.js)). `defineGrammar(dialect, def)` returns the root builder, with `.lower`, `.dialect` and `.grammar` on it. Each construct instance's builder has its slots, its child constructs and its ancestors' methods (calling one ends the child); builders are mutable, so `b.param(…)` without reassigning works. An unknown method throws `B001` at once with a did-you-mean; everything else is collected with the call's `file` and `loc` (from the stack) and `.check()` returns the list, `.build()` throws a `BuildError` carrying all of them or returns the record. `B002`, `B004`, `B006`, `B007`, `B009` and slot `check`s are found at the call; `B003` (Program-namespace refs), `B005`, `B008`, `B012`, `B013` and construct `check`s at `.check()` / `.build()`, when every name is known.
- **Per-instance names** (leaf `3mNV24`). `name(ns, { within: "account" })` declares a name unique only within the nearest enclosing `account` instance (the instance itself, when `account` declares it): B002, and B003 with its did-you-mean and `name one of:` tip, look only at that instance's names, and their messages say which (`'food' is already declared as a flow in account 'a'`). A `ref(ns)` resolves in the nearest enclosing instance of the `within` construct, from the instance or any child under it, earlier or later in it. Chosen as the minimal shape: the record is unchanged (a name-keyed slot is already an object per instance), and a ref to a scoped namespace from a construct outside every instance of its `within` (neither it nor under it) is refused at `defineGrammar` (D011), since there is nothing it could name unambiguously; a qualified ref from outside is not built. `within` must name the declaring construct or an ancestor (else D011, with a did-you-mean when it names none), one namespace has one scope (two `name(ns)` with different `within`, or one with and one without, D011), and `name()`'s options are `{ within, as }` only. Without `within` a namespace spans the Program, as before. The state namespace (`stateOf`) stays Program-wide whatever an opening name's `within`. **One duplicate, one diagnostic** (`AitCG4`): a stateful instance whose opening name its own namespace already refused (B002) is not reported again by the state namespace; one whose name clashes only there (another construct's instance) still is. Messages put `an` before a vowel (`an account`).
- **Number bounds** (leaf `S2OAyB`). A number shape takes `data("number", { min, max, whole })` (with `as` beside them at an argument), and the same `data("number", { … })` stands anywhere inside a shape (`data({ opening: data("number", { min: 0 }) })`, in `oneOf`, `listOf` …), where it takes no `as`. A value below `min`, above `max` or, with `whole: true`, not an integer is B004 naming the bound (`argument 1: 0 is below its min, 1`). **A record holds finite numbers only** (Ben, 2026-11-25, trial 4's hidden r22d and r22e): `Infinity`, `-Infinity` and `NaN` are B004 wherever a number stands (`"number"`, a `"number[]"` item, a number inside any shape), with or without bounds (`key 'maxRate': Infinity is not a finite number, …`); inside a `oneOf` such a value still picks the number's form, so the message says what is wrong rather than listing the forms. A param's own non-finite declared value is said once, by the param check below (`'n' takes a finite number, not NaN`), and a later call that receives that value through `$` is not refused again for it. `whole` is a check on the value at build, not a type: the core has no integer type. A bound on any shape but `"number"`, an unknown key, a `min` or `max` that is not a finite number, `min` above `max`, or `whole` not a boolean is D011. A path into a list now names its element `item n`, not `argument n`.
- **A required child** (leaf `CmIJKc`). A child construct takes `required: true`: each instance of its parent with none of it is B005 at `.check()` / `.build()`, as a missing required slot is (`budget 'b' has no account`, tip `add .account(…)`). `required` on the root, or not a boolean, is D011.
- **The record** is the draft's "The record": openings under `as`, else their namespace, else `name`; a slot whose first argument is `name()` as an object from name to the rest; other slots as one value (`once`) or a list; `units: [{ name, kind, src }]`; children as lists under their construct's name; `record: "calls"` as `calls: [{ slot, args }]`. A lambda is its source text wherever it was passed.
- **Only a lambda's text is compiled.** A function lambda is read by its source text (`String(fn)`), so a variable it closes over is not captured by the lambda itself; what it reads from the file's top level comes in through the module scope (next). A bound function has no source (its text is native code) and is refused as `B007`.

  > **Superseded 2026-11-24 (leaf `gS9dBz`, Ben's ruling in [the architecture synthesis](../../project/2026-11-24-architecture-synthesis.md) §3.2):** this said that a name in a lambda means the Dialect's or the Library's even when a local of that name is in scope (a local `fbm` binds to the Library's `fbm`). A top-level binding named like a Dialect or Library name is now refused instead (`B002`, rename it): one name, one meaning.
- **Strictness options** (leaf `ydiY5Y`, decision MpZZsU, from the H5 run). Opt-in per Dialect, each D011 when its value is not one listed (boolean-only conditions are not an option: they are always on, so a number, string, vector or optional as an if or ternary test, or an operand of `!`, `&&`, `||` in a test, is L003 in every Dialect, and `conditions` is an unknown key); `vector(2, "f64", { multiply: "scalar" })` (vector * vector is L003; `"componentwise"` is the default; it sits beside `aliases`; a number / vector is L003 either way); and a convention's `body: "block"`, static or from a convention function (an expression body is L012). Not opt-in: a slot whose type is not `void` and not optional, and a helper that returns a value anywhere, must return on every path and have no bare `return;` beside a value (L003, one, at the bare return; [kit/lower](../lower/README.md)). **Helpers nothing calls**: `helpers: { may, check: "all" }` (`"called"` is the default; another value is D011) makes `build()` turn every function in the module scope into a unit, read or not (the host's own default export, which `run` leaves out, excepted), so lowering checks it ([kit/lower](../lower/README.md), "Helpers nothing calls"); one that is not a Runtime Lambda is refused at build (B007 or B012, naming the helper), and what it does through a parameter is not checked. **Rejected members**: an object's `rejected: { random: { message, tip?, fix? } }` answers a lambda's use of that member with your message (an L002, with `fix` in the tip as `write …`); a name that is also a member is D007. **Units**: `BuildOptions.keywords` (`{ name: "const" | "let" | "function" }`, from `topLevelBindings` and `topLevelFunctions`) is copied onto each unit as `keyword`, and the root construct's `check` now receives the record with its `units`, so a Dialect can refuse a top-level `let` (the particles reference does, R009). **Shadowing** (issues `lv8O0x`, `JYmuWM`): `BuildOptions.file`, the Program file's text (`moduleScope` passes it), makes the builder run `buildTimeShadows(file, handed)` itself at check and build: the names the file declares at its top level and again in the export's build code, a method, or any function that holds another function (never a parameter of a function that holds none; fail closed, see [kit/parse](../parse/README.md)), leaving out each Runtime Lambda it was handed as a function and everything inside it, matched by its exact text (`String(fn)`) when the file writes that text as exactly one function. A lambda's read of such a name is B013 ("declares it at its top level and again below it, in build-time code or a helper"), since the kit would resolve it to the top-level binding while the lambda's text may mean the inner one; a binding that is itself refused (B007, B012) gets only its own code. So a lambda's own parameter beside a query callback (`(p, dt) => p.items.some((q) => q.x > dt)`) no longer refuses another lambda's read of a top-level `dt`, while a build-time callback or helper holding a lambda still counts. Still fail closed: a lambda given as text proves nothing about the file's arrow of that text; a text the file writes twice excludes neither copy; a top-level helper a lambda reads was not handed, so its parameters count. One shape fails open: a function both handed as a lambda and called at build time, where the call hands the builder a lambda that reads the function's parameter; the text is matched, not its uses, so that read is not B013 (the handed copy then calls a builder method on its parameter, which lowering refuses as L002 unless the object has a member of that name; local probe, 2026-11-27). `BuildOptions.shadowed` is still taken, a plain list of names that refuse whatever `file` says, for a host without the text; until `JYmuWM` it was `moduleScope`'s. The options travel as the Environment's `vectorMultiply` and a slot's `body`. A lambda's extra parameter (L010) no longer draws an L001 for each use of it.
- **Module scope** ([`scope.js`](scope.js)). `.check(options)` and `.build(options)` take `{ scope?, sources?, buildTime? }` (`BuildOptions` in [`define.d.ts`](define.d.ts)): `scope` is the Program file's top-level bindings by name, `sources` each top-level `const` declaration's initializer text by name (`topLevelBindings`' `init`, filtered to `keyword: "const"`: a `let` can be reassigned to an arrow made by other code with the same text, so its text vouches for nothing), `buildTime` the names the file declares only inside build-time code. A host gathers them, since the kit has no module loader: **`withScope(text)`** ([`module-scope.js`](module-scope.js), exported from kit/define, no Node built-ins) is the module's text with an epilogue that exports its top-level bindings (`SCOPE_EXPORT`, and `FUNCTIONS_EXPORT` for the declarations' captured values; last, so every line keeps its number; a file the scan cannot read comes back as it is), the host imports that its own way, and **`moduleScope(text, mod)`** gives the whole `BuildOptions` from the text and the imported module (throwing `ScanError` when the top level cannot be read); the define-trial checker and the page host ([kit/page/host](../page/host/README.md)) both use them, and until leaf `dXp5WO` each kept its own copy. Underneath, the values come from the module, the rest from the file's text with `topLevelNames`, `topLevelBindings` and `buildTimeNames` ([kit/parse/toplevel.js](../parse/toplevel.js), which parses the file with the vendored acorn and reads its tree; no Node built-ins). A lambda's free name that the free-name rule does not allow and the scope holds resolves into a Program unit, as DMG lowering takes a program's top-level consts ([kit/lower](../lower/README.md), "Top-level helpers"): an arrow function is a helper (`{ kind: "fn", src: String(fn) }`), whose own free names resolve the same way, transitively; plain data is a baked constant whose source is the value written out (`{ kind: "const", src }`). **A helper must be the arrow its `const` declaration writes:** `String(fn)` must equal `sources[name]`, else `B012`. **A top-level `function name(a, b) { … }` is a helper too** (decided 2026-11-25), exactly its arrow twin `const name = (a, b) => { … }`: the host puts the declaration's text (`topLevelFunctions`, kit/parse/toplevel.js, whose `init` is `String(fn)`) in `sources[name]`, and the unit's `src` is the equivalent arrow text (`functionAsArrow`), so lowering is unchanged downstream. The same B012 guard applies (a function declared inside the export's block body has no top-level text and is B012, as a nested arrow is). Still B007: an async function, a generator, and `const f = function () {}` (a function expression, with the arrow tip); a body outside the subset is the parser's diagnostic, as for an arrow. A `const f = function f() {…}` whose own name matches is read as the declaration, which means the same. **What a host must guarantee for a function declaration's text to vouch:** a function binding is reassignable like a `let`, so its text proves nothing about the value in `scope`; the host must pass `sources[name]` only when `scope[name]` is the very function the declaration made. Declarations are initialized before any module code runs, so a host can capture each one's value first (the define-trial checker prepends a capture on line 1) and drop the text of any whose scope value differs; a mismatch is then B012. The host may also pass `buildTimeBindings`, the part of `buildTime` the file binds as a `const`/`let`/`var` or `catch` variable (`buildTimeBindings(text)`): a name in it keeps B013's build-time wording even when another lambda has a parameter of the same name. The scan's `init` leaves out comments around the initializer and parens that wrap it, as `String(fn)` does, so `const f = (x) => x * 2 // note` and `const f = ((x) => x * 2);` are helpers. An arrow made by another function (`const mk = (k) => (x) => x * k; const triple = mk(3)`) closes over that function's `k`, which its text loses, and resolving its free `k` against the module scope would silently read some other `k`; the fix is to declare the helper itself at the top level. Without `sources`, no arrow is a helper. **A host must not guess between two declarations of one name:** `topLevelBindings` throws a `ScanError` (naming the name and the second declaration's line) when the file does not parse as a module (a name declared twice, which a module cannot do, sets its `binding`), so none of its initializers can vouch for a helper; the define-trial checker reports it as `LOAD` and checks nothing more of that file. The refusal lives in the scan, not in this module, because `sources` is a plain record by the time it gets here: a host folding the scan's list into it (as `Object.fromEntries` does) would already have kept one of the two. Plain data is a finite number, a string, a boolean, and arrays and plain objects (identifier keys) of them; anything else (null, NaN, a Map, a class instance, a builder chain, a function inside an object, a cycle) is `B012`, and a function that is not an arrow `B007`, each with a fix. The value is read through its own property descriptors, so no getter runs: an accessor, a non-enumerable or Symbol key, the key `__proto__`, an array's hole or extra key, and an Array subclass are each `B012`. A Proxy cannot be told from a plain object, so one is baked as what its traps report. The constant is the value the host saw, not its initializer's text, so `const K = Math.PI / 2` works. A free name in `buildTime` is `B013` ("declared only inside build-time code"), with the fix to move it to the top level or write its value into the lambda's text; when the name is a parameter of another lambda of the file (spawn's `rng` read by update) the message says that instead ("a parameter of another lambda, not a name this lambda can see", tip: pass it in or move the use), still one B013; any other free name stays `B008`, whose tip then also offers the top level, except JavaScript's value globals `Infinity`, `NaN` and `undefined`, whose tip says to use a finite number or a value of the type expected (until H5, 2026-11-25, it offered `$.Infinity`, which no param can hold, and a top-level binding that would shadow the global). Every scope binding named like a Dialect name (an intrinsic, global, type, conversion, a name the environment hook adds), a Library entry or a Program unit is `B002` at the root's call, resolved or not. **Where the units land:** `.build()` puts them first in the root record's `units`, whatever the root's slots (first, so a `.const` may read a top-level constant: a constant sees only those before it), so `lower(record)` stays a function of the record (lowering reads `units` on every instance); so the root construct may put nothing else under the record key `units` (`D017`). Without `scope`, nothing resolves and the record is as before.
- **Binding-time params** ([`params.js`](params.js); the ruling is [the binding-time design](../../project/2026-11-24-binding-time-design.md), Option A). A Program file exports a function of its params, `export default ($) => program(…)…`, and `run(programFn, { values?, scope?, sources?, buildTime? })` calls it with a `$` that answers each declared param with the host's value, else its declaration's `value`, and records the read; then it checks and builds the Program the function returned and returns `{ record, diagnostics }` (`record` null on an error, a `BuildError` thrown at a call included). **A Program file builds one Program:** code that opens the root a second time in one run (`const spare = particles("spare")…; return particles("base")…`) is `B016` at the second opening, whichever of the two it returns (Ben, 2026-11-25, hidden r22p; until then it was the `TypeError` below, since the run's Program is the first opened). **Code that opens the root and returns anything else** (`{ program: chain }`, a number, what `.build()` returns, nothing) is `B017` on the run, pointed at the opening (the coordinator's ruling, 2026-11-25, hidden r22q: the author's mistake, not the host's). A host's mistake throws a `TypeError`: a function that opens no root and returns no builder (the define-trial checker reports it as `C001`), or a value for an undeclared param (reported even when the Program's code stopped at a `BuildError`, the message then naming where it stopped, since a param declared after that point is not known yet), or a value that does not fit its declaration. Every host value is checked at `run`, whether build-time code reads it or only a Kernel does (and when build-time code reads it, before it gets it): it must have the type of the declaration's `value`, be finite when a number, lie inside the declaration's `min..max` and be one of its `options` when it has them. The host's values then replace the declared ones in the record's param declarations, so `record.params` says what was built. The Grammar names its param slot, `params: { slot: "param" }`, a root decl slot taking a name and a declaration (else `D011`); the Dialect names the object lambdas read params through, the name they read it by, and its run-time-only members, `params: { object: "Uniforms", name: "u", runtime: ["t", "aspect"] }` (else `D011`); the kit owns no param construct. A build-time read is folded: the value is in the record where the code put it. The record keeps the reads under `reads` (`{ param, value, by, file, loc }`; `by` is the builder call made next after the read, `top.limit#0` (`#n` counts that slot's earlier calls, as its lambdas' ids have it; the tag is the instance's name, `<name>~2` for a repeat, as in Ref ids, worked out from the instances made so far), or `table "top"` for an opening, or null when none came after; it orders the read among the calls and says nothing about which call used the value, so a value read early and passed late is placed before the next call, its `loc` still right; the root may put nothing else there, `D017`). `grammar.lower(record)` adds `params`, each declared param's binding time, `{ build: [{ by, file, loc }], kernels: [lambda ids], live }`, the Kernels found by their loads of the Dialect's params object (a Program helper as `helper 'name'`), `live` when nothing read it at build; `bindingText(lowered)` prints a line per param, saying where each build-time read was and which call came next (`topN   folded at build, read at 05-query.js:22 (before top.limit#0)`, `year   uniform, read by top.filter#0`; a read after the last call says `(after the last builder call)`). `needsRebuild(record, changed)` is true when build-time code read a changed param. A read before the param's declaration, or of an undeclared one, throws `B003` (with a did-you-mean); a run-time-only member, `B014` with the fix to read it in a lambda, also when it is tested with `in` (`"t" in u`). Before the Program opens its Dialect is not known, so a read then of a name some defined Dialect knows only at run time answers `undefined` and is decided when the Program opens: `B014` if that Program's Dialect lists it (fields' `u.t`), else `B003` (a data Program's `$.t`), placed at the read; if no Program opens, `B003`, which names no Dialect's object. Before it opens, `in` is `B015`. **Every refusal `$` makes (`B003`, `B014`, `B015`) is kept on the run as well as thrown**, so build-time code that catches one (`try { T = u.t } catch {}`) still gets no record and the refusal in `diagnostics`; an exception build-time code throws after a refusal is taken as its knock-on, and the refusal is reported instead. **The one exception is a host's bad value:** the `TypeError` for a value that does not fit is kept on the run when `$` throws it, and `run` rethrows it whatever build-time code did (caught it, caught a `B003` as well, wrapped it, or went on and failed on the missing value), since it is the host's mistake and outranks every refusal. **A param's declared `value` is held to its own declaration** by the same rules as a host value, at the param's call: `B004` (collected, `arg: 1`) when it is not finite, outside `min..max` or not one of `options`, so `.param("n", { value: 99, min: 1, max: 5 })` is refused rather than folded; when the Dialect's own check refused the call already (fields' `F001`, a value outside its range), that is reported alone. A date param's string (`{ value: "2026-01-01", kind: "date" }`) is not checked: the `date` kind is the data Dialect's declaration, and how its string becomes a date is the host's (kit/dialects/data), so the kit has no date format to hold it to. **`$` is read by name only.** Any other read (`"topN" in $`, a spread, `Object.keys`, `Object.entries`, `JSON.stringify`, a rest pattern `{ a, ...rest } = $`, a property descriptor) is `B015`, with the fix to read each param by name, `$.name`: a recording `$` could neither answer it truly nor record it. Destructuring by name (`const { topN } = $`) is a read by name. `$` answers the properties runtimes and test libraries probe (`then`, `toJSON`, `inspect` …, D018's list) with `undefined`, so a param may not take one of those names: `B004` at its declaration, with the fix to rename it. The three that are Object.prototype's own (`constructor`, `valueOf`, `toString`) stay legal param names, since a lambda reads them like any other, and `$` answers a declared one by name (a runtime that probes one then records a read, which can only make `needsRebuild` say yes more often). One form for a value from a param: a zero-parameter lambda where a slot takes a value (`.limit(() => $.topN)`) is `B004` with the fix `.limit($.topN)`. Runs do not nest (one module-level run, safe because builds are synchronous). Not built: caching, a module loader (the host re-runs the function), data-flow attribution.
- **The free-name rule** (`B008`) allows a lambda's own names, the Dialect's globals (with those `environment(record)` adds), intrinsics, Library entries, vector constructors and conversions, and the Program's units. The tip names the Grammar's `const` unit slot, and `$.name` when the Dialect declares `$`. A member of a JavaScript global (`Math.sin`, `console.log`) gets another tip: the bare name when the lambda can see one of that name (an intrinsic, global, Library entry or unit: `use sin, not Math.sin`, `use PI, not Math.PI`), else `Math is not in the language`. The diagnostic's `lambda` field carries the lambda's source and the place inside it (also on a `B007`), so a tool can show the line.

- **`oneOf` with a lambda, and the ambiguous string.** The record keeps a lambda as its source text, which a `"string"` form also takes, so a record's lambdas are found again by matching its text, and a call and its record must choose the same branch. The rule: among the forms a value fits, the one holding the most lambdas wins, the first on a tie. So a string that parses as an arrow function is the lambda (`.y("() => 1")` is the lambda, as `.y(() => 1)` is), any other string is the ref or string (`.y("a")`), and a function is always a lambda; and it holds when the lambda sits inside a compound form (`oneOf({ f: lambda("v") }, { f: "string" })` with `{ f: () => 1 }`, or `oneOf(listOf(lambda("v")), "string[]")` with `[() => 1]`), wherever the `oneOf` sits. A string that is meant as a name or text yet parses as an arrow function cannot be given to such a `oneOf`. Text that holds `=>` but does not parse stays text (or a ref), and the call also gets a `B007` **warning** naming the parse error; a warning does not stop the slot's `check` or `.build()`. A function that is no Runtime Lambda (`async () => 1`, a method shorthand) is the lambda form's `B007`, with its detail, not a `B004` that lists the forms. A value whose record form would be read as another branch than the call took is `B004` at the call: with `{ f: lambda, g: "string" }` and `{ f: "string", g: lambda }`, the call `{ f: "() => 1", g: () => 2 }` fits only the second (a function is no string), but its record, both fields text, ties and would be read as the first, so its `g` lambda would never be lowered. Both fields as text (or both as functions) agree, and take the first form.

- **Lowering** ([`lower.js`](lower.js)) lives on the grammar, because only the grammar knows where lambdas sit in a record: `grammar.lower(record)` returns `{ environment, lambdas: [{ ref, src, result }], helpers, diagnostics, states, params }`. Every lambda goes through `lowerProgram` with the Library units it uses and the Program's units, in that order (as `lowerField` does). A lambda's slot id is `<on>.<slot>#<index>`, plus `.<key>` inside a `recordOf`; a `once` slot drops the index (`swirl.pixel`), so Kernel names match the hand-written Dialects'. Stateful instances share one namespace whatever their construct (an unnamed one goes by its construct's name), because `stateOf(name)` and `states` find an instance by name alone: a second with a name already taken is `B002` at `.check()`. A construct with `state` is built call by call: `init`, then per call its state-namespace refs are checked against the state at that step (`B003`, with a did-you-mean), its lambdas are lowered with that state (the convention's third argument) and their inferred types (in definition terms: `"f64"`, a vector's name, `enumOf`, `opt` …) go to `step`. A `stateOf` loop is `B010`: each instance on the loop is told it depends on its own state, one that only reads a looping state is told so. A convention that returns a reason is `B011`. Lambda type errors keep lowering's own `L…` codes. Every diagnostic in the flat list is tied to where it came from: `B003` and `B011` are pinned at the call (also in a by-slot construct, whose record keeps each call's place), `B011` carries the refused lambda's `ref`, and a lambda's `L…` diagnostics carry `file` and `ref` (their `loc` is inside the lambda's source), a helper's or constant's carry `unit`.

  **Step context.** `step(state, call, inferred, ctx)` gets `ctx = { program, stateOf, error }`. `program` is the record, as init's; `stateOf(name)` is another instance's final state, the same lookup as init's (by instance name, built lazily on first ask, `undefined` for an unknown name), so a join reads `ctx.stateOf(call.args[0]).columns` at the step where the join happens, with no closure in the state. A `stateOf` loop that goes through `step` is `B010`, attributed exactly as one through `init` (each instance on the loop depends on itself, one that only reads it reads a looping state). `error(code, message, options?)` refuses the call with the Dialect's own code; `options` is a check's `{ tip, arg, suggest, fix }` (one function, `dialectError` in [`codes.js`](codes.js), makes both), and a string there is taken as the tip: a diagnostic pinned at the call (`file`, `loc`, as `B011`) carrying `on` (the instance) and `slot`, collected into `lower()`'s diagnostics in call order; a code that is not one letter and three digits, or starts with a reserved letter, throws, as a slot or construct `ctx.error` does. **The state `step` returns still applies after an error**, so later calls and lambdas type against it and one mistake yields one diagnostic; the diagnostic is what makes the Program fail. A `stateOf` loop re-runs the steps of the instances on it for each instance that is told about it; a call reports each of its diagnostics (`B003`, `B011`, `ctx.error`) once however often it runs, so the mistake before a loop is one diagnostic beside the loop's `B010`s, while the same mistake on two calls is two. `init` is unchanged.

  **Instance names.** An instance is named by the value of its construct's `name()` opening, under whatever record key that opening has (`name("table")` records under `table`, `name({ as: "title" })` under `title`), else by its construct's name. `nameOf` in [`record.js`](record.js) is the one place that decides, for the builder and lowering alike; a slot, lambda slot or child construct called `name` renames nothing. `B002` for stateful instances is keyed by this name.

  **Ref ids** are unique within a Program and deterministic. The id is `<tag>.<slot>`, plus `#<index>` unless the slot is `once` (`<index>` counts the calls of that slot alone, from 0: the k-th `op` is `s.op#<k>` whatever other slots hold), plus `.<key>` for a lambda under a `recordOf` key, plus `[n]` when several lambdas of one call share that key (or all lack one): `x.k#0.a[0]`, `x.k#0.a[1]` (two lambdas under `a`, whether a `listOf` or two `recordOf`s sharing the key), `x.k#0[0]`, `x.k#0[1]` (unkeyed, as `rest(lambda())` gives), `x.k#0.0` (the key "0", which `[n]` cannot be mistaken for). A lone lambda has no place. `<tag>` is the instance's name; two instances with one name (two unnamed instances of a stateless construct, or one name in two constructs, or one `name(ns, { within })` name in two instances of the enclosing construct) get `~2`, `~3`, … in record order (`t.k`, `t~2.k`), while `ref.on` keeps the real name. A last guard appends `~n` to any id still taken, so odd names and keys cannot collide. The fields Grammar's names (`swirl.pixel`) are unchanged. `step`'s `inferred` for a call with several lambdas: all keyed, an object by key (a key holding several lambdas has the list of their types); all unkeyed, the list in call order; a mix of keyed and unkeyed, the list of every lambda's type in call order.

  **Own keys.** A name-keyed slot's record is built with own properties, so an entry named `__proto__` is a key like any other and is lowered (not refused with `B004`).

## Seams: ports, frames, inputs, handles

What a Dialect offers and accepts across a seam, in [kit/seam](../seam/README.md)'s vocabulary ([the seams draft](../../project/2026-11-25-seams-draft.md), as ruled 2026-11-26). Four optional `defineDialect` keys, judged with the rest (D024–D030, D032; [`ports.js`](ports.js)):

- **`ports.out`**: `{ seam, from?, note? }` per output. A value output reads the run's `state` by a path (`"score"`) or a UI-style value lambda (`(s) => [s.player.x, s.player.y]`, which may build a point or vector from scalars as an array literal of exactly its dims). **An Event output has no `from`**: a runtime pushes its records in its step (the clocks draft, question 3); a `from` on one is D026.
- **`ports.in`**: `{ seam, note?, default? | required: true, type?, delivery?, record? }` per input. A value input has a `default` or is `required`, and lambdas read it through the `inputs` object as its local type (`inp.radius`). An Event input has a `delivery`, `"reliable"` (the default) or `{ keepLast: n }`, recorded on the Dialect; the queue bound it implies is checked at composition from the runtimes' per-step maxes (kit/compose's S116; below, Runtimes).
- **An Event input's field defaults** (Ben, 2026-11-26). A top-level field of an Event input's record may declare a default in its seam, `<field>: <type> = <value>` (a number, `true` or `false`, a `'string'` or a list such as `[0, 1]`; [kit/seam](../seam/README.md)). A producer whose record lacks the field may then feed the input: the wire fills the default (kit/compose plans it as the wire's `fill`, and the run adds it after the conversions, as the consumer's own value), and never computes a value. The fill always wins: compose planned it because the producer's seam lacks the field, so a stray field a runtime pushes under that name is replaced, and each record gets its own copy of a list default. A wire that drops a producer field and fills a compatible field of the consumer's is S206, a warning that names the likely rename. A field with no default must still come from the producer (S202). A default that does not fit its field, on an output's record, on a value input's record or on a nested record's field is `D028`; a record-typed field takes no default. Lambdas reading the record see the field either way.
- **An Event input's record** reaches lambdas through `record: { name, slots }`: the kit makes a read-only object of the record's fields and a global `name` for it, and only the listed slot conventions may read it (any other lambda's read is L004, since each field's read is the effect `read <name>.<field>` and only those slots' `may` lists `read <name>`). The name may not be a global, object, intrinsic, type, the inputs' or params' name, or another input's record name (D032). **The global is optional** (ruling 6, 2026-11-26): it is null in a listed slot the runtime calls without a record (a spawn by rate), so its type is the record object made optional, a lambda checks it first (`<name> != null`, which lowers to `present`, or `if (<name> == null) return;`), and an unchecked read is L008, whose tip names the check. A check on a global narrows it as one on a `const` local does (a lambda cannot assign a global; kit/lower's `optionalGlobal`). A read in a slot not listed is still L004, and an unchecked one there is L008 as well. kit/run binds the name in each Kernel's closure, set from `ctx.globals` as each call starts, so `ctx.globals.<name> = null` (or never set) reads as null.
- **A named call's lambda** carries `alias`, `<instance>.<slot>.<name>`, in the lowering's `lambdas` when its slot's first argument is a `name()` and the call has one lambda with no `recordOf` key (ruling 1, 2026-11-26); kit/run hands it to the runtime beside the positional id. A declared name is unique in its namespace (B002), so no two calls share one; an alias an id already spells is left out.
- **`frames`**: `{ dims, note, extent? }` per frame; `extent(record)` gives the box `{ min, max }` the frame spans for a built Program. The kit declares `s` (seconds) for every package; a package frame named `s` is D030. A port or a frame named `then` (a runtime probes it on every object, so its handle could not be read) or `__proto__` is refused too (D024, D030). A 1-D frame holds a position (`point1@<frame>`, a plain `f64` local type) or a quantity (`f64@<frame>`).
- **`edges(record)`**: `[{ from, to, scale, offset }]` between the Dialect's own frames. It is a key of the Dialect beside `frames`; an `edges` inside a frame is D030, whose message says so and shows the fix.
- **`inputs: { object, name }`**: the object (declared empty) the kit fills with one member per value input, and the global (declared) lambdas read it by.
- **Draw ports** ([`draw-ports.js`](draw-ports.js); the draw-list draft, as ruled 2026-11-26). A `Draw<max>@<frame>` output (a 2-D frame) takes a builder instead of `from`'s path or value lambda: `from` (a whole list), `each` and `from`, `pen` or `layers`, and optionally `max` (a whole number or `(record) => <n>`); [kit/draw](../draw/README.md) reads it (J001, and each layer held to the Runtime Subset with the subset's own S codes) and the output carries it as `draw` (its layers, their sources and op kinds), with no `from`. A builder reads the record as a parameter and the inputs and params through their globals, Draw inputs included (ruling 4); those two, the intrinsics and the page globals ([`page-globals.js`](page-globals.js)'s `PAGE_GLOBALS`, an explicit frozen list, today only `Math`) are the only globals it is lowered with, since they are all a run gives it (another Dialect global is L001, leaf `9t99go`). A Draw input takes no default, `required`, `delivery`, `record` or `type` (J001): unwired it is `[]`; like a value input, it needs the Dialect's `inputs` object. `grammar.lower(record)` lowers each builder layer through kit/lower ([`draw-lower.js`](draw-lower.js): the state, the record typed from its value, `$`, the inputs with each Draw input a list of ops, the result typed from kit/draw's op table; its L codes at the Dialect's site with its `port`, as an output lambda's are) and adds `seams.draws`, each Draw output's max for that Program and its layers' lowering results (J010 past the seam's ceiling), and `seams.drawHelpers`, the Library units the builders call.
- **`colors`** (`{ <name>: "#rrggbb" | "#rrggbbaa" }`) and **`images`** (`{ <name>: { size, cell?, file?, note } }`): the names a Dialect's draw ops use (J003), carried as `dialect.seams.colors` and `dialect.seams.images`. An image's `file` is the package path of the PNG that holds its pixels (a data file of kind `image`, below).
- **`files`** (`{ <name>: { kind, path, note } }`; [`data-files.js`](data-files.js); the package format draft's ruling of 2026-11-26): the data files the Dialect reads besides its pictures, each by its package path, with a `kind` of `text`, `json` or `csv` that tells the host how to decode it (`DATA_KINDS` adds `image`, an image's `file`). A malformed entry, a kind of `image` (a picture is declared once, in `images`), a `.js` path, a missing note, or one path named twice (here or by an image) is **D034**. `dataFiles(dialect)` lists every data file as `{ path, kind, from }` (`from`: `files.<name>` or `images.<image>`); [kit/package](../package/README.md) checks each when the package loads (K017–K019).

The Dialect value carries the parsed seams as `dialect.seams` (`out`, `in`, `frames`, `edges`, `inputs`) and where it was defined as `dialect.site`. A value output's path and lambda rules are judged at `defineDialect` (D026, D027); what a lambda gives, and each `extent(record)` and `edges(record)`, need a Program, so `grammar.lower(record)` judges them ([`port-lower.js`](port-lower.js)) and adds `seams: { extents, edges, outputs }` to its result. Those diagnostics are the Dialect's: placed at `dialect.site` with the `port` or `frame` they concern.

**Handles** ([`handles.js`](handles.js)). Every generated builder, of any construct, answers read-only `.out`, `.in` and `.frame`: frozen objects whose own keys are the declared names, each a frozen handle `{ program, part, dialect, side, name, known, seam | dims }`. Any other name gives a handle with `known: false`, which kit/compose reports as S111 with what the part has. They live here, not in a wrapper, so a builder diagnostic still points at the author's line (`site.js` skips this folder's frames). A handle read as a number or a string (arithmetic, a comparison, a template) returns NaN and records the read and its site on its Program (`valueReadsOf(program)`), which kit/compose reports as S301; a handle tested as a condition cannot be caught (an object is always truthy). `isHandle` is exported. Nothing may be set on a builder. **`.param.<name>`** (2026-11-26, for kit/compose's param wire) answers a handle of each param the Program has declared so far (`side: "param"`, `seam` from `paramSeam(decl)`: `f64` for a number, `bool`, `str`, or the enum of a string's `options`; none for a date or anything else), and a `known: false` handle for any other name. Where the Grammar's param slot is itself named `param`, `.param` is still the slot's method (calling it declares a param) and answers the handles as properties; every other name, a function's own property such as `call`, `bind` or `length` among them, answers a `known: false` handle (S111), as on any param side. A Grammar with no param slot gets a param side that knows no params.

**`ref("in")`.** The kit fills a Program's `in` namespace from `ports.in`, so a `ref("in")` (a trigger) is checked by name: B003 with a did-you-mean. `ref("in", { kind: "event" | "value" })` takes only that kind; an input of the other kind is B003 that names its kind and lists the inputs that fit. A Grammar with `ref("in")` and no `ports.in`, a `name("in")`, a slot or child construct named `out`, `in` or `frame`, or a `kind` on any other ref or of any other value is D031.

## Per-slot effects

Leaf `8vQJOw`; the spec is [api-effects.md](../../scripts/define-trial/docs/api-effects.md) (its Codes table is binding), the design and its reasons [the effects draft](../../project/2026-11-25-per-slot-effects-draft.md). A lambda may change only the one instance it is handed, and every effect is declared. The checks are [`effects.js`](effects.js) (pattern parsing in [`effect.js`](effect.js)); lowering does the rest ([kit/lower](../lower/README.md)).

- **What a Dialect writes.** A space is `{ pure: true }` or `{ instance: "Obj" }` (D012: exactly one, and `instance` names an object). A value member takes `write: true` (writable) or, on an `"f64"`, `bump: true` (a total). A `fn` member takes `effects: [...]` (a verb); an object takes `call: { params, returns, minArgs?, rest? }` with `effects` beside it (callable, like `rng()`). A static convention, or what a convention function returns, takes `may: [...]`, patterns `verb`, `verb Obj` or `verb Obj.member` over the verbs `read`, `write`, `destroy`, `rng`, `bump`. `helpers: { may: [...] }` takes reads only. `write`, `bump` and `effects` are accepted only on a declared object's members (elsewhere, as in an `object()` type, they stay D001).
- **D021** (a malformed declaration) and **D022** (an instance reachable another way, or a change outside its instance space), every case in the spec's table. A verb's and a call's `effects` get the checks a `may` pattern gets (an unknown verb, object or member, a `write` of a member that is not writable, a `bump` of one that is not a total, a change naming no object: D021), a verb returns `"void"` (D021), and a `write Obj…` or `destroy Obj` may only be an effect of a verb that is `Obj`'s own member, never of another object's verb or any object's call (D022: otherwise a lambda handed a `Totals` could change a `Plant` it was not handed; review finding M1, 2026-11-25). A member pattern or effect naming a member the definition lacks, or an object-level `write` / `bump` of an object with none, waits for the Program when the Dialect has `environment(program)`.
- **Per Program.** When `environment(program)` is called, what it added is checked (its members' `write` / `bump` and its verbs' `effects`, D021 and D022 as above; a member or global giving an instance, D022, path `environment.…`) and every static slot's and the helpers' `may`, and every static verb's and call's `effects`, against the members as they now stand; a problem throws a `DefinitionError` (`environment(program) refused:`). A convention function's `may` and params are checked when its slot is asked for, refused as its other problems are.
- **The Environment.** A `write: true` member gets `store: { type: "value" }` and `effect: "read Obj.m"`; a `bump: true` member gets `bump: true` and `effect: "read Obj.m"`, no store; a verb's `FnSig` its `effects`; an object's `call` becomes `ObjectDecl.call` with its `effects`. Every generated slot gets `may`: the declared list (absent, `[]`) plus `"read <Instance>"` in an instance space. The helper convention's `may` is `helpers.may`, else a read of each instance space's object. The `const` convention keeps its `forbid` list. So a Dialect that declares no effect (fields, data) gets `may: []` everywhere and nothing it lowers changes.
- **Lowering** judges each lambda against its `may` (L004, the tip listing it), lowers `+=` / `++` on a total to the IR's bump (L017 for any other change, or for a read in a slot that may bump it), refuses a write to a member without `write: true` or to part of a vector member (L013), and judges a helper against the helper convention's `may` (one L004, at the helper; its callers are blocked without a diagnostic of their own).

## `defineUI`

`defineUI(builder, decl, options?)` ([`ui.js`](ui.js), the checks in [`ui/`](ui/)) declares the UI that rides with a package: a `stage` (a custom element, or the Dialect's own Draw output; below), `controls` (declared Controls, below), `grips` (draggable stage objects), `actions` (trusted functions the host runs), `tiles` (panels of `stat`, `check`, `table`, `plot`, `runs`, `text`, `row`, `col`, `control`, `param`, `action` and `view` components) and `annotate` (marks on the generated `traces` and `params` views). The declaration is the trialed draft's ([the packet](../../scripts/ui-trial/docs/ui-draft.md), [the findings](../../project/2026-11-25-ui-trial-findings.md)) with these changes, and every mistake is a `U` code: it throws one `DefinitionError` holding every problem, each with `code`, `path`, `message`, `tip` (a did-you-mean in the message) and, inside a lambda, the `line` within it. It returns a frozen UI value `{ package, builder, dialect, stage?, inputs?, control, tiles, annotate }` (`isUI` tells one).

- **The state is the Dialect's.** `builder`'s Dialect declares the run's `state` (above); a UI has no `state` key (a `state` key is `U001`, whose tip says where it goes). A path (`"bounds.width"`) and a lambda's reads (`(s, $) => s.bodies.length`; a table column's `(row, s, $) => row.speed`) resolve against its resolved Type: struct fields; a vector's components (and its aliases); a path stops at a list, but a lambda may read a list's `length` and items by index and a vector's components by name (a string has no `length` and a vector no index: what `lower` accepts, nothing more). A Dialect with no `state` is `U013`. UI lambdas are checked here only for what needs no Program (parse, subset, arity, purity, reads of the state, free names: `U007`); their types are checked by `lower` (next). **The reads are checked structurally, so `defineUI` is sound without `lower`** (Ben, 2026-11-25, leaves kQu7xe and 3kCvsI): every member chain starts at a parameter (`s`, `$`, `row`), a const set to exactly a parameter chain, or a Dialect global such as `Math`, so a chain rooted at a conditional, a logical expression, a call or an array is `U007`. A `const` whose initializer is exactly a member chain from a parameter (`const b = s.bodies[0]`, `const w = s.bounds`, `const p = b.pos`) takes the Type the chain resolves to, and chains rooted at it are checked against that Type like chains from the parameter (undeclared member: `U007`, did-you-mean included); scopes are honored, so an inner `const` or a nested arrow's parameter of the same name hides it. This is how a possibly-empty value is narrowed for `lower`: `(s) => { const b = s.bodies[0]; return b != null ? b.mass : 0; }` lowers clean, where `s.bodies[0].mass` is `L008`. Everything else that holds state in a local is `U007` ("a UI lambda may not hold state in a local"): a const or `let` set from a conditional or logical of struct, list or optional chains, a `let` set from a chain that is a struct, list or optional, a destructuring of a parameter, a `for…of` binding over one, a const of the parameter itself (`const t = s`). A `let` holding a scalar computed from state is legal (`let n = 0; n += s.t`, `let m = s.t * 2`; arithmetic, comparisons, calls and literals are scalars). A list declared with no max is used only as `s.list.length` or `s.list[i]…` (also through a const: `const xs = s.bodies; xs.length`): used whole, or in a loop's header (directly, or through a local computed from its length), it is `U007`. A destructured parameter is refused outright. A call's result counts as a scalar, since the Dialect's call results are never state.
- **`ui.lower(record)` types the lambdas against one Program** ([`ui/lower.js`](ui/lower.js)), as a Grammar's `lower` does a Program's: every UI lambda goes through kit/lower (`lowerProgram`) against the Dialect's `environment(record)`, which is where `$` gets its members (a Program without the param `mass` makes `$.mass` an `L002`). The conventions are built in the UI's own wrapper of that Environment, not declared by the Dialect: an implied pure space (`may: []`, so any effect, `rng()` or a read of a total, is `L004`); `s` the Dialect's `stateType`; `$` the Dialect's `params.object` (an object with no members when it declares none); a column's `row` the item Type of its table's `rows` list; and every list has a `length`, typed as the Dialect's `numberType` (f64 by default) when that type holds the list's max exactly, else f64, as in every lowering (kit/lower builds it in; the verifier takes an f64, or an f32 where the list's max is at most 2^24; the Dialect's own `list` members add to it and win on a name). A state list declared with no max is given the max `OPEN_MAX` (`Number.MAX_SAFE_INTEGER`) in the UI's lowering (and a port's or Draw builder's), since the IR holds a max on every list. That max decides one thing: such a list's length is an f64 even in an f32 Dialect, since an f32 does not hold it exactly; a list with a max of at most 2^24 has an f32 length there, so an f32 Dialect's lambda reading it (`s.stages.length / 3`) computes in f32. It bounds no loop, because no UI lambda loops over such a list (a loop to it would be L007 in an f32 Dialect), and kit/lower is not changed for ordinary Programs. **Corrected 2026-11-27 (leaf `v4Ya0z`):** this said nothing sizes anything by `OPEN_MAX`, while an f32 Dialect's length of an open list was typed f32 and refused by the verifier (V002), so a UI lambda reading it made no Kernel. Each key's result is required: `badIf` and `expect` a `bool`; `max`, `y` (a plot's and a run's) a number; a stat's `value` and a column's `value` a number or a `str`; a text's `value` a `str`; `badge` a `str` or null; `tone` one of `good` `warn` `bad` `dim`, or null. "A number" is f32, f64 or a nominal scalar: each lambda is lowered once with `returns: "infer"` and then against the number type it gave (a core union may not mix number types, V003), else against the Dialect's `numberType`, so a wrong result is lowering's own `L003` at the expression. It returns `{ environment, kernels, lambdas, helpers, diagnostics }`: `kernels` the Kernels by id, only for lambdas that lowered; `lambdas` each with `id`, `path`, `tile`, `key`, `src` and its `LowerResult`; `diagnostics` each lowering diagnostic with the `id`, `path` (defineUI's form), `tile` (null under `annotate`) and `key` it came from (its `loc` is inside the lambda's source), then any Library unit's with its `unit`. An id is the lambda's place as one string: `tiles.health.body[0].items[0].badIf`, `tiles.health.body[2].columns[2].value`, `annotate.params.rate.badge` (a key that is no identifier is quoted: `annotate.params["*"].tone`). **`ui.compile(record)` runs them** ([`ui/compile.js`](ui/compile.js), leaf `dXp5WO`): `lower(record)`, then each Kernel emitted and instantiated through the JS backend as kit/run does a Program's (the Dialect's JS intrinsics, the Library units linked as helpers), so a host never calls the author's function: the lambda's text is what runs. A UI Kernel reads the page globals (`PAGE_GLOBALS`, `Math`) from the page; every other Dialect global is bound as kit/run binds a Program's, a forwarding object over the call's globals: the Dialect's params name (`params.name`; `$` when it names none) is the params the call is handed (its last argument, `evaluate`'s `$`), so a lambda that reads a free `$` (`(s) => $.speed`, or `u.speed` in a Dialect whose params name is `u`) reads them, and any other global throws (a view runs outside a step, where no runtime set it); none is ever the host's global of that name. **Corrected 2026-11-27 (leaf `GYDKN0`):** until then the params were bound as `$` whatever the Dialect's params name, so a Dialect naming them `u` had a free `u` throw, and `value` took a call's last argument as the params however many it was handed. **Corrected 2026-11-26 (review H3, leaf `1Bfx8t`):** until then the binding skipped every name its identifier test did not match, `$` among them, so a one-parameter lambda reading `$` read the page's `globalThis.$` (jQuery's, say). It returns `{ ok, diagnostics, evaluate, value, annotation }`: `ok` is false when a lambda did not lower, and `diagnostics` are `lower`'s. **`evaluate(state, $)`** gives `{ tiles, annotate }`: each tile `{ id, title, place, body }` in declared order, each component as data with its values as the Kernels gave them (a host formats them): `stat` `{ label, value, unit?, max?, bad }` (`bad` by the rule below), `check` `{ label, ok }`, `table` `{ label, columns, rows }` (the column labels, a string column naming its row key, and the rows cut to `limit`), `plot` `{ label, window, y }`, `text` `{ value }`, `runs` `{ label, param, from, to, steps, seconds, y }` with `y` the id its value is read by, `row` and `col` `{ items }`; a component's `element` is kept. A path is read from the state (a column's from its row), and an annotation's string is its own text. A component whose lambda did not lower is `{ kind, label, error, code }` (the L code), one that throws `{ kind, label, error }`; the others still evaluate. `annotate` holds each view's keys' `{ note?, badge?, tone? }`. **`value(id, ...args)`** reads one value by its id (a `runs` tile's `y` with that run's last state and `$`); a lambda's id takes exactly its convention, `(state, $)` or a column's `(row, state, $)`, and any other number of arguments throws a `TypeError` naming it, since the params are the last argument and a call one short would read the state as them (a path or a literal reads only the first); and **`annotation(view, key, state, $)`** one key's marks; under `params` a key's own fields win over `"*"`'s. kit/page's `sweepRuns` runs a `runs` tile with it. A record a rebuild replaced needs `compile` again.

## Argument overrides and sites

`run(fn, { values, args })` ([`params.js`](params.js), [`sites.js`](sites.js)) takes `args`, values by **Argument address**: one argument of one builder call, the call's Ref id (below, "Ref ids": `<tag>.<slot>`, `#<n>` unless the slot is `once`, `~2` for a repeated instance name), `:<i>` (the argument, from 0) and a path into it (`.<key>`, `[<i>]`): `s.op#1:1.ratio`. Each value is put in at its call before the Program is checked, so the Grammar's bounds still refuse a bad one (B004, with no record); an address no call reaches, or a malformed one, is a TypeError, the host's mistake. `#<n>` counts the calls of that one slot (the k-th call of slot `op` is `s.op#<k>` whatever the instance's other slots hold; ruling of 2026-11-27, leaf `IlUYzu`), so an address built from a list index (`s.op#${i}:1.ratio`) reaches the right call; lowering and `siteOf` number calls alike. kit/compose's `callGlue(exported, path, { args })` does the same for a glue's parts. `siteOf(record, target)` finds a target (`"arg.<address>"` or `"param.<name>"`) in a record a build (or `run`) gave: `{ file, loc, slot, arg, path, value, source, calls, min?, max?, whole? }`, the place the builder made the call (the method name's line and column) and its slot (the method the text calls there), the argument's Grammar bounds (a param's own `min` and `max`; for a list of numbers, its element's), `source`, the value the text held there when the record was built (`value`, except in a record built with that argument overridden, whose text still holds the value before the override, a param's declared value included when built with `values`: write-back's stale check, kit/page's H012), `callArgs`, the call's arguments as the text holds them (each override undone), and `calls`, how many calls the record holds at that place, counted with the other records of the composition it was built in (more than one is a loop, a helper called twice, or a glue helper that makes two parts); null for a target no call reaches. Every builder call has an id and a site, a call whose arguments are all literals included: the record keeps every call's place, and lowering numbers every call, so no lambda is needed (confirmed 2026-11-27, before write-back was built; `record.js` did not change). A record copied (a JSON round trip) has lost the Grammar `siteOf` reads it by.

## Runtimes: `defineRuntime`

`defineRuntime(grammar, { clock, init, step, events })` ([`runtime.js`](runtime.js)) declares a package's runtime module ([the clocks draft](../../project/2026-11-25-clocks-draft.md), as ruled 2026-11-26): plain trusted JavaScript over the package's own state, not lowered. [kit/run](../run/README.md) runs it; what `ctx` holds is in its README.

- **`clock(record)`** returns `{ tick: seconds }`, `{ frame: true }` or `{ demand: true }`. `clockOf(runtime, record)` reads it: a tick as an exact rational (`fromNumber` in [`rational.js`](rational.js): the simplest fraction within 1e-12 with a denominator up to a million, so `1 / 30` is 1/30), or why it is not a clock (kit/run's N006).
- **A runtime reads a param's value through `ctx.params`** (the Kernels' `$`), never from the record (`record.params.<name>.value`): the content key keeps a declaration's type, bounds and options but not its value (kit/build, ruled 2026-11-26), so a run whose `$` changes keeps the revision, and a runtime that read the value from the record would not see the change. `clock(record)` reads no param value. No runtime in the repo reads one from the record (leaf `DJZ2z2`, grep of `kit/` and `scripts/`), so this is the documented rule rather than keying the value.
- **`init(record, ctx)`** gives the run's first state; **`step(state, ctx)`** the state after one step. It must not change the state it is handed or keep memory outside it (kit/run checks both in development runs). Event outputs are pushed into `ctx.events.<port>`, never kept in state. `ctx.kernels` holds the Program's compiled lambdas by id (`<instance>.<slot>`) and the part's own by slot name: `ctx.kernels.control` is `ctx.kernels[`${ctx.part}.control`]`.
- **`events: { out: { port: max }, in: { port: max } }`**: every Event port of the Dialect needs its whole, positive per-step max: how many records one step may push, or take. An Event seam carries no max, and since an Event output has no `from` there is no state list to read one from, so the runtime declares it. An input that keeps the last n records takes a max of at least n. The composition sizes each reliable queue from these and the clocks (S116).
- **D033** refuses a declaration that is not on a Grammar builder, a `clock`, `init` or `step` that is not a function, an unknown key, an Event port without a max, a max on a value port or on a port the Dialect lacks, a max that is not a whole number of at least 1, or one below the input's `keepLast`. One `DefinitionError` holds every problem.
- It returns a frozen Runtime `{ grammar, dialect, clock, init, step, events }`; `isRuntime` tells one. A package names its module in the manifest's `entry.runtime` ([kit/package](../package/README.md)).

## Codes

`D…` (a definition), `B…` (a Program) and `U…` (a UI) are listed with their meanings in [`codes.js`](codes.js) (`DEFINE_CODES`, `BUILD_CODES`, `UI_CODES`); D001–D015 are [rules.md](../../scripts/define-trial/docs/rules.md)'s, widened where the revised draft added keys. Beyond the draft: **D017** refuses two things of one construct that the record would put under one key (an opening argument, a child construct, a slot's name or `as`, `units` beside a unit slot or on the root, which takes the module scope's units, `calls` in a `record: "calls"` construct), **D018** refuses a slot or construct named like a property runtimes probe on every object (`then`, `toJSON`, `inspect`, `constructor`, `valueOf`, `toString`, `prototype`, `nodeType`, `asymmetricMatch`, `$$typeof`: the builder answers them with `undefined`, so such a method could never be called), **D024**–**D032** are the seams' (above), **D033** a runtime's (above), **D034** a malformed `files` (above), **D019** refuses a `lambda()` or a `rest()` in a construct's `opens` (not built yet: an opening argument is one value under one record key, so a rest tail there kept only its first value), **D020** refuses a Dialect without a text view (above), **D023** a malformed run's state (above), **D021** and **D022** are per-slot effects' (above; D012 widened with them), **B011** is a convention's refusal, **B012** and **B013** are the module scope's, and **B014** and **B015** the binding-time params' (above), **B016** a run that opens the root twice and **B017** one that opens it and returns something else (above). D016 (which refused `scalar()` before the nominal scalar was built) is retired and its number not reused. A Dialect's own check codes take its own letter; `B`, `C`, `D`, `L`, `P`, `S`, `U` (the UI's), `V`, `J` (kit/draw's draw lists), `H` (kit/page's page diagnostics), `K` (kit/package's) and `W` (kit/lir's verifier) are reserved, and `ctx.error` with one throws. `R` (kit/run's run diagnostics) is not reserved: particles packages already use it for their own check codes, and kit/lir's refusals are R codes too (an open question, leaf `ZH4KWX`).

## Where the build departs from the draft

- A `once` slot's lambda id has no `#index` (above); `ref.index` is still passed. `index` counts the calls of the call's own slot, in a by-slot record and a `record: "calls"` one alike, and the ids are built from it. `ref.key` is the lambda's `recordOf` key, else the call's declared name when the slot's first argument is a `name()` (since H5, 2026-11-25), so a convention can tell which of several `.force("name", …)` calls it lowers; the ids are unchanged. A convention function may be called several times per lambda (once per inference pass), so it must be a pure function of its arguments.
- The root's opening `name()` (`field("domain-warp")`), the Program's own name, is a label and takes any non-empty string; every other `name()`, a child construct's opening included, must be a JavaScript identifier (`B004`, one message for all). Until H5 (2026-11-25) every opening name was a label, so a child took `"9jet"` where a slot refused it.
- A slot `check`'s `ctx.state` is always `undefined`: state needs each lambda's inferred type, so it exists only when lowered. State-namespace refs are checked by `lower`, not by `.build()`; a ref in the opening arguments is checked against the state `init` returns, before any step. A construct **without** state may name its namespaces in `names: { column: (record, { program, stateOf }) => [...] }`, functions of its record and other instances' final states; its refs into them are checked by `lower` too (`B003` with the did-you-mean, pinned at the call; a ref in the construct's opening arguments counts too), so a chart checks its encodings against its table's last step without a state of its own. `names` beside `state`, a value that is not a function, or a namespace a `name()` declares into is `D015`.
- No `edits` on builder diagnostics: the builder has the call's place but not the file's text, so the replacement goes in `tip` (and `fix` from a check).
- A type `enumOf` holds strings only (the core's enums do); a shape `enumOf` may hold numbers.
- A builder in a template literal or `String()` is its description (`[field builder 'p']`), not an error.
- Unit slots in a `record: "calls"` construct go into `calls` like any slot; lowering finds them there.

## Not built

Spawning an instance from a lambda, writes outside the instance a lambda is handed (other than a bump of a total), run-once spaces that write freely, `emit`, effectful intrinsics (host imports) and inferred methods; fragments; build-time slots; Dialect imports; lambdas and `rest()` in a construct's opening arguments (`D019`).
