# kit/define: the Definition API

Declares a Domain Language as data and generates the rest. `defineDialect` says what the language **means** (types, objects, intrinsics with each target's spelling and a reference implementation, the Library, Iteration Spaces, targets, slot conventions); `defineGrammar` says how a Program is **written** (constructs and their slots), and the kit generates the builder, its diagnostics, the record it returns and the lowering of every Runtime Lambda. The spec is [the draft](../../scripts/define-trial/docs/api-draft.md); this page says what is built and where the build departs from it. No Node built-ins.

```js
import { defineDialect, defineGrammar, vector, exact, name, data, lambda } from "./kit/define/index.js";

const d = defineDialect({ name: "tiny", numberType: "f32", types: { vec2: vector(2, "f32") },
  spaces: { pixel: { pure: true } }, targets: { js: { accepts: "*", compare: exact() } },
  slots: { pixel: { params: ["vec2"], returns: "f32", space: "pixel" } } });
const tiny = defineGrammar(d, { root: "tiny", constructs: { tiny: { opens: [name()], slots: {
  pixel: { kind: "decl", args: [lambda("pixel")], once: true, required: true } } } } });

const record = tiny("t").pixel((uv) => uv.x * 0.5).build();   // { name: "t", pixel: "(uv) => uv.x * 0.5" }
const { lambdas, helpers, diagnostics } = tiny.lower(record);  // Kernels, through kit/lower
```

[kit/dialects/fields](../dialects/fields/README.md) is declared with this API: its [`dialect.js`](../dialects/fields/dialect.js) is the draft's worked example completed, and its builder is the one [`grammar.js`](../dialects/fields/grammar.js) generates. Its tests hold the generated builder to what the hand-written one it replaced built (`test/golden/hand-built.json`) and refused.

- **A Dialect value** ([`dialect.js`](dialect.js)). `defineDialect(def)` checks the whole definition and throws one `DefinitionError` holding every problem (`{ code, message, tip, path, file, loc }`: `path` is the key path inside the definition, `loc` the define call). It returns `{ name, numberType, def, intrinsics, library, targets, libraryFor(sources), environment(program, states?) }`. `intrinsics` has the shape of fields' table (`{ sig, ref, componentwise?, <target>: { call, prelude? } }`), `library` is `UnitDecl[]`, and `environment(program)` returns an [Environment](../lower/environment.d.ts) exactly as lowering reads it: type names resolved to core Types, each intrinsic a callable object plus a global, the hook's objects and globals merged in (a member it declares twice throws), and `slot(ref)`.
- **Nominal scalars.** `types` holds vectors and scalars: `date: scalar("f64", { note })` is a named type stored as an f64 (the core's `{ scalar, of: "f64" }`, [kit/ir](../ir/README.md#nominal-scalars-m3)). Its name may be used wherever a type is named (slot params and returns, members, globals, intrinsic signatures, convention functions); it compares only with its own kind and is no constructor: a value enters through a parameter, a member or an intrinsic, and a lambda calling the type's name is `B008`. A lambda that infers a scalar hands its name to a construct's `step`. Another backing is D002, options other than `{ note: string }` D011, and `scalar()` written inline where a type is named D002. A type, vector or scalar, named like a built-in type (`f32`, `f64`, `bool`, `str`, `null`, `void`, `unknown`) or a one-capital-letter type variable (`T`) is `D007`, since it would take that name over everywhere it is written.
- **Slot conventions.** A static convention is resolved once; a function `(ref, program, state)` is called per lambda, and what it returns is checked as a static one is (`D002`, `D005`). `object(label, members)` in a convention makes an object type on the spot, named by its label (numbered when the same label carries other members). The kit makes the `helper` and `const` conventions; a Dialect may not declare those names, nor `method`, which lowering reads specially (`D007`). Every space is pure and no member can carry an effect, so purity holds by construction and a generated convention's `forbid` is empty; the generated `const` convention forbids every effect, as DMG's does (the hand-written fields Dialect forbade none, so a fields constant could call a helper until it was re-declared here).
- **The generated builder** ([`grammar.js`](grammar.js), [`record.js`](record.js), [`shapes.js`](shapes.js)). `defineGrammar(dialect, def)` returns the root builder, with `.lower`, `.dialect` and `.grammar` on it. Each construct instance's builder has its slots, its child constructs and its ancestors' methods (calling one ends the child); builders are mutable, so `b.param(…)` without reassigning works. An unknown method throws `B001` at once with a did-you-mean; everything else is collected with the call's `file` and `loc` (from the stack) and `.check()` returns the list, `.build()` throws a `BuildError` carrying all of them or returns the record. `B002`, `B004`, `B006`, `B007`, `B009` and slot `check`s are found at the call; `B003` (Program-namespace refs), `B005`, `B008` and construct `check`s at `.check()` / `.build()`, when every name is known.
- **The record** is the draft's "The record": openings under `as`, else their namespace, else `name`; a slot whose first argument is `name()` as an object from name to the rest; other slots as one value (`once`) or a list; `units: [{ name, kind, src }]`; children as lists under their construct's name; `record: "calls"` as `calls: [{ slot, args }]`. A lambda is its source text wherever it was passed.
- **The free-name rule** (`B008`) allows a lambda's own names, the Dialect's globals (with those `environment(record)` adds), intrinsics, Library entries, vector constructors and conversions, and the Program's units. The tip names the Grammar's `const` unit slot, and `$.name` when the Dialect declares `$`. A member of a JavaScript global (`Math.sin`, `console.log`) gets another tip: the bare intrinsic when the Dialect has one of that name (`use sin, not Math.sin`), else `Math is not in the language`. The diagnostic's `lambda` field carries the lambda's source and the place inside it (also on a `B007`), so a tool can show the line.

- **`oneOf` with a ref and a lambda, and the ambiguous string.** The record keeps a lambda as its source text, so a record's lambdas are found again by matching its text, and a call and its record must choose the same branch. The rule: a string that parses as an arrow function is the lambda (`.y("() => 1")` is the lambda, as `.y(() => 1)` is), and any other string is the ref or string (`.y("a")`); a function is always a lambda. It holds wherever a `oneOf` sits, inside `listOf` and `recordOf` too. A string that is meant as a name or text yet parses as an arrow function cannot be given to such a `oneOf`.
- **Lowering** ([`lower.js`](lower.js)) lives on the grammar, because only the grammar knows where lambdas sit in a record: `grammar.lower(record)` returns `{ environment, lambdas: [{ ref, src, result }], helpers, diagnostics, states }`. Every lambda goes through `lowerProgram` with the Library units it uses and the Program's units, in that order (as `lowerField` does). A lambda's slot id is `<on>.<slot>#<index>`, plus `.<key>` inside a `recordOf`; a `once` slot drops the index (`swirl.pixel`), so Kernel names match the hand-written Dialects'. Stateful instances share one namespace whatever their construct (an unnamed one goes by its construct's name), because `stateOf(name)` and `states` find an instance by name alone: a second with a name already taken is `B002` at `.check()`. A construct with `state` is built call by call: `init`, then per call its state-namespace refs are checked against the state at that step (`B003`, with a did-you-mean), its lambdas are lowered with that state (the convention's third argument) and their inferred types (in definition terms: `"f64"`, a vector's name, `enumOf`, `opt` …) go to `step`. A `stateOf` loop is `B010`: each instance on the loop is told it depends on its own state, one that only reads a looping state is told so. A convention that returns a reason is `B011`. Lambda type errors keep lowering's own `L…` codes. Every diagnostic in the flat list is tied to where it came from: `B003` and `B011` are pinned at the call (also in a by-slot construct, whose record keeps each call's place), `B011` carries the refused lambda's `ref`, and a lambda's `L…` diagnostics carry `file` and `ref` (their `loc` is inside the lambda's source), a helper's or constant's carry `unit`.

  **Step context.** `step(state, call, inferred, ctx)` gets `ctx = { program, stateOf, error }`. `program` is the record, as init's; `stateOf(name)` is another instance's final state, the same lookup as init's (by instance name, built lazily on first ask, `undefined` for an unknown name), so a join reads `ctx.stateOf(call.args[0]).columns` at the step where the join happens, with no closure in the state. A `stateOf` loop that goes through `step` is `B010`, attributed exactly as one through `init` (each instance on the loop depends on itself, one that only reads it reads a looping state). `error(code, message, tip?)` refuses the call with the Dialect's own code: a diagnostic pinned at the call (`file`, `loc`, as `B011`) carrying `on` (the instance) and `slot`, collected into `lower()`'s diagnostics in call order; a code that is not one letter and three digits, or starts with a reserved letter, throws, as a slot or construct `ctx.error` does. **The state `step` returns still applies after an error**, so later calls and lambdas type against it and one mistake yields one diagnostic; the diagnostic is what makes the Program fail. (A `stateOf` loop re-runs the steps of the instances on it for each instance that is told about it, so a `ctx.error` in a looping instance's steps before the loop can repeat.) `init` is unchanged.

  **Instance names.** An instance is named by the value of its construct's `name()` opening, under whatever record key that opening has (`name("table")` records under `table`, `name({ as: "title" })` under `title`), else by its construct's name. `nameOf` in [`record.js`](record.js) is the one place that decides, for the builder and lowering alike; a slot, lambda slot or child construct called `name` renames nothing. `B002` for stateful instances is keyed by this name.

  **Ref ids** are unique within a Program and deterministic. The id is `<tag>.<slot>`, plus `#<index>` unless the slot is `once`, plus `.<key>` for a lambda under a `recordOf` key, plus `[n]` when several lambdas of one call share that key (or all lack one): `x.k#0.a[0]`, `x.k#0.a[1]` (two lambdas under `a`, whether a `listOf` or two `recordOf`s sharing the key), `x.k#0[0]`, `x.k#0[1]` (unkeyed, as `rest(lambda())` gives), `x.k#0.0` (the key "0", which `[n]` cannot be mistaken for). A lone lambda has no place. `<tag>` is the instance's name; two instances with one name (two unnamed instances of a stateless construct, or one name in two constructs) get `~2`, `~3`, … in record order (`t.k`, `t~2.k`), while `ref.on` keeps the real name. A last guard appends `~n` to any id still taken, so odd names and keys cannot collide. The fields Grammar's names (`swirl.pixel`) are unchanged. `step`'s `inferred` for a call with several lambdas: all keyed, an object by key (a key holding several lambdas has the list of their types); all unkeyed, the list in call order; a mix of keyed and unkeyed, the list of every lambda's type in call order.

  **Own keys.** A name-keyed slot's record is built with own properties, so an entry named `__proto__` is a key like any other and is lowered (not refused with `B004`).

## Codes

`D…` (a definition) and `B…` (a Program) are listed with their meanings in [`codes.js`](codes.js) (`DEFINE_CODES`, `BUILD_CODES`); D001–D015 are [rules.md](../../scripts/define-trial/docs/rules.md)'s, widened where the revised draft added keys. Beyond the draft: **D017** refuses two things of one construct that the record would put under one key (an opening argument, a child construct, a slot's name or `as`, `units` beside a unit slot, `calls` in a `record: "calls"` construct), **D018** refuses a slot or construct named like a property runtimes probe on every object (`then`, `toJSON`, `inspect`, `constructor`, `valueOf`, `toString`, `prototype`, `nodeType`, `asymmetricMatch`, `$$typeof`: the builder answers them with `undefined`, so such a method could never be called), **D019** refuses a `lambda()` in a construct's `opens` (not built yet), and **B011** is a convention's refusal. D016 (which refused `scalar()` before the nominal scalar was built) is retired and its number not reused. A Dialect's own check codes take its own letter; `B`, `C`, `D`, `L`, `P`, `S` and `V` are reserved, and `ctx.error` with one throws.

## Where the build departs from the draft

- A `once` slot's lambda id has no `#index` (above); `ref.index` is still passed. In a by-slot record (no `record: "calls"`) `index` counts in slot-declaration order, since the record keeps no order across slots.
- An opening `name()` (`field("domain-warp")`) is a label and takes any non-empty string; other names must be identifiers.
- A slot `check`'s `ctx.state` is always `undefined`: state needs each lambda's inferred type, so it exists only when lowered. State-namespace refs are checked by `lower`, not by `.build()`.
- No `edits` on builder diagnostics: the builder has the call's place but not the file's text, so the replacement goes in `tip` (and `fix` from a check).
- A type `enumOf` holds strings only (the core's enums do); a shape `enumOf` may hold numbers.
- A builder in a template literal or `String()` is its description (`[field builder 'p']`), not an error.
- Unit slots in a `record: "calls"` construct go into `calls` like any slot; lowering finds them there.

## Not built

Effects, store rules, `emit` and inferred methods (every space is pure); fragments; build-time slots; Dialect imports; lambdas in a construct's opening arguments (`D019`).
