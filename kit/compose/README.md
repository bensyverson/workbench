# kit/compose: the glue program

Composes parts, each a Program built by its own package's Grammar, into one workbench ([the seams draft](../../project/2026-11-25-seams-draft.md), "The glue program", as ruled 2026-11-26). The composer owns every fact that spans two parts: which output feeds which input, and how one part's frame relates to another's. kit/compose checks each wire field by field, plans each conversion through the frame graph as data, and names both sides when something is wrong. It runs nothing: [kit/run](../run/README.md) runs the composed record; given the parts' runtimes, it sizes each reliable Event queue (S116). The composed page's drawing is `FqsPVJ`'s. No Node built-ins.

```js
import { compose } from "kit/compose";
import { maze } from "maze";                 // a package, by its name: the host resolves it to the package's Grammar
import { particles } from "particles";

export default ($) => {
  const level = maze("level").grid(GRID).control(steer);
  const fx = particles("fx").bounds({ width: 320, height: 320 })
    .emitter("pop", { x: 160, y: 160, trigger: "burst" }).rate((t) => 0).spawn((p, rng) => { p.pos = ev.at; });
  return compose("coin-bursts")
    .part(level).part(fx)
    .frame(level.frame.cell, fx.frame.px, "fit")             // or { scale: 32, offset: 16 }, or { scale: 1, anchor: "center" }
    .wire(level.out.picked, fx.in.burst)                     // options: { rename: { pos: "at" }, set: { kind: "coin" }, delay: true }
    .show(fx);
};
```

## API

| Export | Does |
|---|---|
| `compose(name)` | a composition; `name` is lowercase letters, digits and `-` (S102) |
| `.part(builder)` | adds a part: any builder of a Program's chain. Its root's opening name is the part's name, unique (S101) |
| `.frame(a, b, edge \| "fit")` | relates a frame of one part to a frame of another: `{ scale, offset }` (a number for every axis, or one per axis: a point `p` in a is `p × scale + offset` in b), `{ scale, anchor, offset? }` (an anchored edge: the kit computes the offset from the two extents, "An anchored edge", below), or `"fit"` (a's extent into b's, one scale, centered) |
| `.wire(out, in, options?)` | an output handle to an input handle. `rename: { producerField: "consumerField" }` renames record fields, as data; `set: { consumerField: <value> }` is a wire constant (below); `delay: true` makes the consumer read the previous instant's snapshot, which breaks a cycle; `overflow: "keepLast" \| "keepFirst"` (an Event wire only) lets the wire drop what a consumer step cannot take (below). A rename reaches the records of an Event, of a record value and of a `list<{ … }, n>` value. `.wire(out, <part>.param.<name>)`, with no options, is a param wire (below) |
| `.show(part)` | the part whose stage the page shows; one. A layer is a part, so `.show(<layer>)` shows it; `.show(<output>, <output>, ...)`, two or more Draw outputs bottom first, adds a layer named `layers` and shows it ("Layers", below) |
| `.check(options?)` | every diagnostic at once: the S codes below, and a part's own (B, L, D) prefixed `part '<name>' (<dialect>): `, its warnings as warnings (**corrected 2026-11-26**, review M1, leaf `1Bfx8t`: until then only a part's errors were kept, so a part's B or L warnings, a preset's included, never reached the page) |
| `.build(options?)` | the composed record, or throws `ComposeError` (its `diagnostics`, and a message printed as below) when any diagnostic is an error; a warning (S206, S118, S116 with a policy or on a page wire) does not stop a build |
| `.plan(options?)` | each checked wire as text: `level.out.picked → fx.in.burst: at: maze.cell → particles.px, point, ×32 +[16, 48]`, then, for each `"fit"` or anchored step on the path, where its numbers came from: ` (fit at line 5: [-0.5, -0.5]..[9.5, 7.5] in [0, 0]..[320, 320])` |
| `formatDiagnostic(d, base?)` | a diagnostic as the draft prints it (below); `base` drops the glue's folder from the file |
| `scanGlue(text, packages, path?)` | a glue's text, from its syntax tree: its imports by kit/package's `scanImports` (`"kit/compose"`, `"kit/define"` and the package names only, no dynamic import; K007 otherwise), and S301 at the line of any test or comparison of a handle (by shape; see the S301 notes) |
| `rewriteGlue(text, urls, path?)` | a glue's text with each import's specifier replaced by its URL (`urls`: `kit/compose`, `kit/define` and each package's name, to its Grammar entry's URL): `{ text, diagnostics }`, `text` null with what `scanGlue` refuses; throws when `urls` lacks a name the glue may import (the host's mistake). Importing the text is the host's: the kit holds no dynamic import |
| `callGlue(exported, path?)` | calls an imported glue's default export with the glue's `$`: `{ composition, diagnostics }`. A build-time read of `$` is S104 (below), even when the glue catches it; an export that is not a function, throws, or returns something other than a composition is S103; a thrown error carrying kit diagnostics (`diagnostics`) or a kit code (`code`, a handle's S301) keeps them |
| `replan(composed, framesOf)` | a composed record's conversions planned again for the parts' frames in force (`framesOf(part)`: each frame's dims, its extents and the Dialect's edges for the record now in force): `{ ok, convert, frames, edges }`, or `{ ok: false, diagnostics }` (S251, S253, S254, S256). kit/run calls it after a rebuild ("An anchored edge", below) |
| `planOf(kind, edge)`, `ANCHORS` | a conversion's numbers for an edge, by kind (shared with kit/run); the three anchor words |
| `layer(name, output, output, ...)` | a layer part: two or more Draw outputs drawn as one picture, bottom first, whose one output is `.out.view` ("Layers", below) |
| `page`, `PAGE`, `pageRuntimeFor(controls)` | the page part (below): its builder (`page.out.<control>`, an open handle judged against the parts' declared Controls), its name, and its sizing runtime, made from each Control's `perFrame` |
| `queueProblems`, `stepsIn`, `catchUpOf`, `CATCH_UP`, `NOMINAL_FRAME`, `MIN_FRAME` | the queue bound (below), shared with [kit/run](../run/README.md) |
| `COMPOSE_CODES`, `ComposeError`, `isComposition`, `GLUE_SPECIFIERS` | |

**Loading a glue** ([`glue-load.js`](glue-load.js); review M2 and M4.4, leaf `1Bfx8t`). `rewriteGlue`, then the host's import, then `callGlue`: the page host used to rewrite the imports itself, call the export with `Object.freeze({})`, and turn a thrown error's code into its own, so a glue that read `$.n` at build time built its part with `undefined` and nothing said so. A glue has no params ("Each part keeps its own params; there is no glue-level `$`", below), so its `$` refuses every read. Answering a read with a part's declared param instead (one `$` over several parts' params, recorded as reads so kit/run could rebuild a glue part, issue `aRnKm8`) was not built: kit/define's `run` builds one Program, and which part a glue's `$.n` names is a design question.

`options` is `{ packages?, build?, runtimes?, catchUp?, profile? }`: `profile` (a kit/draw profile, or its name, `"canvas"` or `"gameboy"`) turns on the shown draw list's kind check (S401, below) and is kept, resolved, as the record's `profile`, which the page's draw-time check reads; `packages` gives each part's version (kit/package's `loadPackage` results, or `{ name, version }`, matched by Dialect, then by name); `build` is the `BuildOptions` each part is built with (its module scope); `runtimes` (kit/define's `defineRuntime` results, matched by Dialect name) turns on the queue bound below; `catchUp` is the most workbench time one display frame may cover (seconds, default 1/15).

**The composed record** is `{ name, parts: [{ name, dialect, version, record, layer? }], wires: [{ from, to, convert, rename, delay, overflow?, dropped, fill?, set?, delivery }], frames: [{ from, to, line, given, edge }], show, view?, profile? }`; `frames` holds each glue `.frame` call that planned, in glue order (below, "An anchored edge"), which kit/run plans again after a rebuild; `profile` is the renderer profile `check` or `build` was given, resolved from its name (only when one was), so a page reads it from the record (kit/run's `pageView`); a wired page is a part like any other (`{ name: "page", dialect: "page" }`), which kit/run never steps, and so is a layer (`layer` on its entry; "Layers", below). Each `convert` entry is `{ field, kind, rate?, from, to, fromId, toId, scale, offset }` (`from` and `to` are the frames as messages print them, `<dialect>.<frame>`; `fromId` and `toId` are their ids in the frame graph, `<part>.<frame>` or `s`, which `replan` reads, since a Dialect's name may hold a dot): a point by scale and offset per axis, a vector (or a rate of one) by scale per axis with a zero offset, a quantity by one magnitude; a `point1` (a 1-D position) by one scale and one offset. A conversion's `field` is the consumer's name for the leaf, after the rename (rename applies first): `[].at` for a list's items' `at`. `dropped` lists the producer's record fields the consumer does not take; `fill` (only when there is one) gives each field the producer's record lacks and the consumer's Event input declares a default for (`<field>: <type> = <value>`, [kit/define](../define/README.md)), with that default: the run adds it to every record after the conversions, since it is already in the consumer's frame, and never computes a value (the plan says `fills <field> = <value>`); `set` (only when there is one) is the wire constant, given the same way (the plan says `sets <field> = <value>`); a param wire's `to` is `<part>.param.<name>`, with no conversions and no `delivery` (the plan says `sets the param between instants`); `delivery` is the consumer's (`"reliable"` or `{ keepLast: n }`) for an Event wire.

**A wire constant** (ruled 2026-11-26, leaf `8JTaDq`): `{ set: { <field>: <value> } }` sets fields of the consumer's record, as data. Each value is a literal (a number, `true` or `false`, a string, or a list of these; else S102), checked against the consumer field's seam, and each field must be one the consumer's Event record or record value takes and the producer's record (after any rename) does not send: a set never overrides (S208). A field the consumer does not take, a value that does not fit, or a set on a wire with no record or into a list's items is S207. The rest of the consumer's record is compared as usual, so a set field needs no default. kit/run gives each record the set fields after the conversions, as it gives a fill ([kit/run](../run/README.md)).

**A param wire** (ruled 2026-11-26, leaf `x3iG6D`; [`param-wires.js`](param-wires.js)): `.wire(<part>.out.<port>, <part>.param.<name>)` sets a param of another part from a value output. A builder's `.param.<name>` is the handle of a param its Program declares (kit/define; where the Grammar's param slot is itself named `param`, the slot's method answers the handles too). The output's seam is compared with the seam the param's declaration gives: `f64` for a number, `bool`, `str`, or the enum of its `options` for a string (an Event output, another kind, a tagged value, or an enum the options do not cover is S201, S252 or S203). Bounds (`min`, `max`) are not in a seam, so kit/run checks each value as it applies it (N008). A param wire takes no options (S102) and one per param (S112); an unknown param is S111. kit/run applies it between instants, only when the value changes, as a logged `param` input, so the part rebuilds when build-time code reads the param, and replay and `why` see it. Because it applies between instants it orders nothing within one: a loop through a param wire and an ordinary wire is no cycle (no S115), since the ordinary wire's consumer steps between two rebuilds. A param wire from the part's own output, or a loop of param wires alone, is S117: a rebuild runs init, which can change the output that sets the param again with no step between. Given the runtimes, a param wire whose producer steps at a rate (a tick or frame clock) is S118, a warning: each change rebuilds. A host bridge (the host reading an output and logging a param input) stays possible, but nothing checks it.

**Bare package names.** A glue program imports its packages by name (`import { maze } from "maze"`). kit/compose does not resolve them: `scanGlue` refuses anything else before the glue runs, and the host maps each name to the Grammar entry of the package it loaded with kit/package (`loadPackage`; the manifest's `entry.grammar`). In Node that is a module hook (scripts/seams-trial does it); in the page it is the same blob URLs `rewriteSpecifiers` makes.

## Invariants

- **Each part is a whole Program**, built, checked and lowered by its own Grammar as if it stood alone. A part that does not build stops there with its own diagnostics, and its wires are not judged.
- **Every S diagnostic about a wire or an edge carries both sides** as `from` and `to`: `{ part, dialect, version, port | frame, seam | dims }`, or, for a name the part lacks (S111), what it `has`. S101 carries the two parts. S113 (a required input nobody wires) has only the consumer, and S301 (a handle read as a value) only the handle: neither has a second side.
- **The frame graph** holds each part's frames as `<part>.<frame>` (two parts' frames never unify by name), the kit's `s` once for every part, each Dialect's own `edges(record)`, then the glue's `.frame` calls in order, a `"fit"` or anchored one computed from the two extents for the built records. A second path between two frames must agree with the first (S253). Each tagged leaf of a wire converts along the path between its frames, by kind. The graph is a function of the records: kit/run builds it again after a rebuild (`replan`).
- **Renames are data.** The glue has no lambdas. A rename names producer fields and consumer fields; a refused rename is one mistake, so that wire is not compared further.
- **Cycles.** A loop of wires is S115 unless one wire in it is `{ delay: true }`. Glue line order never decides it: the loop is found from the parts and wires, named from the part added first, and parallel wires between two parts are ordered by their port names. Delaying one of several parallel wires leaves the loop, so the fix names every wire of a hop (all the wires from one part to the next) to delay.
- **One wire per input** (S112); a part wired to itself is S114 (a cycle inside a part is its Dialect's business). Each part keeps its own params; there is no glue-level `$`.
- **A wire never computes.** A wire constant is literal data, and a param wire carries the output's value as it is.
- **S301 is a trap, a throw and a scan.** A handle read as a number or a string at build time (`level.out.player * 2`, a template, an ordering comparison) records the read on its Program, and the check reports it at that line. A handle read for a property it does not define (`level.out.picked.y`) throws S301 at once, because it would otherwise read as `undefined` and a test of it would take a branch silently; the properties the kit reads (`part`, `side`, `name`, `known`, `seam`, `dims`, ...), `then`, symbols and the Object.prototype members still work. A handle tested as a condition cannot be trapped (an object is always truthy), so `scanGlue` finds it in the glue's text: a member chain ending `.out.X`, `.in.X` or `.frame.X` in the test of an `if`, `while`, `for` or `?:`, the operand of `!` or `typeof`, the left operand of `&&`, `||` or `??`, the right operand of one of those only when the logical is itself in a test position (`const h = flag && level.out.picked` selects a handle and is fine), or either side of `===`, `!==`, `==`, `!=`, `in` or `instanceof` (`h !== undefined` and `h == null` hide the same mistake), the `switch` discriminant or a `case` value, and a comparison operand that may be a handle through a logical, a ternary's arms or a sequence's last value (`(flag && h) === 1`); a sequence or ternary in a test position is read through the same way (`(0, h) ? …`). Each report carries the handle chain's own line.
- **The S301 scan works by shape, so it has limits.** It misses a handle that was first aliased (`const h = a.out.x; if (h) {}`), destructured (`const { x } = a.out`) or passed to a helper that tests it. It also flags any chain of that shape, so an ordinary object with `in`, `out` or `frame` keys (`config.in.length`) is a false positive; rename the key.

**The page** ([`page.js`](page.js); Ben's ruling 5, 2026-11-26; declared Controls, 2026-11-27) is a built-in part whose Event outputs are the composed parts' declared Controls (kit/define's `defineUI`, `controls`): the kit knows no Control of its own. Each part's UI is read from the options' `packages` (kit/package's `loadPackage` results, or any entry with a `ui`), matched by Dialect, and `page.out.<control>` resolves to that Control's record seam; a name no part's UI declares is S111, listing the page's Controls, and, when the packages carry no UI, saying to pass the loaded packages. A glue wires one like any output, `.wire(page.out.<control>, <part>.in.<input>)`, with the usual seam, rename and S checks; a wire from the page adds it as a part, so no `.part(page)` is needed (one is allowed). One name is one Control: two parts' equal declarations (canonical data, neither with `each` nor `to`) are one Control the glue may wire to both, and any other pair is S119. S120 warns of a declared Control whose input nothing wires; S121 of two Controls binding one key code (the first declared takes it). The composed page entry gains `controls: { <control>: { kind, seam, records, perFrame, latency?, keyed?, decl } }` (the declaration as data, its functions left out), which kit/run checks page inputs against and a host builds its forms and key maps from; each part entry gains `pointer: { <Draw output>: "<input>" }` from its UI's stage and view tiles. It has no frames, no inputs and no step: kit/run delivers each page input in the log to every wire from that Control at the input's own stamp. For S116 it is a frame part that sends each Control's `perFrame` records a display frame (`pageRuntimeFor`); its warning on a page wire says what happens past the consumer's max: a state Control **folds** (the first max − 1 in order, then the latest), a delta one (`triggers`) **carries over** (the rest wait for the next steps, none dropped). `callGlue(exported, path, { args })` builds a glue's parts with argument overrides (kit/define's `run`, `args`), for a Grip's preview inside a glue.

> **Corrected 2026-11-27 (declared Controls, leaf `FhnOhO`):** this paragraph described `PAGE_CONTROLS`, the DMG host's pad and four buttons, fixed in the kit, sized at `PAGE_CHANGES_PER_FRAME` (2) per control; both retired, with `pageInputProblem` and the `pageRuntime` constant.

**An overflow policy** (Ben's ruling 7, 2026-11-26): `{ overflow: "keepLast" | "keepFirst" }` on an Event wire turns its S116 into a warning that names the policy (the fix: raise the max and remove the policy if every record matters). At run time each consumer step takes at most the consumer's max, the newest or the first, and drops the rest, counted in `stats().overflow` and noted once per wire (kit/run). The consumer's max never changes, and a wire that cannot overflow is unchanged. A policy on a page wire replaces its default fold ("The page", above), and its S116 warning says so: keepFirst can then drop the final release and leave a button down. A policy on a value wire, or one that is neither, is S102. The plan says `overflow keepLast`.

**Draw wires** ([`draw.js`](draw.js); the draw-list draft, as ruled 2026-11-26). A part's Draw outputs are judged at the max its built Program gives (kit/define's `seams.draws`, ruling 1), so S204 and both sides' printed seams use it, not the Dialect's ceiling. A Draw wire plans one conversion of kind `draw` (`field` `""`) along the frame path, by scale and offset; kit/run converts each op by it ([kit/draw](../draw/README.md)'s `convertOp`). The composed record's `view` names the shown part's Draw output the page draws: its only one, or the one named `view` (S402 when there are several and none is). Given `profile`, the kinds the shown list can hold are read from its builder and followed through every Draw input the builder spreads to the producer wired to it, and through every input of a layer ("Layers", below); a kind the profile does not draw is S401, naming the output whose builder writes it and the shown output. Counts are never judged here: the composer owns the budget, and the profile counts at draw time. A builder whose kinds the kit cannot see (a computed tag, a helper's result) is left to the draw-time check; it does not hide the kinds the kit can see, which are judged all the same.

**Queue bounds** ([`queues.js`](queues.js); the clocks draft's queue ruling). Queues live in workbench time, so their length depends only on rates and per-step maximums, as in synchronous dataflow. With the runtimes, each reliable Event wire's bound is the producer's per-step max (its runtime's `events.out`) times the most producer steps one consumer step can see: for a tick consumer, in a window of its period (a tick producer's `ceil(period_c / period_p)`); for a frame consumer, in a window of the catch-up cap; a demand consumer is woken by the Event, so one producer step. A frame producer counts as stepping at most every 1/240 s, except into a frame consumer: the two step on the same frames, so one producer step. A demand producer counts at most once per instant: the distinct instants of the tick clocks (where two tick clocks meet, one instant; exact while their combined pattern repeats within 100,000 steps, an upper bound past that), plus the frames. Into a frame consumer, whose window (its last frame, this frame] holds one frame, that is 1 plus the tick instants in the catch-up cap. A bound above the consumer's max (its runtime's `events.in`) is S116, naming both sides and the two fixes: raise the max, or `{ keepLast: n }` on the input. `queueProblems(parts, wires, runtimes, { catchUp })` is exported for the scheduler, which refuses the same composition.

The codes are the relay trial checker's ([scripts/seams-trial](../../scripts/seams-trial/README.md)), kept where the meaning is unchanged, so its records still read; S115, S116 and S205 are new with the 2026-11-26 rulings, and S117, S118, S207 and S208 with the rulings on a wire constant and a param wire (the same day); S404 with the layer (2026-11-27). In a run, a re-plan's S251, S253, S254 or S256 is a failed rebuild's diagnostic, in its build event ([kit/run](../run/README.md)).

## Layers

Ruling: Ben, 2026-11-27, [the layer and package tests plan](../../project/2026-11-27-layer-and-package-tests-plan.md), "Rulings" 1 ([`layer.js`](layer.js)). Drafted in leaf `LiOmY9`, revised after three blind composers wrote the M4 glue against it, all clean at their first check with no massage ([the layer dogfood findings](../../project/2026-11-27-layer-dogfood-findings.md)), and built in leaf `pQKgWN`. Each decision below that the ruling leaves open gives its reason.

A **layer** is a built-in part, like the page, that draws several Draw outputs as one picture, each over the one before. The kit knows the producers wired into it, so it derives what a composer would otherwise copy by hand: its output's max is the sum of the producers' built maxes (kit/define's `seams.draws`), each input takes its ceiling from its producer, and its frame is the bottom layer's, so no ceiling and no canvas size is typed. Where a picture sits over the bottom one is still the composer's: a `.frame` edge (below, "Placing a picture"). Because it is a part, a layered picture can be shown, wired into another part's Draw input, or layered again.

```js
import { compose, layer } from "kit/compose";

// a layer made by name: its arguments are Draw outputs, bottom first
const <layer> = layer("<layer>", <part>.out.<output>, <part>.out.<output>);
return compose("<name>")
  .part(<part>).part(<part>)
  .frame(<part>.frame.<frame>, <part>.frame.<frame>, { scale: <n>, offset: [<x>, <y>] })
  .show(<layer>);                                        // or .wire(<layer>.out.view, <part>.in.<input>), or layer it again

// the shorthand: two or more Draw outputs, bottom first, add a layer named `layers` and show it
return compose("<name>").part(<part>).part(<part>).show(<part>.out.<output>, <part>.out.<output>);
```

### API

| Export or call | Does |
|---|---|
| `layer(<name>, <output>, <output>, ...)` | a layer part named `<name>` (lowercase letters, digits and `-`, as `compose`'s; S102 otherwise), over two or more Draw output handles, in painter's order: the first argument is drawn first, at the bottom. Fewer than two, an argument that is not an output handle, or one output given twice is S102; an output whose seam is not a Draw list is S404 |
| `.part(<layer>)` | allowed, never needed: a layer joins the composition at the first call that names it (`.part`, `.show`, a `.wire` or `.frame` naming one of its handles, or another layer's argument), as a wire from the page adds the page. `.part` of one layer twice is S102 |
| `.show(<layer>)` | shows the layer: the page draws its output, `view` |
| `.show(<output>, <output>, ...)` | shorthand for `.show(layer("layers", <output>, <output>, ...))`: two or more Draw output handles, bottom first. A part named `layers` beside it is S101, whose fix says to name the layer with `layer(<name>, ...)` |
| the producers | each output's part is added with `.part(<part>)` as usual: a layer joins the composition when it is named, but naming an output adds nothing, so an output of a part not added is S102 (as for `.wire`) |
| `<layer>.out.view` | the layer's one output: `Draw<sum>@<frame>`, where `sum` is the sum of its producers' built maxes and `<frame>` is the bottom producer's frame. Wire it like any Draw output (S204 against a consumer's smaller max), show it, or pass it to another layer |
| `<layer>.in.<...>`, `<layer>.frame.<...>`, `<layer>.param.<...>` | none: S111, with a fix that names what to do instead (pass the output to `layer`, relate the bottom producer's frame) |

### Decisions

- **How a glue makes one: both a `layer(<name>, ...)` builder and the `.show` shorthand.** The ruling asks for both: a part, so a layered picture can be wired or layered again, which needs a handle the glue can name (`<layer>.out.view`); and the shorthand, because showing two pictures as one is the common case and needs no name. `layer` is exported by kit/compose beside `page`, so a glue imports nothing new (`GLUE_SPECIFIERS` already allows `"kit/compose"`). The shorthand's layer is named `layers`, a fixed name, so the plan, diagnostics and addresses (`lab:<name>#layers.out.view`) can name it; a glue that wants another name writes `layer`.
- **Inputs: given as arguments, in painter's order by position; not named ports wired with `.wire`.** Order is the only thing that tells a layer's inputs apart, and an argument list shows it on one line; named ports would make the composer invent a name per input and then keep a second order (the wires' or the names') in step with the drawing. So a layer's inputs are fixed when it is made: no `.wire(<output>, <layer>.in.<...>)` (S111), no wire options on them (no rename, set, delay or overflow means anything for a picture). In the composed record each argument is still a wire, `<part>.out.<output> → <layer>.in.<i>`, `<i>` counting from 0 at the bottom, so the plan, the cycle check and kit/run treat it as they treat every Draw wire. One output given twice in one layer is S102: drawing the same list twice doubles its count for nothing a composer would want, and is almost always a slip. The same output may feed several layers, as an output may feed several wires.
- **Ceilings come from the producers.** Each input's seam is its producer's output seam at that Program's built max (`withDrawMaxes`, as for every Draw wire), so no input is ever too small and a layer input is never S204. The output's max is the sum of those maxes: the most ops the concatenation can hold. A producer that does not build stops with its own diagnostics, and the layer, like any consumer of an unbuilt part, is not judged; nor are wires from it.
- **Differing frames: each input converts to the bottom input's frame through the frame graph.** The bottom input's frame is the layer's frame; every other input plans a `draw` conversion from its producer's frame to that one, by the same path search as any wire, so the composer relates frames with `.frame` exactly as for a wire, and no extent is typed twice. No path is S251 (its fix suggests the `.frame` call between the two parts' frames), two disagreeing paths S253. Draw frames are always 2-D, so S257's dims case cannot arise. The layer has no frame of its own in the graph: a second name for the bottom producer's frame would be a node with nothing to say, and `.frame` on it would be a second way to say the same edge. When the bottom input is itself a layer's output, the frame is that layer's bottom frame, and so on down.
- **What the page draws, and its box.** A shown layer's list is its inputs' converted lists concatenated bottom first; the box kit/run's `pageView` gives the renderer is the bottom producer's frame extent for that producer's record in force (followed down through a layer at the bottom), **grown to the union of its other inputs' placed boxes** (each input's own box, its frame's extent or a layer's box, mapped by its wire's conversion; an input whose frame has no extent adds nothing), so a picture anchored outside the bottom one (a label under it) is on the page, and the box need not start at the origin (Ben's ruling, 2026-11-27; until leaf `QqirvU` it was the bottom producer's extent alone). A bottom frame with no extent gives no box, as a shown part's does; the page then has no size, and since a layer has no text stage to fall back on (below), it reports **H010** rather than showing a blank page (a shown part with no extent keeps its text stage, and no diagnostic). The page sizes its canvas to that box (kit/page's `page.size`, at creation) and draws from its `min` corner, so an upper picture's ops outside every input's box fall off the canvas, as any shown list's do; nothing clips or moves them. The page host shows each part's tiles, inputs and params as it does today; its fallback stage (a custom element or the text view, for a shown part with no Draw output) never applies to a layer, which always has one, so the host never looks a package up by a shown layer's name (kit/page/host's `textStage` hides its fallback stage for a layer).
- **Placing a picture** (added after the dogfood: all three legs asked). `.frame(<a>, <b>, { scale, offset })` maps a point `p` in frame `a` to `p × scale + offset` in frame `b`, so `.frame(<top part>.frame.<frame>, <bottom part>.frame.<frame>, { scale: 1, offset: [<x>, <y>] })` draws the top picture's origin at `[<x>, <y>]` in the bottom picture, at its own size. `"fit"` scales the top extent by one scale to fit inside the bottom one and centers it, which suits a background, not a panel. A conversion moves a `text` op's `at` and never scales its glyphs ([kit/draw](../draw/README.md)'s op table), so a top picture that holds text wants scale 1. An anchored edge computes the offset from the two extents: `.frame(<top part>.frame.<frame>, <bottom part>.frame.<frame>, { scale: 1, anchor: [<x anchor>, <y anchor>] })` ("An anchored edge", at the end of this file; built in leaf `QqirvU`). Until then the offset was computed by hand (to center a 160-unit panel on a 192-unit level, 16); the layer derives the ceilings and the box, the anchor the placement.
- **S401 follows through a layer.** The kinds a layer's output can hold are the union of its inputs' kinds, each followed to its producer as a Draw input is today (`kindsReaching` visits every input of a layer, and through a layer wired into a part's Draw input). S401 names the output whose builder writes the refused kind, never the layer, and the shown output (`<layer>.out.view`). An input whose kinds the kit cannot see is left to draw time and does not hide the other inputs' kinds. Counts stay the profile's at draw time: the summed max is a ceiling, not a budget.
- **kit/run never steps a layer** ([kit/run](../run/README.md), "Layers"). It has no state, no clock, no runtime and no params, so a composition needs no runtime for it (as for the page), it adds nothing to the log, the state hashes or `stats()`, and S116 never concerns it (Draw wires are value wires). Its output, whenever a wire or `pageView` reads it, is each input wire's list carried as any Draw wire's is (`carry`, so `convertOp` by the planned edge) and concatenated in order. A read through a delayed wire reads every producer under the layer as the instant began, since the delay is the reading wire's; `snapshot(<layer>)` answers `{ state: null, revision: 1, T, draws: { view } }` computed the same way (`T` the latest instant a producer under it committed at). The scheduler orders a layer's consumers after all its producers, through its input wires. A record kit/compose would not have built is refused (N007), never run or drawn empty: a layer with an input from no producer, an output on two inputs, a `layer.inputs`, `max` or `frame` that disagrees with its wires, a delay or rename on a wire into it, or a wire from a layer port but `view`.
- **Cycles.** A layer's input wires count in the cycle check like any wire (S115), but they take no options, so the fix never names one: it names the delayable wires of the next hop in the loop (typically the wire from the layer into the part whose output the layer holds).
- **How kit/run tells a layer from a user part.** A part entry in the composed record carries `layer` (below). A name or Dialect name alone cannot tell (kit/run and kit/page test the `layer` field everywhere, so a user Dialect named `layer` is an ordinary part) a built-in from a user package that happens to be named `layer`, and several layers can exist, so the page's check (`dialect === "page" && name === "page"`) does not carry over.

### The composed record

A layer is a part entry `{ name: "<layer>", dialect: "layer", record: {}, layer: { inputs: ["<part>.out.<output>", ...], max: <sum>, frame: "<part>.<frame>" } }`, with no `version`, after the parts, in order of first mention (a layer among another's arguments comes before it). Each input is a wire entry `{ from: "<part>.out.<output>", to: "<layer>.in.<i>", convert, rename: {}, delay: false, dropped: [] }`, listed before the glue's own wires, whose `convert` is empty for the bottom input (already in the layer's frame) and one `draw` conversion for any other input in another frame. When the layer is shown, `show` is `"<layer>"` and `view` is `"view"`; a layer's one Draw output is named `view`, so S402 never concerns it.

### Codes

S404 is the layer's own: a layer argument whose output is not a Draw list (in the codes table above). Kept with a layer's meaning: S101 (a layer named like another part, `layers` included), S102 (`layer` given fewer than two outputs, a name that is not lowercase letters, digits and `-`, something that is not an output handle, an output twice, a handle of a part not added; `.show` given a mix of a part and outputs, or one output alone), S111 (a layer's `in`, `frame` or `param` handle), S115 (a loop through a layer), S204 (a layer's output into a smaller Draw input), S251 and S253 (an input's frame and the bottom frame), S401 (followed through). `.show(<part>.out.<output>)` with one output is S102: showing one output of a part with several is a different question (S402's), not a layer's.

### The M4 trial's glue, with a layer

The trial's composer wrote a 70-line `overlay` package (`scripts/m4-trial/runs/2026-11-26/compose/overlay/`) and a glue that copied `Draw<302>` and `Draw<8>` from the producers and repeated the level's 192 by 128 pixels as the canvas size. With the layer, that trial's glue (real names, from [that run](../../scripts/m4-trial/runs/2026-11-26/compose/workbench.js)) reads as below; it builds and draws on the page ([scripts/m4-trial](../../scripts/m4-trial/README.md)'s `test/layer.test.js`):

```js
import { compose, page } from "kit/compose";
import { gemgrid } from "gemgrid";
import { scoretimer } from "scoretimer";

export default () => {
  // 12 by 8 cells of 16 pixels. Two rows of wall on top sit under the score panel.
  const level = gemgrid("level").map([
    "############",
    "############",
    "#P..*....*.#",
    "#.##.##.##.#",
    "#.*......*.#",
    "#.##.##.##.#",
    "#.*..*...*.#",
    "############",
  ]);
  const round = scoretimer("round").label("GEM RUSH").lasts(30);

  return compose("timed-gems")
    .part(level).part(round)
    .frame(round.frame.panel, level.frame.px, { scale: 1, offset: [16, 4] })
    .wire(page.out.pad, level.in.pad)
    .wire(level.out.picked, round.in.scored, { set: { points: 1 } })

```

No overlay package, no `.size`, no copied ceiling: the layer `layers` is `Draw<72>@px` in gemgrid's `px` (67 + 5, from the two built Programs; **corrected 2026-11-27**, leaf `teBNYM`: this said `Draw<310>`, 302 + 8, which are the Dialects' declared ceilings, not the built maxes), its page box is gemgrid's `px` extent for this map (192 by 128), and the one `.frame` call relates the panel to the level directly instead of both to a third canvas. Its plan's two layer lines read `level.out.view → layers.in.0: unchanged` and `round.out.view → layers.in.1: (value): scoretimer.panel → gemgrid.px, draw, ×1 +[16, 4]`. Naming the layer instead, for a glue that wires or layers it again, is `const screen = layer("screen", level.out.view, round.out.view)` with `layer` imported beside `page` and `.show(screen)`.

## An anchored edge

Drafted in leaf `JBkhsf`, dogfooded in leaf `wCDTzk` ([findings](../../project/2026-11-27-anchor-dogfood-findings.md)), and built in leaf `QqirvU` (2026-11-27), with the re-plan on rebuild that also fixes issue `Wd9nH5` ("fit" edges, a Dialect's edges and the page box stayed stale after a rebuild changed an extent). Why: every blind composer who placed the M4 score panel on the level (three dogfood legs and two rerun legs, [the layer dogfood findings](../../project/2026-11-27-layer-dogfood-findings.md), [the rerun findings](../../project/2026-11-27-layer-rerun-findings.md)) computed the offset by hand from the two extents, and asked for an anchored edge. A hand offset goes stale when a picture's size changes, and `"fit"` cannot help a picture of text, since a conversion never scales a `text` op's glyphs. Ben un-parked it on 2026-11-27 ("I guess we should design the anchor API"). Each decision gives its reason; the dogfood's result is at the end.

**Ruled (Ben, 2026-11-27):** the re-plan on rebuild (kit/run recomputes every wire's conversions after a rebuild; a failing re-plan fails the rebuild), and **a layer's page box grows** to the union of its inputs' placed boxes, so a picture anchored outside the bottom one (a label under it) still shows, and the box may not start at the origin ("Layers" ▸ "What the page draws, and its box").

An anchored edge is an ordinary `.frame` edge whose offset the kit computes from the two frames' extents. It adds one key, `anchor`, to the edge the glue already writes:

```js
.frame(<part>.frame.<frame>, <part>.frame.<frame>, { scale: <n>, anchor: [<x anchor>, <y anchor>] })
.frame(<part>.frame.<frame>, <part>.frame.<frame>, { scale: <n>, anchor: [<x anchor>, <y anchor>], offset: [<x>, <y>] })
.frame(<part>.frame.<frame>, <part>.frame.<frame>, { scale: <n>, anchor: <anchor> })   // one anchor for every axis
// each <anchor> is "min", "center" or "max": where on that axis the first frame's box meets the second's
.frame(<part>.frame.<frame>, <part>.frame.<frame>, { scale: <n>, anchor: { from: <anchor>, to: <anchor> } })
// the pair form (added after the dogfood, leaf `wCDTzk`): the first frame's `from` point on the second's `to` point, each an <anchor> or an array of one per axis
```

### The form

| Key | Takes | Means |
|---|---|---|
| `scale` | a number for every axis, or one per axis (required, nonzero, as today) | as today: a point `p` in the first frame is `p × scale + offset` in the second |
| `anchor` | `"min"`, `"center"` or `"max"` for every axis, or an array of one per axis; or a pair `{ from, to }` of those (**changed 2026-11-27**) | on each axis, the first frame's extent, scaled, is aligned with the second frame's extent at that point: its low edge on the low edge (`min`), its middle on the middle (`center`), its high edge on the high edge (`max`). A single anchor is the pair `{ from: a, to: a }`; a pair puts the first frame's `from` point on the second's `to` point, so a caption's top on a figure's bottom is `{ from: ["center", "min"], to: ["center", "max"] }` |
| `offset` | a number for every axis, or one per axis (default 0) | with `anchor`, added after the alignment: a nudge from the anchored place, in the second frame's units. Positive moves toward `max` on that axis, so an inset from a `max` side is negative and from a `min` side positive (**changed 2026-11-27**: a leg had to derive the second) |

The kit's offset, per axis `i`: scale the first extent (`[min × s, max × s]`, its ends swapped when `s` is negative, so a flipped picture still lands inside), then take the second extent's point (its `to`, or the one anchor) minus the scaled box's point (its `from`, or the one anchor) (the low ends for `min`, the middles for `center`, the high ends for `max`), and add the glue's `offset`. The result is a plain `{ scale, offset }`: every check, path, conversion and printout downstream is the one an ordinary edge gets. In a Draw frame, as the page draws it, y grows downward, so `"min"` on y is the top and `"max"` the bottom: a picture in the bottom-right corner is `anchor: ["max", "max"]`.

### Decisions

- **Vocabulary: `min`, `center` and `max`, per axis, not named points.** The leg that named one asked for `"bottom-center"`. Named points (`top`, `bottom-left`, …) need 2-D and a known direction for y, but an edge relates frames of any dims (a 1-D time axis, a 3-D scene), and a frame's y can grow upward (a chart's data frame, a lens's millimeters about the optical axis). `min` and `max` are the fields of the extent itself (`{ min, max }`, [kit/seam](../seam/README.md)'s Box), so the word says which number is read, in any frame. And the per-axis shape is the one `scale` and `offset` already have (one value for every axis, or an array of one per axis), so it adds no second shape. The cost is a translation in 2-D Draw frames (`min` on y is the top), stated in the table above. If a dogfood shows composers reach for compass words anyway, the fix is the words, not a second vocabulary beside these.
- **One anchor for both frames, or a pair `{ from, to }`. Changed 2026-11-27 after the anchor dogfood** (leaf `wCDTzk`, [findings](../../project/2026-11-27-anchor-dogfood-findings.md)): the first draft had only the single anchor (the first frame's `min` meets the second's `min`, and so on) and parked separate anchors (a caption's top on a figure's bottom, CSS's or Qt's self-and-parent pairs) until a case asked. Both blind legs given "a label centered under a box, touching its lower edge" asked for them: a single anchor can only put the label inside the box, flush with its bottom, and the only way left was a hand-computed offset of the label's height, which is the fault the anchor exists to remove. The two layer legs wanted a panel that does not cover the game, for the same reason. The single anchor stays as the shorthand for the pair with the same point twice, so the common case (a HUD or legend in a corner) is unchanged. A pair is the one way a picture can leave the other's box, so a layer's page box grows to hold every input's placed box (Ben, 2026-11-27; it was the bottom producer's extent, which would have left a label under the bottom picture off the page).
- **Margin or inset: none; `offset` is the nudge.** A separate `margin` key would mean one more name, and an inward sign has no meaning for `center`. `offset` already exists and keeps its meaning (added after scaling); with an anchor it is relative to the anchored place. The one trap is the sign at a `max` side, which the table states and S257 cannot catch (both signs are valid). An inset is a glue literal: it cannot follow a part's param (a glue has no `$`, S104), so an inset that must track a part's own margin belongs in that part.
- **Scale: any scale, as today.** The alignment is computed on the scaled box, so `scale: 1` (a HUD, a legend, a label: text never scales) and any other scale (a thumbnail at `0.5`, a flip at `-1`) need no second rule. Restricting it to 1 would add a code and help no one. **Added 2026-11-27 (dogfood):** two things composers asked about. The anchor aligns the two extents as numbers and does not check that `scale` makes their units agree (a `scale: 1` between a pixel frame and a cell frame is accepted, as for any edge), and a first picture larger than the second is aligned by the same arithmetic, so at `center` it overhangs both sides, with no warning; a layer's page box grows to hold the overhang.
- **What it needs: both frames' extents, for the built records.** Each frame's `extent(record)` ([kit/define](../define/README.md)), as `"fit"` needs. Either one missing is **S256**, its message extended from `"fit"` to an anchored edge, its fix naming the frame without one and offering an ordinary edge, `{ scale: …, offset: … }`. Two frames of different dims are **S257**, as for any edge. A bad `anchor` (a word other than the three, an array of the wrong length, a pair missing `from` or `to` or with another key) is **S257**, a malformed edge. No new code. An unknown edge key is S257 naming the edge's keys (`an edge takes scale, offset and anchor, not 'rotate'`), with a fix that gives each form for the frames at hand with placeholders and no numbers (`.frame(<a>, <b>, { scale: <n>, offset: [<x>, <y>] })`, the anchored form, or `"fit"`). Until leaf `QqirvU` it said `an edge takes only scale and offset, not 'anchor' (there is no rotation in v0)` with the fix `{ scale: 32, offset: 16 }`, which both dogfood panel legs called misleading. A Dialect's `edges(record)` keeps the old message: it takes no anchor.
- **When the offset is computed: when the composition is checked or built**, from each part's built record's extents (`part.extents`, as `"fit"` reads them), and again whenever a part's record changes (below). An anchored edge is a function of the two records; it is never a number the glue holds.
- **How kit/run sees a rebuilt extent: it plans the frames again.** Until leaf `QqirvU` kit/run copied every wire's conversions from the composed record at `createRun` (`kit/run/wires.js`), and `pageView` read the box from the composed record's part records (`kit/run/draw.js`), so a rebuild that changed an extent moved neither, for a `"fit"` edge or a Dialect's `edges(record)` alike (issue `Wd9nH5`, confirmed by its repro, `kit/run/test/replan.test.js`). A glue edit is not that case: the host composes again, so every anchored edge is computed afresh. A rebuild inside a run (a `rebuild` input, or a build-time param through `options.build`) is. So the composed record keeps the glue's edges as written (`frames`, below); when a rebuild changes a part's content key, kit/run plans each wire's conversions again with `replan` (the frame graph from the parts' frames, each Dialect's `edges(record)` for the record now in force, then `frames` in order, each anchored or fit edge computed from the extents now in force), and the page's box comes from the record in force (`run.composed`). A plan that fails (two paths that now disagree, S253; and, by the same rule, a path the rebuild removed, S251, or a quantity's path that no longer scales its axes alike, S254; an extent the rebuild lost, S256, cannot arise today, since a frame's `extent` is the Dialect's and an extent that throws fails the lowering first) fails the rebuild as a rebuild fails today: the previous revision runs on, and the build event carries the S diagnostic. A plan that succeeds applies from the rebuild's stamp: a value or Draw wire read after it converts by the new edge; an Event record already queued keeps the conversion it got when it crossed (`kit/run/delivery.js` converts on push). The build event names each edge that moved, `{ from, to, before, after }`, so `why` can say which extent moved it. The plan is a function of the records in force, so a replay plans the same, and a rewind past the rebuild restores the earlier plan with the earlier record. This one rule also fixes the same staleness for `"fit"`, Dialect edges and the page box; it is the frog, and an anchor that went stale at the first param rebuild would repeat the hand offset's fault.
- **The plan prints the edge it applies, then where it came from.** A wire's line ends as today with the composed edge, and each anchored or fit step on its path adds `(anchored at line <n>: [<x anchor>, <y anchor>] +[<x>, <y>], <box> in <box>)` (for a pair, `[<from anchors>] on [<to anchors>]`) or `(fit at line <n>: <box> in <box>)`, each box `[<min>]..[<max>]` and the offset always one number per axis, so a reader sees which two extents gave the numbers. The path text in S253 prints an anchored step the same way.
- **`"fit"` stays as it is.** It is the case "scale to fit, then center" and suits a background; an anchor at a fixed scale suits a panel. Both are derived edges under the same rules (both extents, computed at check, planned again on a rebuild). The anchor does not cover `"fit"` (an anchor's scale is a number the glue gives; fit's is computed), so nothing is retired. Folding the two into one form, `{ scale: "fit", anchor: … }`, would let a fitted picture sit at a corner, which no case asks for, at the price of `scale` taking a word. Ben's call if such a case appears.
- **Existing edges.** A Dialect's `edges(record)` stays `{ scale, offset }`: a Dialect relating its own frames reads its own record and needs no anchor, and a key other than those two is refused there as today. Only the glue's `.frame` takes `anchor`.
- **S253 and chains.** An anchored edge is compared by its computed numbers. A second path between its two frames that agrees is no error; one that disagrees is S253, as for any edge, and its message prints the anchored step's derivation. Chains compose as today: an anchor relates the two frames it names, by their own extents, and a path through it composes it with the others (run backward when a wire goes the other way). Anchoring one frame on a second and the second on a third places the first in the third by both. A layer has no frame of its own (S111): to place a picture on a layer, anchor it on the frame of the picture at the layer's bottom, followed down, which is the layer's frame. An anchor reads the declared extent, never the ops a picture draws: a picture that draws outside its extent anchors by its extent.

### The composed record

The record adds `frames`: each glue `.frame` call that planned, in glue order, `{ from: "<part>.<frame>", to: "<part>.<frame>", line, given, edge }`, where `given` is `"fit"` or the edge as written, normalized per axis (`{ scale, offset, anchor? }`, an anchor always as the pair `{ from, to }` of per-axis words, a single anchor the pair with one point twice), and `edge` is the `{ scale, offset }` computed for the records the composition was built with. Each wire's `convert` is unchanged in shape: it is what the path gives.

### Codes

No new code. **S256** is `"fit"` or an anchored edge with a frame that has no extent, or (`"fit"`) dims that differ. **S257** gains a malformed `anchor`. **S253** and **S251** are unchanged in meaning; S251's fix for a Draw wire (a picture onto a picture) whose frames both have extents offers `{ scale: 1, anchor: "min" }` beside `"fit"`. In a run, a re-plan's S253 (or S251, S254 or S256) is a failed rebuild's diagnostic, in its build event.

### Beyond the HUD

Two placements from [Ben's sketches](../../project/2026-11-27-workbench-sketches.md) that are not games:

```js
// a legend (or a label) on a chart: Lens Bench's performance tab, or a label on its cross-section
.frame(<legend>.frame.<frame>, <chart>.frame.<frame>, { scale: 1, anchor: ["max", "min"], offset: [-<inset>, <inset>] })
// a label under a box (changed 2026-11-27, dogfood): the pair form, touching, with no hand-computed height
.frame(<label>.frame.<frame>, <box>.frame.<frame>, { scale: 1, anchor: { from: ["center", "min"], to: ["center", "max"] } })
// a box on a Book page: a running header, a page-number badge, a fixed margin note
.frame(<box>.frame.<frame>, <page>.frame.<frame>, { scale: 1, anchor: ["center", "max"], offset: [0, -<inset>] })
```

- **A legend or label on a chart or a lens cross-section: served.** Both are one picture over another at its own size, at a corner of the other's extent, which is the HUD's case; the anchor follows the chart's or the cross-section's extent when a param that sizes it (the lens's imaging area, the chart's size) rebuilds the part, by the re-plan above. The chart itself waits on an x/y series chart in Draw (gap 5 of [the feasibility findings](../../project/2026-11-27-sketch-feasibility-findings.md)); the anchor does not. If the cross-section's frame is millimeters with y up, the anchor still reads the right numbers (`min` and `max` are the extent's), but a picture drawn in pixels then wants a scale between the two frames, which is the stage-units question below.
- **A sidebar or footnote on a Book page: not served; a fixed box on the page is.** A sidebar's or a footnote's place follows the text flow: which page it lands on and how far down depends on pagination, which the Book's runtime computes per page and per reflow. An anchored edge is one static edge per composition, computed again only on a rebuild, and relates whole frames, so it cannot put a box beside the line that cites it. The Book part places its own sidebars and footnotes, taking another package's content as data (gap 7) or, for a placed drawing, through a transform op (below). What the anchor does serve on a page is a box that sits at the same place on every page: a running header or footer, a page number, a watermark, a margin column at a fixed side.

### Where it meets the open gaps

Not designed here; each is where the anchor would touch a gap the feasibility findings name.

- **Stage units and zoom** (gap 5: today one unit is one pixel). An anchor is in the second frame's units. If the stage zooms, a picture anchored to a zoomed frame moves and scales with it, which suits a label pinned to a lens element and not a legend or a HUD, which should stay the screen's size. That wants an anchor to the view (the screen), not to a frame: a target the frame graph does not have.
- **Several views** (gaps 1 and 5: one shown output today). An anchor relates two frames, not a view's box, so a picture placed in one view of several is placed by its frames; anchoring to a view's own box (a tab, a split's pane) is the same missing target as zoom's.
- **A transform op** (the draw-list draft parked a group or transform op; Book needs one to place another package's diagram). An anchored edge places a whole list once per wire; a transform op would place a sub-list inside a list, as often as the producer wants (one diagram per page, at a place pagination computes). The anchor does not replace it. Its arithmetic (a box aligned in a box at `min`, `center` or `max`) is the part such an op could share.
