# Draw-list paper trial

The dogfood trial of the ruled draw-list draft ([project/2026-11-26-draw-list-draft.md](../../project/2026-11-26-draw-list-draft.md), "Next"), before `Draw` is built (leaf `e3qYus`). A relay of three blind sessions: a **maze author** gives the maze package (entity-shaped) a `Draw` output built one op per item; a **particles author** gives particles (Canvas-shaped) one built with a pen; a **composer**, on their hand-ins, writes a **root package** whose `Draw` inputs take both pictures and whose `Draw` output layers them with a HUD, and a glue program that wires and shows it. The findings are in [project/2026-11-26-draw-list-trial-findings.md](../../project/2026-11-26-draw-list-trial-findings.md).

It is a **paper trial**: `Draw` does not exist in the kit, so the checker emulates it from the packet's `draw.md`, on the real kit for everything else. It reuses the seams relay harness ([scripts/seams-trial/](../seams-trial/README.md)): its run.sh guards, its placeholder `seams.md`, `runtime.md` and `packaging.md`, its package checks and G codes, its loader, D-pad and run helpers, and its `summary.js`.

## What is here

| Path | What |
|---|---|
| `docs/` | the trial's own packet, in placeholder style (names and numbers an author chooses are `<placeholder>`s with their rule; no worked example): `draw.md` (the `Draw<max>@frame` seam, the op table, `colors` and `images`, the three builders `from` / `each` + `from` / `pen` and `layers`, `Draw` inputs read through a whole-list builder's second parameter, conversion on the wire, renderers and profiles), `rules.md` (R1–R10, the W codes), `task-{maze,particles,compose}.md` |
| `brief.md`, `run.sh` | the brief and launcher: `run.sh maze\|particles <dir> <model>`, `run.sh compose <dir> <model> <maze-leg> <particles-leg>`. `<dir>` must be fresh, absolute, outside the repository and `~/.claude` (use `/private/tmp/e3qYus-<leg>`). It copies `draw.md`, `rules.md`, the role's task, seams-trial's placeholder `seams.md`, `runtime.md` and `packaging.md`, `check.sh` and `hash.sh`; an author gets the seams relay's reference hand-in (`scripts/seams-trial/fixtures/valid-2/<role>`, version 0.2.0, ports and runtime already there); a composer gets both authors' packages as they left them and `api.md` (kit/API.md) to write its root package with. No `reference.md`: kit/package's reference would print the stand-in ports |
| `check.js` | `node scripts/draw-trial/check.js <dir> --role maze\|particles\|compose`, with `DRAW_TRIAL_LOG` appending one JSON line per run. Exit 0 clean, 1 violations, 2 bad invocation, 3 the checker failed (the stack goes only to the log, so a blind leg sees no repository paths), 4 a folder is missing |
| `checker/define.js` | the `kit/define` a hand-in imports (the UI trial's stand-in, with Draw emulated): `defineDialect` takes each `Draw<max>@frame` port and the `colors` and `images` keys out into `draws`, and puts an Event port of `{ at: point2@<frame> }` in each Draw port's place. The real kit then accepts the Dialect, and kit/compose checks every Draw wire (S111, S112, S251, S301) and plans its frame edge, which the checker converts each op by; nothing ever pushes to those ports, so a run is unchanged. `defineRuntime` adds the stand-in ports' events maxes |
| `checker/hook.js` | resolves every `kit/define` import to `define.js`, registered after the UI trial's hook so it runs first |
| `checker/ops.js` | the op table typed (`typeOp`), `colors` and `images` checked, a color resolved to `#rrggbbaa`, an op converted by an edge (draw.md's column: positions by scale and offset, `size`, `r`, `width` by scale, `tiles` and `text` by `at` only), its box, and an op carried across a wire (colors resolved, images named `<part>.<image>`) |
| `checker/builders.js` | a Draw output's builders read into layers (W002), the static max of their source (an `each` list's max, a pen layer's `max`, an array literal's ops plus each spread input's max), the source scanned with kit/parse (subset codes; `map`, `flatMap`, `filter`, `forEach`, `reduce`, `push`, `concat` are W003; a free name that is not a parameter, a Dialect global other than `$` and the inputs, or a top-level helper or constant of the file is W003; a helper it calls is scanned too), and the builder run as plain JavaScript on one state |
| `checker/render.js` | the Canvas 2D stub (one call per op, counts, ops outside the stage) and the Game Boy profile (refuses `rect`, `ellipse`, `line`, images not in 8-by-8 cells or scaled, a third `tiles` layer, a stage over 160 by 144, more than 40 sprites or 10 on a row; colors to 4 shades by brightness), and the profile's composition-time refusal of a `Draw<max>` over 40 |
| `checker/legs.js` | **An author leg:** the seams relay's `checkLeg` (its G002–G004 dropped: the starting package already has them), W030 (minor below 3), the Dialect's Draw declarations (W001–W003, a static W005), then every example run headless (the maze steered to a coin) and the list built after every step: typed (W004), within its max (W005), not throwing (W006), showing the run (W010: the maze, an op over the player's cell; the particles, ops near the first five live particles), and the largest list drawn by both renderers (the Game Boy's with the frame's extent fit into 160 by 144). **The compose leg:** the one root folder beside `maze/` and `particles/`, kit/compose's check with the stand-in seams printed as `Draw<…>@<frame>`, the root's own declarations, the shown root (W020), the Draw wires (W021: both ends Draw, the output's max within the input's), both pictures wired into the root (W022); then the run, steering the maze to a coin: after each step each producer's list is built, carried and converted by its wire's edge into the root's inputs, and the root's builder runs on them; its list is typed and held to its max, must hold a text op (W023), both pictures (W022), and within half a second of the pickup a particles op within one converted cell of the coin, drawn after the maze's op there (W024); then the renderers on the largest shown list, and a replay |
| `fixtures/valid/` | the integrator's reference hand-ins, written from `docs/` (the dogfood): maze 0.3.0 with `view: Draw<8193>@cell` in three layers (`each: "walls"` rects, `each: "coins"` ellipses, the player as one whole-list op) and `walls` and `coins` added to the state; particles 0.3.0 with `view: Draw<10000>@px`, a one-line pen of ellipses; `arcade/`, a root package (`board`, `fx` Draw inputs, a `score` value input copied into the state by its runtime, `view: Draw<18194>@screen` as `[...i.board, ...i.fx, <text op>]`); and `workbench.js`. The leg folder for a compose check is `fixtures/valid/` itself |
| `test/` | `ops.test.js`, `builders.test.js`, `render.test.js` (units), `legs.test.js` (the reference hand-ins pass every leg; each of twelve broken copies gives its code) |
| `record.js` | `node scripts/draw-trial/record.js <leg-dir> <runs-dir>/<leg>`: copies a finished leg's package folders, `workbench.js`, `REPORT.md`, `log.jsonl` and its transcript, gzipped |
| `runs/2026-11-26/{maze,particles,compose}/` | the three recorded legs: hand-in, `REPORT.md` (the leg's own), `REPLY.md` (its closing reply, saved by the integrator), checker log, gzipped transcript |

`fixtures/` and `runs/` import `kit/define` by its bare name, so they are excluded from `tsconfig.json` and kept out of `test/` ([project/gotchas.md](../../project/gotchas.md)).

## Running the trial

The maze and particles legs run in parallel, then the compose leg on their hand-ins:

```sh
scripts/draw-trial/run.sh maze /private/tmp/e3qYus-maze claude-sonnet-5-5
scripts/draw-trial/run.sh particles /private/tmp/e3qYus-particles claude-sonnet-5-5
scripts/draw-trial/run.sh compose /private/tmp/e3qYus-compose claude-sonnet-5-5 /private/tmp/e3qYus-maze /private/tmp/e3qYus-particles
node scripts/seams-trial/summary.js /private/tmp/e3qYus-maze /private/tmp/e3qYus-particles /private/tmp/e3qYus-compose
```

`run.sh` needs the sandbox off (`claude` reads `~/.claude`).

**Run 2026-11-26** (one relay, Sonnet 5.5 at every leg). The maze leg took 9 turns, 82 s and $0.34, and was clean at run 1. The particles leg took 9 turns, 62 s and $0.34, and was clean at run 1. The compose leg took 12 turns, 125 s and $0.56, and failed W024 three times. That was a checker defect: W024 converted the coin's cell by the maze's Draw wire edge, which starts from the frame the picture is drawn in. It is now fixed, with the recorded leg as its regression test. The composer's hand-in, unchanged, now checks clean, with a burst of 60 ops over the coin at (44, 68). The author legs' Game Boy note also now says that it fits the frame to the screen, which the maze leg had read as contradicting `draw.md`. The findings are linked above. Copy each leg to `runs/<date>/<leg>/` afterwards, and `diff -r` the composer's `maze/` and `particles/` against the authors' hand-ins (the checker trusts the hashes).
