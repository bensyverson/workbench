# The H5 run

H5 (M3, leaf `3Cd9hb`): fresh agents build the particles language from [kit/START.md](../../../kit/START.md), [kit/API.md](../../../kit/API.md) and (from 2026-11-25, after the rerun) the topic pages in [kit/docs/](../../../kit/docs/) alone, and the [hidden programs](../hidden/README.md) decide green. Each agent is a separate `claude -p` started in a fresh directory outside the repository, so it loads no `AGENTS.md` and no project memory (unlike a subagent, which inherits both: [project/gotchas.md](../../../project/gotchas.md)), and its stream-json transcript records every tool call, so what it named in its tool calls is measured rather than self-reported (the Read tool's files, the files `cat`, `head`, `tail` and `sed -n` named, and the paths of its Bash commands; not what a command's output showed it, and not a path a command built in a variable). Blindness itself is not enforced: it rests on the brief and on checking the transcript afterwards ([below](#usage)).

| Path | What |
|---|---|
| `brief.md` | the brief each agent got, word for word |
| `run.sh` | sets up one agent's directory (`START.md`, `API.md`, the topic pages as `docs/*.md`, `dream-code.md`, `check.sh`) and runs `claude -p` there with the brief: Bash, Read, Write, Edit, Glob and Grep allowed; web, subagents and MCP servers off |
| `summarize.js` | per directory: model, turns, time, tokens, tool calls, the files opened with the Read tool and the files read through the shell (`cat`, `head`, `tail`, `sed -n`), every call that touched a path outside the directory, checker runs and the first clean run |
| `runs/<date>/agent-x/` | the record: each agent's definitions (and any module of its own), examples, `REPORT.md`, and `log.jsonl.gz` and `transcript.jsonl.gz` (gzipped; `gunzip -k` them into a scratch copy before `summarize.js`). The first run, 2026-11-25, is [project/2026-11-25-h5-run.md](../../../project/2026-11-25-h5-run.md); the rerun after the rulings, `runs/2026-11-25-rerun/`, is [project/2026-11-25-h5-rerun.md](../../../project/2026-11-25-h5-rerun.md). From the rerun on, each recorded log line keeps only the files that changed since that file was last logged (`filesPresent` lists them all), since probe loops of a thousand checker runs otherwise repeat every file each time |

## Usage

```sh
scripts/particles/h5/run.sh /private/tmp/<job>-h5/agent-a claude-opus-5-5     # one agent; the directory must not exist
node scripts/particles/h5/summarize.js /private/tmp/<job>-h5/agent-*           # the run figures
node scripts/api-pilot/score.js /private/tmp/<job>-h5/agent-a scripts/particles/hidden --lang particles   # the hidden score
```

The directory must lie outside the repository and outside `~/.claude` (a blind run cannot write there: project/gotchas.md); `run.sh` refuses either. The directory must be an absolute path (a relative one is refused), and `run.sh` canonicalizes it before the guard: it resolves `..` and symlinks in the part that exists (`cd` and `pwd -P`) and refuses `.` or `..` in the part that does not, so `/private/tmp/../../Users/…/repo/x` and a symlink into the repository are refused too, and nothing is created before the guard passes. **That guard stops a mistyped path, not an agent.** The agent runs as you, unsandboxed, with Bash, Read and Glob over the whole disk, so it can read the repository if it chooses. Blindness rests on the brief (which tells it to use only its directory) and on the after-the-fact check below; this tooling does not sandbox it, and a run whose transcript names a repository path is not blind. Its Bash runs unsandboxed, since `claude` and the checker need the home directory. The H5 score leaves out seven hidden rejects (r21b, r21c, r21s, r21u, r21l, r21n, r22l; [hidden/README.md](../hidden/README.md)): report the score over the rest, and those seven separately.

`summarize.js` flags a Bash command as outside when, leaving out heredoc bodies, it names an absolute path (or `/` itself, as in `find /`) not under the directory (system binaries aside), climbs out with `..`, or names `~` or `$HOME`; a Glob or Grep is flagged for an outside `path`, an absolute or `~` `pattern` (Glob) or `glob` (Grep), and a Read for a path under `~`. `//` comment markers, `</canvas>`-style text and URLs are not paths. It lists every call it flags whole, so the reader judges. It still over-flags what is not in a heredoc but looks like a path: an `import … from "../x.js"` inside a quoted shell string counts as climbing out, a sed substitution such as `s/a/"b"/` can read `/"b"` as a path, and a `/tmp` or sibling scratch path is outside the directory, which it is. Recorded over the H5 runs and the UI trial runs (2026-11-25), the flags fell from 1 to 41 per run to 0 to 15, none naming a repository path. A path built some other way (`R=$(dirname …); cat $R/x`, a `cd` then a relative path) is not caught: read the flagged list and skim the transcript's Bash calls. Paths are judged against the directory the agent ran in (the transcript's init `cwd`), not the directory the transcript was copied to, so a recorded run summarizes as it ran. The check that settled the first run was a scan of every tool input for a repository path (`/Users/`, `workbench`, `kit/define/`), which found none.

The figures are what the tool calls name. `Read tool` lists the files opened with the Read tool; `shell reads` lists what `cat`, `head`, `tail`, `sed -n` and similar named (JSON: `reads`, `shellReads`). Neither is every file the agent saw: a Grep, an `ls` or a command's output shows content too.
