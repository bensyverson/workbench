# Definition API trial kit

The dogfood trials of the Definition API (M3): fresh agents get only the API document, a strict rule set and the data-tools Dream Code, define the data-tools language with the API as far as it goes, and report where it failed them. Trial 1 (leaf `lMNmIB`) ran on paper, on the first draft, checked by a script with its own copy of the validators; trial 2 (leaf `O63kB5`) runs on the API as built ([kit/define](../../kit/define/README.md)), and the checker runs the real thing. The design behind the API is [project/2026-11-24-definition-api-design.md](../../project/2026-11-24-definition-api-design.md).

## Usage

```sh
node scripts/define-trial/check.js <dir>          # <dir> holds data.dialect.js, data.grammar.js, examples/*.js
node scripts/define-trial/check.js <dir> --json   # the same result as one JSON object
DEFINE_TRIAL_LOG=trial.jsonl node scripts/define-trial/check.js <dir>   # also log the invocation
node scripts/define-trial/check.js <dir> --lang budget   # another language: <dir>/budget.dialect.js and budget.grammar.js
node scripts/define-trial/check.js <dir> --effects --lang particles   # the per-slot effects draft (trial 4)
```

Each violation prints as `<file>:<line>: <code> <message>` and a `  fix:` line (then a `  tip:` line when the kit gave both a fix and a different tip); rules.md lists the codes. Exit 0 means no violations, 1 violations, 2 a bad invocation, 4 a missing directory or definition file. With `DEFINE_TRIAL_LOG` set, every invocation appends one JSON line: `time`, `dir`, `ok`, `diagnostics`, `files` (the text of every candidate file) and `loadError`.

How it works: a Node module hook (`module.registerHooks`) resolves `kit/define` to `checker/define.js`, which re-exports the real kit/define, so the candidate's files run unchanged. Its `load` hook appends to each example an export returning the file's top-level bindings (named by `topLevelNames`, [kit/parse/toplevel.js](../../kit/parse/toplevel.js); lines keep their numbers), and the checker passes them, with each top-level `const` declaration's initializer text (`topLevelBindings` filtered by `helperSources`, so a helper is only the arrow its `const` declaration writes; a name the scan finds declared twice is `LOAD`, below) and the file's `buildTimeNames`, to `.check({ scope, sources, buildTime })` and `.build(…)`: the module scope a lambda's free names resolve against ([kit/define](../../kit/define/README.md), "Module scope"). A lowering error inside a top-level helper is placed at its `const` line. A `DefinitionError` from `defineDialect` or `defineGrammar` is recorded, each problem located by searching the file for its path's keys from the call's line; a refused Dialect is replaced by a stand-in with its convention names, so the Grammar is still checked without knock-on refusals. Once both definitions are accepted, each example is loaded (a `B001` thrown at a call is reported as the kit gave it), its default export, the Program as a function of its params (`($) => program(…)…`, a function of exactly one parameter, C001 otherwise; one parameter with a default, `($ = {}) => …`, counts, though its `length` is 0, and a rest parameter does not), is built by kit/define's `run()` with the params at their declared values, which gives every collected `B…` code and the Dialect's own checks, and a Program that builds clean is passed to the Grammar's `lower()`: construct state call by call, convention functions, every lambda's body. A lowering diagnostic inside a lambda is placed at its line by finding the lambda's source in the file. An exception from the candidate's own functions (`environment`, a convention, a check, `init`, `step`) is `C005` at the line that threw.

The checker's own codes: `C001` (an example neither exports a builder chain nor is refused), `C005`, `C006` (an import other than `kit/define` or the candidate's own files, static or dynamic, in the Dialect, Grammar or an example: R1) and `C007` (no example files at all: R6); `LOAD` is a definition file that cannot be loaded at all, or an example whose top level the scan misread: `topLevelBindings` found a name declared twice and threw a `ScanError`, so the checker reports it at the second declaration and checks nothing more of that file rather than vouch for a helper by either declaration. Check v0's other codes are retired, and the kit's own replace them: `C002` (a lambda that does not parse) is `B007`, `C003` (a free name) is `B008`, `C004` (an unknown method) is `B001`, and a call to a `rejected` name, which v0 accepted, is `B009`. D001–D015 keep their numbers (now the kit's own, widened where the API grew), D016 is retired, D017–D020 are new (D020: a Dialect without `text(state)`).

What it does not do: run any target (nothing is emitted or compared), or check a `// REFUSED:` comment's claim.

## The --effects mode

`--effects` (`checkDir(dir, { effects: true })`) checks a hand-in against [docs/api-effects.md](docs/api-effects.md), the per-slot effects draft, which `kit/define` does not have yet; [docs/rules-effects.md](docs/rules-effects.md) is its task and codes. Without the flag nothing changes. It is a shim over the real kit, with no kit change:

1. **Before** the real `defineDialect`, `checker/effects/validate.js` checks the draft's declarations on the definition object: D012 widened (exactly one of `pure: true` and `instance`), D021 (a malformed effect declaration) and D022 (an instance reachable another way, or a change outside its instance space), every case the packet's Codes table lists, each at its line with a fix. A member pattern naming a member the definition lacks, or an object-level `write` / `bump` of an object with none, is deferred to lowering when the Dialect has `environment(program)`, which may add it.
2. `strip.js` takes the declarations out so the real kit accepts the rest: instance spaces become `{ pure: true }`; `may` and `helpers` go; `{ value, write }` and `{ value, bump }` become the bare type; `effects` go from verbs, intrinsics and objects; an object's `call` (not in the API as built) travels as an `{ fn }` member named `call()`. Convention functions and `environment(program)` are wrapped, so what they return is stripped and recorded per Program.
3. Each Program is lowered by kit/define's `lowerRecord`, called with the Compiled grammar rebuilt from the Grammar definition, against the real Environment patched (`lower.js`): each writable member and total gets a store rule and a `read Obj.member` effect, each verb its `effects`, each callable object its `call` with its `effects`; conventions keep `forbid: []`. **The shim's choices:** the store rule is `{ type: "f64" }` for every writable member, vectors included (lowering never reads the rule's type, and no `Coerce` holds a vector, the draft's "store rule for a vector place" gap); and because the IR verifier would refuse that (V002) and drop the kernel under `npm test`, `switches.verify` is off while the shim lowers. A total is a writable f64 to lowering: a bump lowers as a read and a write.
4. **After** lowering (`check.js`), the definition checks that need the Program (what `environment(program)` added, what a convention function returned: D021, D022 at the Dialect, `(when examples/… was lowered)`), then each lambda's effects, its helpers' included, against its slot's `may` by prefix match, reads of the slot's own instance always allowed in an instance space (L004, naming the effect and slot, the fix listing `may`); each helper's own effects against `helpers.may` (L004 at the helper), whose default when the Dialect gives no `helpers` is a read of each instance space's object (`["read Plant"]` for the garden), so a total read in a helper must be listed. Totals are read from the syntax tree (`totals.js`, kit/parse): only the statement `x.m += e` or `x.m++` is a bump; any other change is L017, and so is a read of a total in a slot that may bump it; a write to a total the tree does not show (an alias) is L017 too. A write to a member that is not writable is the real lowering's L013.
5. **Expected refusals:** an example whose first line is `// REFUSED: <code>` must fail (any diagnostic, from the definitions, the builder or lowering); its diagnostics are folded into one info line, `REFUSED declared <code>; the checker gave …`, which gates nothing. One that checks clean, or exports no Program, is `C008`.

## Running a trial

Give each agent a private directory holding copies of `docs/api-draft.md`, `docs/rules.md` and [the Dream Code](../../project/2026-11-24-data-tools-dream-code.md) as `dream-code.md`, and a `check.sh` that runs the checker with `DEFINE_TRIAL_LOG` set. Tell it to read nothing else in the repository, and to write `REPORT.md` with a shell heredoc if its Write is refused ([project/gotchas.md](../../project/gotchas.md)). Record per agent the model, what it guessed, what it asked for, its difficulty score, and how much its output needed changing to comply. `trial-2-briefs.md` has trial 2's setup and brief word for word.
