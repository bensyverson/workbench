# Seams relay trial

The dogfood trial of kit/compose's seams: a relay in three blind sessions. A **maze author** adds output ports, frames and a runtime to the maze package, knowing nothing of particles; a **particles author** adds inputs, frames and a runtime to particles, knowing nothing of maze; a **composer** writes a glue program, `workbench.js`, with `kit/compose`, so a burst plays where the maze player picks up a coin, and the checker runs it.

The first relay (2026-11-25, leaf `cDqmIK`, [the findings](../../project/2026-11-25-seams-relay-trial-findings.md)) ran against the seams draft through stand-ins; its packet is in `packet-2026-11-25/` and its nine legs in `runs/2026-11-25/`. Its reference example was the task's own pairing, so it could not test whether strangers' field names meet (finding 8). **The rerun's packet (2026-11-26, leaf `WnmLua`)** is written against the real kit ([kit/seam](../../kit/seam/README.md), [kit/define](../../kit/define/README.md)'s ports, frames and `defineRuntime`, [kit/compose](../../kit/compose/README.md), [kit/run](../../kit/run/README.md)), and its worked example is an unrelated pairing: a step sequencer (`drums`) and a scoreboard's lamps (`board`). It is the first time fresh agents meet `record: { name, slots }`, `rename`, `delay`, `delivery`, rates (`/s`), the kit's `s`, `point1` and runtimes, and the composer's glue is checked and run headless.

### What writing the reference hand-ins found

Writing `fixtures/valid-2` from `docs/` alone changed the docs three times and found two kit gaps:

- **Repeated slots' kernel ids.** A slot a construct calls more than once (particles' `.force("gravity", …)`) lowers to `<instance>.<slot>#<n>`, n the call's place among all that instance's calls, which the record (`record.forces.gravity`) does not carry. `runtime.md` said only `<instance>.<slot>`; it now says how to match them by order, and the particles runtime does so. **Kit gap:** a runtime cannot look a named decl's kernel up by its name.
- **A record's name must be set for every call of a listed slot.** `spawn` sees the burst's record as `ev`, but a spawn by rate has no record, and a kernel reading an unset global throws. `runtime.md` now says to set a stand-in record. **Kit gap:** `record: { slots }` cannot say "only when this input drives the call".
- **Instants start at 0.** `runtime.md` said a `tick: 1/8` part steps at 1/8, 2/8; it steps at 0, 1/8, …
- `seams.md` now says `ref("in")` works inside a `data({ … })` shape, which the particles Grammar needs for an emitter's option.

## The massage the rulings force

The 2026-11-26 rulings change one thing the relay authors wrote: **an Event output has no `from`** (a runtime pushes its records; [the clocks draft](../../project/2026-11-25-clocks-draft.md), question 3), which the real kit refuses as D026. `massage` removes that `from` and nothing else; `RUNS` lists each edit by the recorded file's line, and the test holds it to that list.

| Leg | Massage |
|---|---|
| r1-maze, r1-compose (its `maze/`) | `from` removed from 4 Event outputs (`entered`, `picked`, `bumped`, `cleared`): maze.dialect.js lines 82–85 |
| r2-maze, r2-compose | 1 (`picked`): line 72 |
| r3-maze, r3-compose | 3 (`picked`, `bumped`, `cleared`): lines 80, 85, 90 |
| r1-, r2-, r3-particles | none |

The state lists those outputs read stay in the Dialects, unused by any port. **Not massaged:** r2's `time` and r3's `sec` frames (1-D, seconds, each package's own) and their `f64@time` / `f64@sec` outputs. The ruling gives every package the kit's `s`, but a package's own 1-D frame is still legal (only a frame named `s` is refused, D030), so nothing forces the change: a composer who wired one to a stranger's `f64@s` would get S251 and would relate the two with `.frame`. Whether a 1-D frame that means seconds should be refused is a question for the rerun. With the massage, the three compositions plan `×40 +[20, 45]` (r1, plus `level.out.cleared → fx.in.pulse`, dropping `at`), `×32 +16` (r2) and `×32 +16` (r3).

## Running the trial

A relay is three legs: the maze and particles legs run in parallel, then the compose leg on their hand-ins. Copy each leg's directory to `runs/<date>/<relay>-<role>/` afterwards. The checker trusts the package hashes, so a composer who edits a package and re-hashes it passes it: when recording a compose leg, `diff -r` its `maze/` and `particles/` against the author legs' hand-ins.

Run 2026-11-25: three relays, nine legs, all clean ([the findings](../../project/2026-11-25-seams-relay-trial-findings.md)); records in `runs/2026-11-25/r{1,2,3}-{maze,particles,compose}/`, rechecked on the real kit by `real.js` (below the massage table). Rerun 2026-11-26: two relays (A on Sonnet 5.5, B on Haiku 5.5), six legs, all clean, every composition bursting at the converted pickup and replaying exactly; relay B's composer bridged `at` to `pos` with `rename` ([the findings](../../project/2026-11-26-seams-relay-rerun-findings.md)). Records in `runs/2026-11-26/{a,b}-{maze,particles,compose}/` (report, checker log with one extra line from the integrator's recheck, gzipped transcript, hand-in). Placeholder arm 2026-11-26 (leaf `KTrmEL`, `PACKET=placeholder`, legs under `/private/tmp/KTrmEL-relay/`): relay C clean at every leg, its composer bridging `at` to `pos` with `rename`; relay D's names met as written (`at`), but its composition stops at S116 (the maze declares 64 records a step, the particles take 8), which no glue can fix ([the findings](../../project/2026-11-26-placeholder-docs-findings.md)). That leg first showed S116 as "the checker failed" (exit 3): `checkComposeLeg` built the composition with the runtimes but checked it without them. `loadCompose` now checks with every runtime, so S116 is a diagnostic at the glue's line. One smoke leg proved the launcher end to end (2026-11-26, `run.sh particles /private/tmp/WnmLua-smoke/particles claude-haiku-5-5`): 50 turns, 235 s, $0.09, eight checker runs, clean from the sixth; not recorded as a trial leg.
