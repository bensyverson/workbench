# The H5 run: findings

*2026-11-25, leaf `3Cd9hb`. Six fresh agents (two Opus, two Sonnet, two Haiku) each built the particles language ([the sheet](../scripts/particles/docs/dream-code.md)) from [`kit/START.md`](../kit/START.md) and [`kit/API.md`](../kit/API.md) alone, at `6df64d0` (7,196 tokens together; `set -a; . ./.env; set +a; node scripts/api-pilot/count-tokens.js kit/START.md kit/API.md`). Each ran as its own `claude -p` in a fresh folder outside the repository, so it loaded no `AGENTS.md` and no project memory, and its transcript records every tool call. The hidden programs, written from the sheet alone before any document existed, decided green. Tooling and brief: [`scripts/particles/h5/`](../scripts/particles/h5/README.md). Hand-ins, logs and transcripts: [`runs/2026-11-25/`](../scripts/particles/h5/runs/2026-11-25/).*

## The result in one paragraph

**Every agent built the language through the API from the two documents alone.** No agent opened a file outside its folder: no tool call of any of the six names a path in the repository (a scan of every tool input in the transcripts; agent D saw kit file names in a stack trace its own probe printed, and opened none). Every builder was generated by `defineGrammar`. Over the scored set (the hidden set less the seven H5 excludes), four agents scored **27/27 accept and 126/126 reject**. Agent C missed one reject. Agents D and F refused seven valid Programs because the sheet's naming rule is ambiguous (below). **But the score overstates the result.** The sheet requires refusals the kit cannot express: a number as a condition, vector × vector, a rate that can end without a `return`, checking helpers nothing calls, and a helper checked once per set of argument types. The hidden set has no program for most of them. Five agents named the same gaps unprompted. Two of them (C and D, both Sonnet) wrote a parser and type walk of 700 to 900 lines inside their Dialect to enforce the gaps. That is the "work around it" START.md tells them not to do silently; both reported it. Difficulty was 3 or 4 on every tier.

## What the agents found

### The API cannot say these sheet rules (kit design gaps)

| Gap | Agents | What they asked for |
|---|---|---|
| Helpers nothing calls are never checked; the sheet says every helper is checked (refusals 6, 7, 8, 12, 24) | A, B, C, D, E, F | check every top-level function, or put uncalled ones in `units` |
| A number as a condition (`if (p.heat)`, `!p.life`) type-checks | A, B, C, D, E, F | a Dialect switch, `conditions: "bool"` |
| Vector × vector and number / vector type-check | A, B, C, D, E, F | an operator table on `vector()` |
| A value-returning block may end without `return` on some path | A, B, C, D, E, F | a "returns on every path" check whenever `returns` is not void |
| No custom message for a member or name a lambda may not use (`Math.random`, `p.collide()`) | A, B, E, F | a `rejected` list for Dialect members, like the Grammar's |
| A lambda slot accepts a named arrow or source text, not only one written in place | A, B, C | `lambda(conv, { inline: true })` |
| A top-level `let`, or a constant that is not a number expression, is readable data, and `units` reports a `let` as `kind: "const"` | A, B, C, D, F | record the keyword; a Dialect rule for top-level data |
| Helpers are monomorphic: `id(1)` beside `id(p.vel)` is L014, though the sheet checks a helper "for each set of argument types", so **valid Programs are refused** (no hidden accept has it) | C, D | per-argument-type specialization |
| An expression body where the sheet wants a block (update) | B, D, E, F | a convention option, `body: "block"` |
| The narrower Runtime Subset (strings, `**`, arrays, shadowing `Math`/`vec2`): the excluded seven | C, E, F | an operator and syntax allow-list (backlog, "narrowing the Runtime Subset") |
| A handle passed whole (`h($)`, `h(counters)`) is allowed; the sheet refuses it | C, E | a handle flag, "never passed whole" |
| No control over which code a mistake gets, and some mistakes give two (`(t, live, rng) => rng()` gives L010 and L001) | A, B, D, F | suppress follow-on codes after a parameter-count error |
| A default for an optional slot (`tick` 1/60, `seed` 0) | F | `default:` on the slot |

The first four rows were found by all six agents, unprompted. They are the strongest signal of the run, as the per-instance namespace was in the pilot.

## Verdicts

**H5: Six agents on three tiers (two each of Opus, Sonnet and Haiku) built particles through the API from START.md and API.md alone (7,196 tokens). Every one built a passing language. Measured from their transcripts, none read kit source and none hand-wrote a builder.** Over the scored hidden set, four were perfect. One missed a reject. Two refused seven valid Programs, all from one sheet ambiguity, now settled. **H5 holds for building a language. It does not yet hold for the sheet's strictness.** About six sheet rules cannot be said in the API, and two Sonnet agents wrote a parser of 700 to 900 lines to say them. The hidden set does not test most of those rules, so the score does not show the gap. Per the AGENTS.md ruling, that difficulty is feedback on the design: the gaps above go to Ben, and the run repeats after the design changes.

**H11: Not tested in M3.** No agent wrote a pass, and the queries still have no client.
