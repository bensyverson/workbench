# START.md and API.md pilot: findings

*2026-11-24, leaf `qwgSOL`. Three fresh agents (one Opus, one Sonnet and one Haiku) each got only [`kit/START.md`](../kit/START.md), [`kit/API.md`](../kit/API.md) (both at `ca06ede`) and a one-page Dream Code sheet ([`scripts/api-pilot/docs/dream-code.md`](../scripts/api-pilot/docs/dream-code.md)), and defined a budget-planner language with the Definition API. Hidden programs written from the sheet alone decided green. Brief: [`scripts/api-pilot/pilot-brief.md`](../scripts/api-pilot/pilot-brief.md). Hand-ins: [`scripts/api-pilot/runs/2026-11-24/`](../scripts/api-pilot/runs/2026-11-24/). Kit: [`scripts/api-pilot/README.md`](../scripts/api-pilot/README.md).*

## The result in one paragraph

**All three agents passed every hidden program**: 12 of 12 that must check clean, 21 of 21 that must be refused, on all three tiers. None read a file beyond the three documents (each one's own account, in its report's Files section), and none wrote a builder by hand: every builder was generated by `defineGrammar`. Two checked clean on their first checker run. API.md and START.md are about 15k characters together, against the define-trial packet's 42k. All three agents hit the same two gaps, unprompted. First, a `name()` namespace spans the whole Program, so a name unique only within one construct instance (a flow within an account) had to be taken as a string and checked by hand. Second, the record's shape (where opening arguments and children land) had to be guessed or probed. The second was a documentation error: API.md said an unnamed opening argument lands under `name`, but it lands under `arg1`. Both are now fixed in API.md, along with four smaller points.

## Design gaps they reported (for Ben)

1. **A per-instance namespace** (A, B, C): `name("flow", { within: "account" })`, so B002, B003 and did-you-mean work for names unique within one instance. All three hand-wrote it. This is the strongest signal of the pilot.
2. **Ranges on data shapes** (A, B): an opening at least 0, a horizon 1 to 120 and whole, a month 1 to 12 and a param's value within `min..max` were all hand checks. (The kit now refuses a param whose declared value misfits its own declaration, B004, but only for `value`.)
3. **A required child construct** (B, C; pitfall 3's workaround works).
4. **A ref that may not name its own instance**, or `ctx.instance` in a slot check (A).
5. **A default for an optional slot** (C: the sheet's horizon defaults to 12).

Kit output quirks were filed as leaves: a check's `fix` hidden behind its `tip` in the checker's output (`AkBOlK`), two B002s and "a account" for one duplicate instance (`AitCG4`), and L010's tip printing object labels and `x` (`EwxjrV`).

## Verdict for H5 (pilot)

**Pilot, 3 agents (Opus, Sonnet and Haiku, one each), on the budget planner built through the API from START.md and API.md: all three built a passing language from the documents alone, with no kit source read and no builder hand-written.** It is a pilot, not the H5 run: n is 3, the language is pure (no effects), the agents self-reported which files they opened, and the documents have changed since, unrerun. The stateful fourth domain (leaf `3Cd9hb`) is the real test.
