## The result in one paragraph

**M3 built a kit that fresh agents build languages on.** The Definition API (`kit/define`: `defineDialect`, `defineGrammar`, construct state, binding-time params, module scope, per-slot effects) declares a Dialect as data and generates its builder. It carries three Grammars with no hand-written builder: fields (re-declared, its harness figures unchanged), data (four constructs) and particles (a root with a child construct, and effects).
- **H5 holds** for building a language. Six blind agents on three tiers built particles from 7,994 tokens of documentation (`kit/START.md` and `kit/API.md`). None read kit source or hand-wrote a builder, and four refused every scored hidden reject.
- **H5 does not hold** for the particles sheet's full strictness. Half the agents still wrote a parser for the rules Ben parked.
- **H2:** the core stayed neutral across four Dialects. No data- or particles-specific logic is in `kit/ir` or `kit/lower`, and the DMG and fields figures did not move. Effects now have a second user (particles), while integer stores remain DMG-only. The IR carries only 7 of the data Dialect's 21 table calls.
- **H4** is not tested against DMG.
- **H11** is not tested.

## H4: can most fluent grammars be declared as constructs and slots?

**Not tested against DMG.**
- **Built:** Dialect data plus a generated builder for three Grammars, none of which needed a hand-written builder:
  - fields: one construct, re-declared, Kernels JSON-identical and harness figures unchanged (leaf `iJtvVE`'s note);
  - data: four constructs, program, table, chart and view (`kit/dialects/data/grammar.js`);
  - particles: a root and a required child construct, `emitter`, with names unique per instance. This is the reference plus twelve blind hand-ins over two runs.
- **Untested:** DMG's grammar, fragments and build-time slots.

What a hand-written builder used to add, and where it went:
- **Refusals moved to `.build()`.** fields' hand-written builder refused at the call; the generated one collects refusals and throws them at `.build()`, with a code, the call's line and a fix (B001–B017).
- **A free name is a builder error.** A free name in a lambda (`Math` in a field) is now B008 at build, where it was L001 in lowering, so the H3 trial kit's classification of three cases changed (`scripts/h3-trial/README.md`).
- **The table's per-step types.** A table's per-step column types need each lambda's inferred type, which no static declaration could give: construct state with `step(state, call, inferred, ctx)` (trial 1's finding).
- **Kept outside the API on purpose:** fragments, build-time lambda slots and new components. The data Grammar refuses `.fragment` and `.component` with a fix.
- **The parked DMG re-declaration** (backlog, "re-declaring DMG"): DMG's builder lives in the original HTML, and the delivery decisions forbid copying it, so H4's real test needs a DMG builder written from scratch.

### Every change to the core, and why

Classes as in M2:
- **D:** an assumption from an earlier Dialect, moved out or generalized.
- **C:** a flaw in the core, now exposed.
- **N:** a new need the core now carries.

From the leaves' notes (`vNfBwn`, `iJtvVE`, `8vQJOw`, `9IQ6uP`, `ydiY5Y`, `LWKjTf` and the review fixes), checked against the diff.

1. **A nominal scalar over f64, `ScalarType` (N).** The data Dialect's date is `{ scalar: "date", of: "f64" }`. It compares only with its own kind, refuses arithmetic, and the LIR refuses it, so GLSL never sees one. `ir.d.ts`, `types.js`, `verify-rules.js`, `lower/scalar.js`. No interpreter or JS change, since a scalar is its backing double.
2. **Null narrowing by `x != null` / `x == null` (C).** `lower/nullcheck.js`. A first version also narrowed `x !== null`, which a review found unsound, because the core itself yields undefined (`find`, an index past the end). Corrected in `6edf1f1`.
3. **Constants may call pure helpers when a Dialect says so (D).** `constants: { calls: "pure" }`. The hand-written fields builder allowed it silently, and the generated one forbade it until Ben ruled (`iySXYx`).
4. **Per-slot effects (N).**
   - In the IR: the `bump` statement, `Place.total` and a `value` store rule, through the verifier, listing, interpreter (`host.bump`), JS (`+=`), LIR (R002) and query walk.
   - In lowering: `SlotDecl.may` (L004 against a slot's allowed effects) and L017.
   - This is the first effect vocabulary that is not DMG's. A caller of a helper that does not lower now gets no Kernel and no diagnostic of its own (`blockedBy`), so the DMG survey counts it under helpers, and M1's figures hold.
5. **The handle rule, L018 (C/N).** A handed-in object is used only as `h.member`, `h.method()`, `h()` or a whole argument (`lower/handles.js`). It came from trial 4's hidden rejects, and it closes aliasing that would let a lambda escape its own instance.
6. **An assignment to a Dialect global lowered clean and vanished from the Kernel (C).** `$ = 1` is now L013 (`ecaae3e`). This failed open.
7. **Strictness a Dialect asks for (N).** `conditions: "bool"`, `vectorMultiply`, a slot's `body: "block"` and `checkAllHelpers` (helpers nothing calls are lowered untyped). All are off by default, so DMG, fields and data are unchanged (decision `MpZZsU`).
8. **Returns on every path (C).** It is on for every Dialect. A value-returning lambda or helper that can fall off its end is L003. The repo survey found no preset, golden or example it newly refuses, though two DMG unit-test snippets encoded the old leniency.
9. **DMG's words moved out of lowering's tips (D).** `Environment.tips` (`readOnly`, `loopBound`, `size`, `topLevel`) and `forbidMove`. "Baked values are ROM constants … declare an .attr" was a core string, and fresh particles agents met it (H5 run). This is the only change to `kit/dialects/dmg`: +13/−3, the tips moving in.
10. **Module scope (N).** A lexical scan of a Program file's top-level bindings (`kit/parse/toplevel.js`, `blank.js`), so a lambda's free name resolves to a top-level helper or constant. It fails closed: a duplicate name is a ScanError. Two known misreads are parked (backlog, "harden the module-scope scan").
11. **Declared tables looked up by own key, and one L003 per `||` (C).** `Math.toString` found `Object.prototype` (issues `CQKwBO`, `Uv2uas`, `a8921a7`).
12. **The GLSL capability check reads `kit/query` (N, and a simplification).** `capabilities.js` went +14/−44, with its goldens unchanged.
13. **Smaller items:** one parse subset line; `interp/exec.js` runs `bump`; `emit/js` emits it; `lir/lower.js` refuses a total.

**Counts by first-listed class**: of the 13, D 2 (3, 9), C 5 (2, 5, 6, 8, 11) and N 6 (1, 4, 7, 10, 12, 13). The split is my judgment.

### What stayed specific

- **Integer store rules (`u8`…`fix`) remain DMG-only.** No later Dialect stores an integer, and the hostless integer backend that would exercise them is not built.
- **Events, timers, rng as a world service, queries over entities: DMG-only.** particles' `rng` is a callable handle, and its verbs (`kill`) are declared effects.
- **The data Dialect's table semantics are not in the IR.** Of the 21 table calls in Dream Code examples 2–5, only the 3 derives and 4 filters are whole Kernel computations (7 of 21). An aggregate's Kernel is one call to a host method. `rename`, `cast`, `trim`, `replace`, `dropNulls`, `dedupe`, `groupBy`, `agg`'s grouping, `join`, `sort` and every chart encoding live in the Grammar's `step` as types only, and nothing in the kit runs them. The count is `kit/dialects/data/README.md` ("Limits"); `grep -oE '\.(derive|filter|limit|agg|groupBy|join|sort|sortDesc|rename|cast|trim|replace|dropNulls|dedupe)\(' kit/dialects/data/examples/0[2-5]*.js` finds the same calls, plus three in comments.

### Verdict

**H2: four Dialects (DMG, fields, data, particles); the core stayed neutral.**
- **Pure lambdas** (fields' pixels, data's rows) needed one new type (the nominal scalar) and one narrowing rule. **Per-instance effects** (particles) needed one new statement (`bump`), one place flag and one store rule.
- **The failure condition did not trigger:** no domain logic in `kit/ir` or `kit/lower`, and the DMG and fields output did not move.
- **Effects are no longer DMG-only.** Integer stores still are.
- **The IR carries only the data Dialect's row lambdas,** 7 of 21 table calls. It does not carry groupBy, agg, join or sort, so "a neutral core covers data tools" holds for their lambdas, not for their table algebra.
- **Caveat:** as in M2, review caught the core's worst flaws (items 2, 6), so neutrality was reached by review as much as by design.

## H5: can a fresh agent build a small workbench from about 8,000 tokens of kit documentation?

**Pilot, six agents, two each of Opus, Sonnet and Haiku, on particles built through the API from START.md and API.md alone (7,994 tokens).**
- **The docs cover the full workflow:** a Dialect, a Grammar, effects, checks and examples, with no `hello` Dialect (Ben ruled API.md's worked example replaces it).
- **No agent read kit source or hand-wrote a builder,** in either run (a scan of every tool call's input, [H5 rerun](2026-11-25-h5-rerun.md)).
- **The rerun's score:** over the scored hidden set (27 accepts, 141 rejects), four agents were perfect, beating the reference. The other two missed only rules the reference also misses, plus, for one, an option it never turned on.
- **Verdict: H5 holds for building a language.**
- **It does not hold for the sheet's full strictness.** Three of six agents (one Opus, two Sonnet) wrote a tokenizer or parser of 320–560 lines. It enforces rules the API cannot say: the narrower Runtime Subset, reserved local names, lambdas written in place, handles passed whole, and an uncalled helper's parameter type. Ben parked all but the last. The documents are sufficient. The remaining gap is the kit's design, and whether a Dialect may narrow the subset is Ben's open call.
- **The earlier pilot:** on a smaller sheet (a budget planner), one agent per tier passed 33/33 ([pilot](2026-11-24-api-pilot.md)).
- **The budget:** the proposal gave START.md 1,500 tokens and API.md 4,000. They grew to 7,994 together, against H5's 8,000, because API.md now carries the worked example and per-slot effects. The next API addition needs cuts first.
