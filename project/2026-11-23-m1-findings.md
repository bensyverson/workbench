# M1 findings: the game slice, H1 and H10

*2026-11-23 · findings · the report that closes M1 ([plan](2026-11-23-m1-game-slice-plan.md)). Code at the branch that adds `scripts/dmg-diff/`, after the IR review fixes (job D8Sv9n). Every figure names the command that reproduces it; run them from the repo root.*

**Headline.** The approach works on a real grammar. 105 of the DMG Workbench's 126 runtime lambdas parse, lower to a typed IR and emit JavaScript unchanged. In presets 04–07, every lambda (25 of 25), swapped in alone and all at once, reproduces the original trace over 3000 frames on three seeds and ten param settings: 30 runs, 0 differences. **H1 holds for the simpler half of the presets and is open for the games**: of the 21 rejections, 11 come from top-level helpers, 9 from constructs lowering does not handle yet, and only 1 from the subset itself. **H10 is supported in a narrow form**: closure execution was removed for four presets with nothing visible depending on it, and the IR answered questions the closures could not, but the emitted code still leans on the host's proxies for integer coercion, which is where one IR level already falls short.

> **Corrected 2026-11-23 (review of dmg-diff):** "only 1 from the subset itself" undercounts. The survey files a rejection under `helpers` first, so its `subset` column counts lambdas whose *only* class is the subset. Five lambdas carry an error from a rule the subset makes on purpose: 21 `snake.onFrame#0` (L005), 21 `bot` (S111 closure, S109 spread), 22 `Ball.onFrame#0` (S111), 23 `flappy.onFrame#0` (S101 `while`), all four also using helpers, and 23 `bot` (L007, a step other than ±1, which widening 5 would admit). The verdict stands, but the subset bites on the games more than the headline says. Also, 23 `Bird.onFrame` needs `w.bg` as well as a rewrite of its `for…of`: lowering does not look inside a `for…of` body, so that L002 is hidden.

What this does and does not show:

- **It covers the review's gaps.** 06's `done` first fires at tick 2399 and was never reached by the 600-frame check; it is now reached on all three seeds, and a restart on seed 11. timer(spawn)'s sweep arm and its early return now run.
- **The u16 wrap path of 04's `Mole.onFrame` is unreachable in the shipped preset.** ttl is set to `linger × 60` with `linger ≥ 0.5` (the slider clamps build-time overrides to its minimum), so a mole that is up never holds ttl 0. The edited case reaches it, and the host's wrap warning is compared, but the IR's "compare the unwrapped value" choice cannot be told apart from comparing the stored value in this program (see the mutants).
- **Sensitivity** (`node scripts/dmg-diff/cli.js mutants`): of 9 planted faults, 5 are caught and 4 are equivalent under the host, each with its reason in [`sensitivity.js`](../scripts/dmg-diff/sensitivity.js): the stored-vs-unwrapped compare in 04 (no reachable value tells them apart), 06's `secs > 0` guard (the game ends in the same tick), 06 `whack` returning `null` for `false` (its caller tests truthiness), and 07's `break` vs `continue` on a full pool (`w.spawn` returns null with no effect). The boundary `y > 144` vs `>=` in 07 is caught only by the burst-6 case on two seeds of three: the evidence for boundary conditions is thin.
- **Evidence below the trace.** The fast suite now also runs 58 lambdas against their originals on logging stand-in worlds (`kit/emit/js/test/semantics.test.js`), which pins evaluation order, laziness, query semantics and truthiness; and all 24 one-line mutants of lowering and the emitter from the IR review are killed (job D8Sv9n's note).
- **Beyond 04–07.** Each of the 105 lowered lambdas, swapped in alone, matches on seeds 7 and 11 over 1200 frames (the IR review's probe p5, re-run against this branch; not committed, because the prerelease suite is scoped to 04–07). Swapping the 80 lambdas outside 04–07 belongs in M3's prerelease suite.

## H1: do models write runtime lambdas comfortably inside the subset?

**Verdict: yes for the simpler half, not shown for the games.** The presets were written by a model with no knowledge of the subset, which is the right condition for H1, and 83% of their lambdas (105 of 126) are inside it as written. The rejections are mostly not the subset's: 11 use top-level helpers, which the proposal's §5.5 already rejects with a fix that does not exist yet (`.const()` covers values, not functions), and 9 use constructs the subset allows in spirit but lowering does not handle (destructuring, `for…of`, list indexing, string methods, `w.bg`). Only one lambda (23's bot) hits a rule the subset makes on purpose. *(Undercounted: five do; see the correction under the headline.)*

Where the evidence is weak:

- **The lowering was built while reading these presets.** The dialect describes the surface they use; a new program would find gaps these did not. The 9 `not-yet` rejections are the visible part of that.
- **The games (20–26) are where the subset bites**, and they are 7 of 22 presets but 14 of the 21 rejections. Writing a BG-map game inside the subset needs `w.bg`, destructuring and declared helpers; whether a model writes those comfortably is untested.
- **"Comfortably" was not measured.** No model was asked to write or rewrite a lambda under the subset's diagnostics. The rewrites above are judged cheap by reading, not by watching a model do them.
- **One domain, one author.** All 126 lambdas are DMG game code from one generation run.

**Widenings the evidence supports** (recommendations for Ben to rule on, not decisions):

1. **Program helpers as lowered functions.** 11 lambdas in 6 presets call top-level helpers (`nth`, `placeFood`, `flip`, `step`, …) that are themselves ordinary subset code. Lowering them as program functions, like the DMG's methods, would remove the largest class at once. The alternative is the proposal's "declare it": a `.fn()` builder would need a grammar change.
2. **`for…of` over a bounded list**, including a short literal list of entity references (20, 21, 23). It is bounded by the list's length, so it keeps the IR's guarantee.
3. **Destructuring of structs and fixed tuples** (21, 22, 25): `const { cx, cy } = …`, `const [dx, dy] = DIRS[d]`.
4. **List indexing with a declared bound** (30, 31), and **string intrinsics** (`repeat`, `toUpperCase`) in the dialect (11, 30).
5. **A constant step other than ±1** in a counted loop (23), if its start and bound are checkable.

Not supported by the evidence: closures (21, 22), `while` (23), spread (21). Each appears once and has a direct rewrite.

**Types beyond the proposal's §5.2** that lowering needed (from the IR leaf, job KHQFvD): strings and string enums (sprite names, choice params, buttons, event and pool names); optional entity references with narrowing (`w.rng.pick`, `w.spawn`, `find`); unions (draw results, bot results, printf arguments); variadic printf; lists with a maximum length (so `each` is bounded); struct payloads and method signatures inferred program-wide to a fixed point; keyed functions whose literal key selects the signature (`w.param("x")`). §5.2's list of numeric types, vectors and matrices covers none of these, and a game dialect needs all of them.

## H10: does the IR earn its keep?

**Verdict: supported for the question M1 can answer, with one clear limit.** §14's test is "remove direct closure execution from one workbench". For presets 04–07, every runtime closure was replaced at once by code emitted from the IR, and nothing visible changed: state, logs, RNG draws and the framebuffer match over 3000 frames (`node scripts/dmg-diff/cli.js diff`). This was done in the headless oracle, not in the workbench page, and for 4 of 22 presets.

The stronger case for the IR is what it made answerable that the closures could not ([Manuel's framing](2026-11-23-passes-queries-and-several-irs.md): judge the IR by the questions it answers):

- **Effects.** Every statement records its reads, writes and intrinsic effects, so "may this `draw` change state?" is a check (L004), not a hope. No preset violates it, which the closures could not show. The review found the check could be bypassed through a method that failed to lower; it now refuses that (L014).
- **Evaluation order.** The review found that compound assignment evaluated a receiver twice (two RNG draws for one `+=`). No preset hit it, so no trace would ever have shown it; the IR made it a visible, testable property, and it is fixed.
- **Bounded loops.** Every loop's bound is named in the IR (`param burst`, `size ≤ 24`); the review showed the first check was too weak, and it now requires a reachable bound.
- **Integer stores.** Where each sized-integer store happens is explicit (`store.u16 self.ttl, t0`), which is what a C or wasm backend needs.

**Where one IR level already falls short:**

- **Coercion is left to the host.** The JS backend emits a plain assignment because the DMG proxy coerces and logs; a backend without that host needs explicit truncate, clamp and wrap, and the host's own rules are irregular (`w.oamStart` stores `(v | 0) & 255`, approximated as `u8`). That is a second, lower stage, as the [passes note](2026-11-23-passes-queries-and-several-irs.md) argues.
- **Queries are inlined to loops at lowering.** `filter` becomes an `each` with a `push`, so a pass asking "which queries does this kernel run?" sees loops, and a backend that has a native filter cannot get it back. A higher stage that keeps queries as queries would serve both.
- **`present` and `truthy` were one op until the review.** The IR said "tests an optional" and meant JavaScript truthiness; it took a reviewer to see it. Ops whose meaning depends on the source language belong in a stage that says so.
- **Draw results are a union of a sprite name, a partial record and null**, which the IR can type but no backend other than JS can return as is.

## What M2 and M3 should change

Weighed against [the passes note](2026-11-23-passes-queries-and-several-irs.md), which M1's evidence mostly supports:

- **M2 (shader slice):** treat the core IR as one stage. M1's IR already wants a stage above it (queries, source-language truthiness) and one below it (explicit coercion). The shader slice is the first backend with no host to lean on, so it should own the lower stage, with an IR verifier run after each lowering. The pixel debugger reads spans, which every M1 node already carries.
- **M2:** keep the differential check, but plan for its limits: M1's mutants show that a long run misses boundary changes unless a case aims at them. With no closure to compare against in GLSL, the comparison is JS against GLSL under tolerance, and the reference interpreter M1 declined (job KHQFvD) becomes necessary.
- **M3 (kit v0):** before extraction, add the small query API the passes note lists (loops, effects, def-use, reaching stores) and run M1's own checks through it: L004's effect check, L007's bound check and the receiver-once property are each a query plus a rule. That also makes the IR review's findings regression-testable as queries.
- **M3:** decide the subset widenings above, and give helpers a home: they are the largest class of rejections.
- **Who owns the passes** was ruled by Ben on 2026-11-23: the middle path, to be tested in M3 as H11 ([the passes note](2026-11-23-passes-queries-and-several-irs.md)). M1's evidence agrees: every check that mattered in M1 (effects, bounds, order, coercion) is a property of the core IR the kit must guarantee, so the kit should own the core, its verifier and the query API; the stages that differed by target or domain (the DMG's coercion, its query intrinsics, its draw unions) were exactly the dialect's. M1 has no evidence on whether an agent can write a correct domain pass.
