# Boolean-only conditions: what broke and what was edited (leaf W8gh6f)

Ben, 2026-11-26: no truthiness in Bench, no opt-out. A non-bool `if` or ternary test, or non-bool operand of `!`, `&&`, `||` in a test, is L003 in every Dialect; the `conditions` Dialect option is removed (naming it is now an unknown Dialect key). Callback predicates (`filter`, `find`, `some`, `every`) are tests too. The kit has no truthy loop test: loops are canonical bounded `for` only. Figures below come from `npm test` (fast suite) and `node scripts/dmg-diff/cli.js survey`, run in the worktree on 2026-11-26.

## The kit change

- `kit/lower/expr.js` `test()`: every non-bool is L003 with a tip per type: optional `m == null` / `m != null`, number `n !== 0` (or `> 0`), string `s !== ""`, vector a component. Lowering no longer emits `truthy`; `present` still comes from the loose null check. A bare optional const still narrows after the L003, so one mistake is one diagnostic (null-check.test.js pins it).
- Removed: `conditions` from `DIALECT_KEYS`, `CONDITIONS`, the D011 check, `define.d.ts`, `environment.d.ts`, `dialect.js`.
- **The brief's tip was wrong for optionals.** It named `m === undefined`; the kit refuses a strict check against `undefined` (L003, "true for null, the empty value here"). The tip names the loose null check, `m == null` / `m != null`, which narrows a const and draws no S116.
- New test file `kit/lower/test/bool-conditions.test.js` (4 tests: bool still works; number/optional/string/entity as `if`, ternary, `!`; `&&` / `||` operands; each type's tip).
