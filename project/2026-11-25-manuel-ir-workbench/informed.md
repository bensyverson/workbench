# Manuel's IR Workbench: the consult, checked against what we have

## 1. Verdict

The consult's verdict is that our direction holds, that Manuel's numbers support the synthesis's ruling against a strategy layer and a pass framework, and that three premises need tightening: what the harness can claim, D5's two-way split into exact and tolerance, and float bumps under per-slot effects (consult §3). After checking, I agree with the direction and with the first premise. The third is already decided: the effects draft settles float bumps by the target's compare mode (`project/2026-11-25-per-slot-effects-draft.md`, "Decisions", float-bump bullet). The second is right in principle, but nothing we run today reaches it: the harness only feeds finite, bounded inputs (section 3, Q1), so no GLSL-undefined input arises in the recorded cases. Its strongest new finding is one it could only guess at, and the code confirms it (Q5). Five of the fields Dialect's fifteen non-operator intrinsics (`fract`, `min`, `max`, `sqrt`, `atan2`) and three call-style operators (`vmul`, `vdiv`, `vneg`) have GLSL spellings that no harness case ever runs. Their JS spellings are checked against the reference directly, but only on eight hand-picked finite samples. Most of the rest is already built, already decided, or belongs to the Composition milestone.

## 3. The consult's questions, answered from the code

**Q1. What inputs does the harness generate?** A fixed pixel grid and hand-picked param sets, with nothing random and so no seed. Pixel centers come from `pixelUv` (`kit/harness/cases.js:39-41`), looped by `kit/harness/evaluate.js:15-17`. The sets are three per remap sketch (`cases.js:58-73`: defaults, an off-center lens, a lens on the edge), nine for domain-warp (`:81-89`) and six for the stress case at the edge of its declared ranges (`:116-120`). No input is NaN, ±0, ±∞ or subnormal. They could not be: `uv` lies in (0, 1), and every host param value must be finite and inside `min..max` (`kit/define/README.md`, "Binding-time params"; fields' F001 for range). Edge values can appear only as intermediate values inside a Kernel.

**Q2. Which faults are planted, and what is the kill rate?** There are 28 faults (`kit/harness/faults.js:172-205`): 8 operator, 9 constant (one in GLSL text), 4 swizzle, 4 JS rounding and 3 spelling (`glsl-mediump` among them). Twenty-six can be planted in JS and twenty-four in GLSL. The latest run caught JS 24/26 and GLSL 21/24 (`project/2026-11-25-handoff-effects-trial.md:36`). The five escapes all have recorded reasons: two sub-tolerance GLSL nudges (`:185`, `fog-base-small`), an equivalent mutant (`:198`), swirl's blindness to rounding, and mediump acting as highp on this GPU (`:204`). None is an edge-only fault.

**Q3. How does GLSL comparison treat NaN, ±∞ and undefined operations?** `compare.js:73`: a component pair identical by `Object.is` differs by 0, so NaN against NaN and +∞ against +∞ agree. NaN against a number, or ∞ against a finite value, differs by `Infinity` and so always exceeds the figure. −0 against +0 sets `exact` false (`:69-70`), which fails the JS pair, but differs by 0, which passes GLSL. There is no undefined-domain notion and no inconclusive outcome. Readback is `RGBA32F` (`kit/harness/gl.js:91,121`), so outputs are not clamped. In practice the recorded cases never call `sqrt`, `pow` with a negative base, or `atan2` (Q5), so the question has not come up.

**Q4. Does the IR's JSON form round-trip −0, NaN and ±∞?** It refuses them rather than round-tripping them. The verifier rejects a non-finite `num` and a negative-zero `num` (`kit/ir/verify.js:300-301`; "write the negation of 0"), and V012 checks that the JSON form parses back equal under `Object.is` (`verify.js:67-78`; `kit/ir/README.md:84,88`). Every route a number takes into a Kernel is guarded earlier:
- a literal that reads as Infinity, or that overflows f32, is L016 (`kit/lower/numeric.js:47-51,81-84`);
- a baked constant must be finite (B012), and −0 is written out as the text `-0` (`kit/define/scope.js:30`);
- record numbers are finite only (B004, `kit/define/README.md`, "Number bounds", Ben 2026-11-25);
- host param values must be finite (`run`).

One caveat: the CLI lowers with `switches.verify` off (`kit/lower/index.js:21,90`; gotcha 2026-11-25), so V012 runs only under `npm test`. The front-end guards make that harmless as far as I can find (INFERRED). Content keys and replay state hashes are not built (grep finds no hashing in `kit/`).

**Q5. Is every intrinsic's per-target spelling exercised by a program?** No. Counting calls across `kit/dialects/fields/programs/*.js` and `library.js`:
- `fract`, `min`, `max`, `sqrt`, `atan2`, `vmul`, `vdiv` and `vneg`: 0 each;
- `floor` 5, `clamp` 10, `mix` 14 and `length` 8, among others.

The harness runs only `uv-remaps.js` and `domain-warp.js` (`cases.js:3-4`). So eight GLSL spellings never run against a GPU, including `atan2`'s rename to GLSL `atan` (`kit/dialects/fields/intrinsics.js:74`). Their JS spellings are checked against the reference (`intrinsics.test.js:30-46`).

**Q6. Will per-slot effects permit f32 bumps, and on which targets?** Bumps are f64 only ("a statement `bump place, value` (f64 only)", effects draft, "Lacks" 1). Particles declares only a JS target compared exactly (draft sketch, line 73). WebGL2 has no float atomics, so the question decides itself for GLSL, as the consult guessed (INFERRED).

**Q7. Is the kit synchronous end to end?** Building and lowering are synchronous (`kit/define/README.md`, "Runs do not nest … safe because builds are synchronous"). `runCase` is async only because GPU readback is (`kit/harness/run.js:122,131`).

**Q8 to Q10** are about Manuel's system and not ours to answer.

## 4. Where the consult was wrong about us

It saw the proposal and the synthesis only (consult header), so it missed these:

- **Float bumps** are decided by the target's compare mode (effects draft), not left open. Its §3.4 restates that ruling, adding only the count-scaled tolerance.
- **The check output** is richer than the mocked "8/8" line it quotes. It reports the worst component, pixel, set and source line, and the components over the figure (`compare.js`, `kit/harness/README.md`). There is no seed because the cases are recorded, not sampled.
- **Kill rate** is already a number per run, and an escape without a reason fails the run (`scripts/shader-diff/README.md`). The consult places fault planting among our strengths, but treats kill rate as a missing measure.
- **JSON and floats (risk 7, Q4)**: non-finite numbers and −0 are refused at every entry and in the verifier. A baked −0 survives as `-0`.
- **Declared effects (2.1b, R2)**: in our design, intrinsics cannot declare effects, and lowering infers Library effects. Only host verbs declare them.
- **Trial diaries (2.10)**: already structured, with verbatim diagnostics logged mechanically.
- **Edge-first sampling (2.2a)** assumes free Kernel inputs. Ours are bounded and finite by declaration, so the edges live at intrinsic level.
- **The "14 files" for M2** (consult §2.6, from the proposal) predates the Definition API. Five kit files still import fields (2.6 row).
